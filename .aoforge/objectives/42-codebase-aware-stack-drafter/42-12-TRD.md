<anti_patterns>
- One `git` spawn per directory. Collect candidate area dirs, then make ONE
  `git -C root check-ignore --no-index --stdin -z` call (exit 1 means none ignored; that isn't an error).
- Filtering with default (index-aware) check-ignore. A tracked file under an ignored dir is reported
  "not ignored", which is exactly the `.planning` miss. Use `--no-index` for areas.
- Descending into ignored dirs and then discarding. Prune before the walk goes deeper, so a huge
  ignored `dist/` isn't walked.
- Making the init preflight fatal. adopt calls initProfile(write) and must keep working. Report
  `ignored`, don't refuse.
</anti_patterns>

<error_recovery>
- git missing, not a work tree, or a spawn error: fall back to the static list only. Record
  `ignore_source: 'static'` on the result for debugging. Never throw.
- If git's directory-pattern semantics are surprising (`dist` vs `dist/`), always query dirs with a
  trailing slash and add a fixture for both rule spellings.
</error_recovery>
