# TRD 42-04: Task-runner reader (Make / Task / just / npm-family / conventional scripts)

<objective>
Create `stack-runners.cjs`, a pure structural reader of task-runner targets and their bodies, so the
drafter can prefer runner targets over raw CI steps (SDR-02 preference order). It also feeds command
verification: does `make -C svc test` exist?

The ~10 manifest/runner-only repos that drafted `commands: {}` (aoinference-shaped `control-plane/Makefile`,
eden-libs-shaped subshell-fan-out justfile, ao-terminal-shaped Taskfile with `:` names,
devcluster-shaped `bin/*.sh`) are the fixtures.

This module does NOT classify. It returns raw logical body lines. 42-07 runs them through
`stack-shell.normalizeScript` and `stack-classify`. That keeps this TRD independent of 42-03 in the
same wave.

Output: stack-runners.cjs, its test, and a fixture module.
</objective>

<anti_patterns>
- Reading `.PHONY:` or pattern rules (`%.o: %.c`) or variable assignments (`X := y`, `X ?= y`) as targets.
- Treating `include other.mk` targets as missing. `hasTarget` must return `'unknown'` when the
  Makefile has an `include` and the name isn't found statically.
- Walking into `node_modules`, `.git`, `vendor`, `third_party`, `.worktrees`, `.dart_tool` or `build`
  for runner files.
- Emitting `make test` for `svc/Makefile`. It must be `make -C svc test`.
</anti_patterns>

<error_recovery>
- Taskfile YAML: use a small indentation reader (like stack-ci), not yaml-lite. Taskfiles use
  `{{.VAR}}` templating and anchors. Unknown shapes are skipped.
- A justfile recipe body is the indented lines after `name params:`. `set`, `alias x := y`, `import`
  and `mod` lines are not recipes (record aliases).
- A package.json parse error gives no npm targets and no throw.
</error_recovery>

## Test list

Outermost (readRunners over a repo) to innermost (per-format parsers).

1. `readRunners(root)` on a repo with root `Makefile` and `svc/Makefile` returns targets from both. The svc targets have `dir: 'svc'` and `invocation: 'make -C svc test'`.
2. Makefile body: `test:` + `\tgo test -race \` + `\t  ./...` gives body `['go test -race ./...']`. `@echo x` gives `echo x`. `-rm -f y` gives `rm -f y`. Variables, `.PHONY` and pattern rules are not targets.
3. Makefile with `include common.mk`: `hasTarget(root, {runner:'make', dir:'', name:'lint'})` is `'unknown'` when not statically defined, and `true` for a defined target. A Makefile with no include gives `false`.
4. Taskfile.yml: `lint:go:` with `cmds: [golangci-lint run]`, `test:` with `cmd: go test ./...`, `aliases: [t]` give targets `lint:go` and `test`. `hasTarget` resolves alias `t`.
5. Taskfile `cmds:` items in `- cmd: x` form and `- task: other` form. The `task:` form becomes body `task other`.
6. justfile: `fmt:` + `  (cd lib-a && dart format .)`, `test *args:` with body, `@lint:` (quiet), `alias t := test`, `set shell := [...]` gives recipes `fmt`, `test`, `lint`, plus alias t. Bodies are kept verbatim (subshell fan-out preserved).
7. package.json + `pnpm-lock.yaml` gives the manager `pnpm`: `pnpm test`, `pnpm run build`. With `yarn.lock` it is yarn. With no lockfile it is npm.
8. Conventional scripts: `bin/test.sh`, `bin/build.sh` and `scripts/verify.sh` give targets `./bin/test.sh` etc. with `runner: 'script'`. A non-executable `.sh` is still listed with `executable: false`.
9. The depth limit: runner files deeper than `maxDepth` (default 1) are ignored. Skip-dirs are never read.
10. Exec enrichment: an injected `exec('task', ['--list-all','--json'])` returning a hand-built JSON string adds tasks missed statically. When exec reports the runner is absent (throws ENOENT), the static result is unchanged.
11. An empty repo gives `[]`, with no throw.
