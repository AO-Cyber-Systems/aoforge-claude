# TRD 42-08: Recommendations report — `.planning/STACK-REPORT.md`

<objective>
SDR-06. Compare each repo's CI and local tooling against its resolved profile and detected areas.
Emit a reviewable `.planning/STACK-REPORT.md`, which proposes changes and never applies them. The
checks cover:
- missing lint/format/vuln gates
- missing `-race`/coverage
- non-fatal analyzers
- no local runner target mirroring a CI gate
- missing Maestro/integration tests for Flutter apps
- generated-code drift
- Helm/Docker hygiene
- no CI at all

The report also carries the drafter's downgrade notes (locked Q2), so CI-only commands that became
`discover` are not lost. Q8: while implementing DART-COVER, confirm `dart test --coverage=<dir>` in a
throwaway Dart package fixture if dart is installed. Record the result and set the proposal text
accordingly.

Output: stack-report.cjs, a fixture module, tests, and adopt integration.
</objective>

<anti_patterns>
- Rows that fire on every repo (noise). Severity follows the research table: GO-COVER is info,
  GO-LINT is info when go vet is present, and so on. A check whose stack isn't detected emits nothing.
- Treating `uses:` actions as absent (the golangci-lint action counts as GO-LINT present).
- Proposing flags you haven't verified. DART-COVER: `flutter test --coverage` (verified). The
  `dart test --coverage=coverage` text is used only if the Q8 fixture check confirms it, else the
  proposal says "verify locally".
- Proposing tools as if installed. The proposal names the tool. Presence isn't assumed (staticcheck,
  hadolint and osv-scanner are absent on this machine).
</anti_patterns>

- Keep IDs stable. Renaming an ID is a breaking change for anyone grepping reports.

## Test list

Outermost to innermost.

1. CLI `stack report --write` on a Go fixture with CI `go test ./...` (no -race), no vet, no govulncheck, and a Makefile with `test` only: the file is written, frontmatter counts are correct, and GO-RACE, GO-VET and GO-VULN are gaps. `.github/workflows` is unchanged (content hash equal).
2. CLI `stack report --raw` writes nothing and returns JSON findings sorted by (severity, component, id).
3. CLI `stack report --draft --raw` on a repo without STACK.md: `profile_source: 'draft'`, and STACK.md still doesn't exist.
4. Applicability: a pure Go repo has zero DART-*/FLUT-* rows. A Flutter app with no `.maestro/` gets FLUT-MAESTRO info. With `.maestro/` plus CI `maestro test`, there is no FLUT-MAESTRO row.
5. Weak: `flutter analyze --no-fatal-infos` gives DART-ANALYZE weak. Bare `gofmt -l .` gives GO-FMT weak. A step with `continue-on-error: true` running golangci-lint gives GO-LINT weak.
6. Expansion: CI `make lint` whose Makefile body is `golangci-lint run` counts as GO-LINT present. A CI step `./scripts/vuln-gate.sh` whose body contains `govulncheck` counts as GO-VULN present.
7. `uses: golangci/golangci-lint-action@v6` counts as GO-LINT present.
7r. Record level (Task 1 only): `buildRecords` sets `weakMarkers` (`--no-fatal-infos`, `|| true`, bare `gofmt -l`) and `continueOnError`. A CI `make lint` yields a CI record plus an expanded record with `origin: 'runner'` and the target body text. `./scripts/x.sh` yields `origin: 'script'` records from the file body. `uses:` yields `text: 'uses:golangci/golangci-lint-action'`. A self-referencing target doesn't loop.
8. LOCAL-MIRROR: CI has `go vet`, runners have no vet target, so the gap names `lint`. When the runner has it, there is no row.
9. CI-MISSING: no `.github/workflows` gives an info row. HELM-LINT is a gap when Chart.yaml exists and only `helm lint` runs (no kubeconform).
10. GO-GEN-DRIFT is a gap when `sqlc.yaml` exists and no `git diff --exit-code` follows a generator in CI.
11. Draft notes: a missing-binary fixture gives a `DRAFT-NOTE-test` info row naming the candidate and binary_missing.
12. Deterministic: two runs give byte-identical output (with the date injected).
13. adopt report: STACK-REPORT.md is written when absent and not overwritten when present. ADOPT-REPORT.md links it. Each gap gives one medium row.
14. Q8 probe, SKIP-ONLY: `t.skip` when dart is absent. When present, run `dart test --coverage=coverage` in a temp minimal Dart package and log the outcome via `t.diagnostic`. This test never fails on the outcome; it only informs the DART-COVER proposal text and the SUMMARY.
