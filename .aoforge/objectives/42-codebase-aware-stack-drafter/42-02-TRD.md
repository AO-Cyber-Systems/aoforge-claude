# TRD 42-02: Ship fixed go/dart/flutter as bundled tier-2 profiles

<objective>
SDR-04, plus the data half of SDR-05. Fix the three draft profiles and move them into a new plugin
directory, `plugins/devflow/devflow/stack-profiles/`. Teach the loader to look in a bundled tier
after the user/org tier (`~/.claude/devflow/stacks/`), so drafts can say `extends: go|dart|flutter`.
The profiles' `agent_tooling.mcp`/`skills` are then inherited by every draft (SDR-05 data).

Locked decision: tier-2 profiles are NOT mirrored into `~/.claude/devflow/stacks/`. That directory
stays user/org territory. The sync-runtime swap `removeDir(target)` would wipe it (research Pitfall 1).

Purpose: every fleet draft is currently `extends: general`. This makes tier-2 real.
Output: three fixed profiles, the bundled-tier loader lookup, repointed tests, and the one-line
sync-runtime `SUBDIRS` entry that keeps the drift guard green. The docs/stack-profiles/README.md
pointer, the stacks-survive regression test and the testing-strategy/PROPOSAL pointers ship in 42-10.

## Accepted SDR-04 deviations (recorded at planning, accepted by job-checker)

- **"ship/install them as tier-2"**: the profiles are shipped **bundled** in the plugin
  (`devflow/stack-profiles/`, resolved after the user tier). They are **not installed** into
  `~/.claude/devflow/stacks/`, which stays user/org territory (locked decision; the mirror swap
  would wipe it).
- **"flutter enabled_tools whitelist → disabled_tools"**: implemented as server `args`
  (`--enable cli --disable pub_dev_search`). There is no `enabled_tools`/`disabled_tools` list,
  because `dart mcp-server` filters by FEATURE flags and `.mcp.json` has no per-tool filter
  (verified live, research 2.2).
- **"add maestro to flutter"**: added as Testing prose, not a default `e2e` command. The drafter
  (42-07) emits `e2e: maestro test .maestro` only when `.maestro/` exists, and the report (42-08)
  proposes it for Flutter apps without flows.

## Keeping the suite clean in this wave

Creating `devflow/stack-profiles/` would make `hooks/sync-runtime.test.js` case B ("drift guard: no
real devflow/ subdir is absent from the mirror") fail. Task 1 therefore adds `'stack-profiles'` to
`SUBDIRS` in the SAME commit that creates the directory. Case B reads `SUBDIRS` from the hook source,
so no test edit is needed. The per-wave `npm test` gate stays at the 2 known handoff-e2e failures.
</objective>
