<codebase_examples>
stack-draft.cjs ranking today considers only source, confidence and weak:
```js
function rankOf(item) {
  const s = SOURCE_RANK[item.source];
  return [s === undefined ? 9 : s, item.confidence === 'low' ? 1 : 0, item.weak && item.weak.length ? 1 : 0];
}
```
The root-key loop in `assembleDraft` walks `runCands` in rank order and takes the first `resolved`
one. The inherit path already exists: `equivalent(c, parentRun)` sets `inheritedAt`, so an omitted
key means inherited.
stack-runners.cjs Make targets push `{ runner, dir, file, name, aliases, body, invocation }`
(collectMake ~line 221). Taskfile tasks come from `parseTaskfile` → `{ name, aliases, body, dir }`,
and justfile recipe headers carry `name params: deps`.
stack-evidence items: `{ key, command, form, source, sourceFile, cwd, area, runner, confidence, weak, tool }`.
</codebase_examples>

<anti_patterns>
- Rejecting `go test -short ./...` or `go test -race -coverprofile=c.out ./...`. Those are broad.
  Only the listed narrowing shapes are narrow.
- Treating `-count=1` / `-v` / `-timeout` as narrowing.
- Ranking by alphabetical target name. Use the canonical order, then source order.
- Emitting new `integration`/`e2e` keys from narrow candidates. Those go to notes only.
- Changing the order of non-runner sources (declared > runner > ci > manifest stays).
</anti_patterns>

<error_recovery>
- A runner test target whose body can't be read (`unverifiable-body`-like) keeps today's behaviour:
  breadth `unknown` is treated as broad, so no regression. Note it with status `breadth-unknown`.
- If canonical ranking changes an existing e2e expectation, check that fixture. If the old pick was a
  variant, the new pick is the fix; say so in the commit body. Otherwise, fix the ranking.
</error_recovery>
