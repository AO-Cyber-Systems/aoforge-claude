# TRD 32-02: The offline path stops fabricating a score, and every state is nameable

<objective>
Close AO-Cyber-Systems/aodex#485's second defect: `flutter-ui-eval.cjs:343` returns
`confidence: 0.99` and `matches_expected` for a comparison that never happened. The offline
judge reads only `request.state_id` — it never opens `screenshot_path` and never reads
`expected`. Any consumer reading those fields would reasonably conclude a judge looked at
the image.

Also closes a corollary found during planning: the planner's own `buildManifestStub` emits
states keyed `id`, while the engine reads `state_id`, producing `"reviews": [null]` — a
finding nobody can act on because it has no name.

Resolved intent: kind=plugin, work=bugfix, tdd=strict, depth=comprehensive,
fixture_strategy=generators. Constraints honored: no_llm_test_data, no_property_based_default,
no_gherkin_layer.
</objective>

  `confidence`/`matches_expected` is not an error when evidence is `label`).

<gotchas>
- **`confidence` and `matches_expected` are currently REQUIRED by `validateJudgeResult`.**
  You cannot simply delete them from the offline result — every offline state would fail
  validation and drop to `review`, which would be wrong for a LABELLED state. A hand-written
  label IS a legitimate deterministic assertion; it just is not a perceptual one. Make the
  validator evidence-aware (C2/C3) in the same change that drops the fields.
- **Back-compat is load-bearing here.** `flutter-ui-eval-fixtures.cjs:71` builds results with
  `confidence: 0.9` and the existing suite asserts they validate. C4 pins that. Gate the new
  strictness on `evidence === 'vision'`; leave the legacy path (no `evidence` field) exactly
  as it is.
- The live path's `parseVisionResponse` produces the vision-side result — tag it
  `evidence: 'vision'` there, not at the call site, so every live result is tagged regardless
  of caller.
- For A1, accept `st.id` as a fallback for `st.state_id` **with an advisory** — do not
  silently normalise. The point is that the state becomes nameable, not that the shape
  mismatch becomes invisible.
- `${PIPESTATUS[0]}` inside `bash -c '...'` (or `set -o pipefail`) — never bare `$?` after
  a pipe. The interactive shell is zsh; always wrap.
</gotchas>

<anti_patterns>
- Do NOT keep `confidence` and merely lower the number (e.g. `0.5`). An invented number is
  still an invented number; the fix is to stop reporting a score for an unperformed
  comparison, not to report a humbler fake one.
- Do NOT drop `evidence` in favour of relying on the existing top-level
  `judge: 'offline-label-echo'` field. That is a RUN-level field; a single JudgeResult
  handed to a consumer in isolation must carry its own provenance.
- Do NOT weaken C4's legacy path to make C3 simpler. The existing 60 tests are the
  regression net for this whole objective.
- No new dependencies.
</anti_patterns>

<error_recovery>
- If dropping the fields cascades into `aggregateVotes`/`scoreState` failures, check whether
  those functions read `confidence` — planning confirmed they do NOT (they read `is_broken`
  and `defects[].severity` only). A failure there means something else changed.
- If C4 breaks, you have made the new strictness unconditional instead of evidence-gated.
</error_recovery>
