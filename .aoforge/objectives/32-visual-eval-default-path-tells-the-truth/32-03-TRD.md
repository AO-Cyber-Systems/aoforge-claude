# TRD 32-03: Judge selection is explicit, and the default stops claiming gate authority

<objective>
Close AO-Cyber-Systems/aodex#485's third defect: `--judge live` is opt-in, so a plain
`verify flutter-ui-eval <manifest>` is a labels lookup wearing a gate's clothing.

**The decision (made deliberately; full reasoning in OBJECTIVE.md "Decision: what the
default judge does"):** the default stays offline-labels and stops claiming to be a gate.
Judge selection becomes explicit, and the rollup declares its own standing — `binding` on
the live path, `advisory` on the labels path. Only a `binding` pass may clear a surface
from human verification.

Rejected: making live the unconditional default (would make the dogfood suite issue real
billed nondeterministic vision calls, breaking the `network: false` contract). Rejected:
live-when-credentials-present (a run whose meaning you cannot read off the command — the
#485 failure mode in different clothes).

Resolved intent: kind=plugin, work=bugfix, tdd=strict, depth=comprehensive.
Constraints honored: no_llm_test_data, no_property_based_default, no_gherkin_layer.
</objective>

<gotchas>
- **G3 must not make a real API call.** Run it with the credential env vars unset
  (`env -u ANTHROPIC_API_KEY -u ANTHROPIC_AUTH_TOKEN -u ANTHROPIC_BASE_URL ...` — verified
  during planning to produce the credential-less downgrade above). Asserting `gate` on a
  credential-less live run is free, deterministic, and CI-safe. A test that would spend
  money if a key happened to be exported is not acceptable.
- `gate` is the run's STANDING (what authority its verdict carries), not its OUTCOME. A
  live run that fails is still `binding`. Do not conflate them.
- Also update 32-01's `unjudged[]` narrative in the verifier doc if the routing block
  references reviews only — an `unjudged[]` entry must also keep the surface on the human list.
- `${PIPESTATUS[0]}` inside `bash -c '...'`; never bare `$?` after a pipe.
</gotchas>

<anti_patterns>
- Do NOT make `live` the default, conditionally or otherwise. See the rejected options in
  `<objective>` — both were considered and rejected with reasons; re-litigating them in
  code is out of scope for the executor.
- Do NOT remove the offline path or make `--judge` mandatory. A bare invocation must keep
  working for dogfooding; it just must stop claiming gate authority.
- Do NOT let the `gate` field replace `judge`/`network`. They answer different questions
  (what ran / did it touch the network / what authority does the verdict carry).
- No new dependencies.
</anti_patterns>

<error_recovery>

  sentence — the whole point is that an advisory pass may NOT claim that payoff.
</error_recovery>
