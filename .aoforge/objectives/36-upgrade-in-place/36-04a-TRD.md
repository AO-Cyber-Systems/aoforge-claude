# TRD 36-04a: Migrations 0001–0003, moved out of validate.cjs

<objective>
Write the first three registry migrations and make `validate health --repair` call them, so each
repair lives in one place:

| Id | Safety | Detects | Does |
|---|---|---|---|
| 0001 config-stamp | auto | config.json absent, flat v1 keys present, or a template top-level section missing | writes the nested template shape, preserving every effective setting |
| 0002 job-to-trd | auto | `*-JOB.md` / `JOB.md` under objectives/ without a TRD counterpart | renames to TRD, logs one line in STATE.md |

The runner (36-01) writes the `devflow{}` stamp itself. 0001 only guarantees the file and its
shape.

## Runtime model (binding, from OBJECTIVE.md)

- CommonJS, sync fs, no new deps. Migrations require from `..` (`../config.cjs`, `../state.cjs`).
- Migration files export `{ id, title, since: '2.11.0', safety, detect, apply }` plus named helpers.
  `since` is the next release version (the one that will ship them); nothing bumps the version here.
- Tests use mkdtemp projects and homes. Nothing touches the real `~/.claude`.
- Commits via `df-tools commit --files`. 1Password failure → STOP and report. Never bypass signing.
- One plain command per Bash call. Never port 8080.
- Commits: `test(36-04a): ...` → `feat(36-04a): ...` → `refactor(36-04a): ...` for the validate rewiring.

   and write the output to a file in your session scratchpad (never the repo).

   `test at <file>:<line>:<col>` then `✖ <name> (<ms>)`; strip the duration.

5. **Never edit `baseline-failures.tsv`** to pass the gate. Tests added by this objective are not in
   the TSV and must pass.
