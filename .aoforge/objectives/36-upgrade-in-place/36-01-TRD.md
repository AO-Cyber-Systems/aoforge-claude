# TRD 36-01: The upgrade runner — registry, contract, backup, stamp, report

<objective>
Build `lib/upgrade.cjs`, the engine every other TRD in this objective plugs into. It loads a
registry of one-file migrations, validates each against the migration contract, runs `detect` on
each in id order, and on `apply` backs up outside the repo, runs the selected migrations, stamps
`config.json`, and returns a report. No real migrations exist yet (36-04a/b/c add them); every test
here uses fixture registries written into temp dirs.

Also build the shared fixture module every later objective-36 test imports. `fixture_strategy:
generators` → Task 1 writes the builders first.

Resolved intent: kind=plugin, work=feature, tdd=strict (OBJECTIVE `overrides.tdd`),
depth=comprehensive, test_list_first=required, fixture_strategy=generators.
Constraints honored: `no_llm_test_data` (hand-built builders), `no_property_based_default`,
`no_gherkin_layer`.
</objective>

## Runtime model (binding, from OBJECTIVE.md)

- CommonJS `.cjs`, synchronous fs, **no new npm dependencies**. Node built-ins only in upgrade.cjs
  (`fs`, `path`, `os`, `crypto`).
- `userHome` is **injected**. Tests use `fs.mkdtempSync` fake homes. **Nothing may read or write the
  real `~/.claude`.** upgrade.cjs never calls `os.homedir()` itself; the caller passes `userHome`.
- Git fixtures set `commit.gpgsign=false` with `git -C <fixture> config` — **on the fixture repo
  only**. Never on this repo, never `--global`.
- Commits go through `node ~/.claude/devflow/bin/df-tools.cjs commit "<msg>" --files <paths>`. If
  signing fails (`1Password: agent returned an error`), STOP and report. Never bypass signing.
- One plain command per Bash call. No DevFlow gate is bypassed. Never use port 8080.
- Commits: `test(36-01): ...` (RED) → `feat(36-01): ...` (GREEN) → optional `refactor(36-01): ...`.

## Test list

Copy this list into the header comment of `upgrade.test.cjs` first (house style:
`brownfield-detector.test.cjs:1-27`). Order is outermost (report shape) to innermost (helpers).

Registry (loadRegistry):
1. Missing registry dir → `[]`.
2. Three valid migrations written as `0003-c.cjs`, `0001-a.cjs`, `0002-b.cjs` → returned in id order 0001, 0002, 0003.
3. `0001-a.test.cjs` and `README.md` in the dir are ignored.
4. Missing `detect` (or `apply`) → `RegistryError`; `problems` names the file and the missing field.
5. `safety: 'maybe'` → `RegistryError` naming the allowed values `auto|confirm`.
6. `id: '0002'` inside file `0001-a.cjs` → `RegistryError` (id/filename mismatch).
7. Two files with id 0001 → `RegistryError` (duplicate id), and `problems` lists BOTH files.
8. `since: 'soon'` → `RegistryError` (must be `X.Y.Z`).
9. Several bad files → ONE error whose `problems` has one entry per bad file (report everything, not first-only).

check():
10. v1 fixture + fixture registry {0001 auto applies, 0002 auto not-applicable, 0003 confirm applies} → `pending=[0001]` (with `safety:'auto'`, `title`, `reason`), `pending_confirm=[0003]`, `skipped=[{id:'0002', reason}]`, `from: null`, `to: <pluginVersion>`.
11. check() writes nothing: `snapshot(project)` before === after, and no `backups/` dir under the fake home.
12. A `detect` that throws → entry in `failed` with `phase:'detect'`; `up_to_date` is false (a check that could not run is never a pass).

apply():
13. Applies 0001 only (0003 is confirm, not named) → `applied=[0001]`, `pending_confirm=[0003]`, `changed_files` = 0001's paths + `.planning/config.json`.
14. `only: ['0003']` → runs the confirm migration 0003 and not 0001; stamp version NOT advanced (0001 still applicable and unrun) but `migrations_applied` includes 0003.
15. `confirm: true` → runs 0001 and 0003; stamp `version === to`.
16. `only: ['9999']` → throws `RegistryError` "unknown migration id 9999".
17. Backup: path is `<home>/.claude/devflow/backups/<slug>-<8 hex>/<ts>/`, contains `.planning/config.json` with the PRE-apply bytes and `CLAUDE.md` when present; `path.relative(project, backup)` starts with `..`.
18. Two applies in the same millisecond `now` → distinct backup dirs (`-1` suffix), never overwrite.
19. A migration whose `apply` throws → `failed=[{id, phase:'apply', error}]`, later migrations do NOT run, stamp version not advanced, report still returned (no throw).
20. A migration returning `changed: ['/abs/x']` or `['../x']` → `failed` with a path error.
21. `dryRun: true` → migrations receive `ctx.dryRun === true`, no stamp written, no backup, tree unchanged; `changed_files` lists what WOULD change.
22. Second apply → `applied: []`, `changed_files: []`, `backup: null`, tree byte-identical (idempotence of the runner).
23. Stamp-only: project stamped `2.0.0`, no migration applies, `to = 2.10.1` → stamp rewritten to `2.10.1`, `changed_files: ['.planning/config.json']`, `backup: null`; other config keys (and key order) preserved.
24. `ctx` shape: a probe migration records the ctx it received → `{projectRoot, userHome, pluginVersion, dryRun, options}` exactly.

Stamp helpers:
25. `readStamp` → `null` when config.json is absent or has no `devflow`; returns `{version, migrations_applied, upgraded_at}` otherwise.
26. config.json that is not valid JSON → `apply` does not write it; `failed` has `{id:'stamp', error}`.

<gotchas>
- **Repo slug + hash:** slug = `path.basename(fs.realpathSync(projectRoot))` lowercased, non
  `[a-z0-9]` runs → `-`; hash8 = `sha1(fs.realpathSync(projectRoot)).slice(0, 8)`. On macOS, mkdtemp
  paths under `/var` realpath to `/private/var`; always realpath before hashing so the hook, the CLI
  and tests agree.
- **Timestamp dir:** `now.toISOString().replace(/[:.]/g, '-')`. If it exists, append `-1`, `-2`, …
  Never overwrite a backup.
- **Guard:** if the computed backup dir is inside `projectRoot` (`!path.relative(projectRoot, dir).startsWith('..')`),
  throw. Backups inside the repo are exactly what this objective removes.
- **Backup only when a migration will write.** A stamp-only change does not back up (test 23).
- **writeStamp** must preserve key order and every other key: parse, set `devflow`, stringify with
  2 spaces + trailing newline. Absent config.json → create `{ "devflow": {...} }`.
- **`version` advance rule:** set `devflow.version = to` iff `failed` is empty AND no applicable
  `auto` migration was left unrun (because of `only`). Otherwise keep the previous version (or omit).
- `detect` receives the same `ctx` as `apply`. Migrations are responsible for honouring `ctx.dryRun`
  (36-04 tests that); the runner additionally skips backup and stamp on dryRun.
- Load migration modules with `require(abs)`; delete `require.cache[abs]` first so tests that rewrite
  a registry file see the new source.
- `fs.cpSync(src, dst, { recursive: true })` is available (Node ≥ 16.7; this machine runs 24).
</gotchas>

<anti_patterns>
- Trusting the stamp alone to decide what is pending. `detect` decides; the stamp is a record.
- Writing a backup under `.planning/` or anywhere in the repo.
- Calling `os.homedir()` inside upgrade.cjs (tests could then touch the real home).
- Stopping at the first registry problem (test 9 requires all problems).
</anti_patterns>

<error_recovery>
- A test leaks files into the real home → stop, remove only the leaked path you created, and trace
  the call missing its `userHome`. Never "clean up" anything else in `~/.claude`.
</error_recovery>

     name, re-run output and why it's unrelated. Don't block.
5. **Never edit `baseline-failures.tsv`** to pass the gate. Tests added by this objective are not in
   the TSV and must pass.
