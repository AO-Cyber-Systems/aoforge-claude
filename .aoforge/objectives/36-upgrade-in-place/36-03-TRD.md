## Runtime model (binding, from OBJECTIVE.md)

- **Tests spawn the CHECKOUT CLI** (`plugins/devflow/devflow/bin/df-tools.cjs`) with
  `env: gitEnv(fakeHome)` (HOME, XDG_CONFIG_HOME, GIT_CONFIG_NOSYSTEM) and `cwd`/`--path` at an
  mkdtemp project. **Nothing reads or writes the real `~/.claude`.**
- The mirror (`~/.claude/devflow`) does not have `upgrade` until release. For manual checks, use
  `node plugins/devflow/devflow/bin/df-tools.cjs …` from the repo root, and only with `--check` or
  against a temp project. Do NOT run `upgrade --global` without `HOME=<fake>` in this TRD.
- CommonJS, sync fs, no new deps. Commits via `df-tools commit --files`; 1Password failure → STOP,
  never bypass. One plain command per Bash call. Never port 8080.

<gotchas>
- `--only` accepts `0006` or `0004,0006` or repeated flags. Pass an array to upgrade.cjs.
- `--path` resolves relative to `cwd`; `cwd` is the default. Refuse a path without `.planning/` for
  `--apply` (exit non-zero). `--check` on such a path prints `not a DevFlow project` and exits 1.
- Exit codes: `output(report, raw, summary, report.failed.length ? 1 : 0)`.
- Global mode: `--global` alone = check (`dryRun: true`); `--global --apply` = apply without
  adoption; `--global --confirm` = apply with adoption. `userHome = os.homedir()` (spawned tests set
  HOME).
- The `validate.test.cjs` runHealth helper mocks `process.exit`. W040 tests must pass `homeDir: tmpHome`
  so the backup/lookup never resolves the real home.
- gen-docs (`scripts/gen-docs-data.cjs`) parses df-tools.cjs; a new case is picked up automatically.
</gotchas>

daemon/PID tests fail in any git worktree). So this gate compares failing test **names** against
`.planning/objectives/36-upgrade-in-place/baseline-failures.tsv` (21 lines, `file:line<TAB>name`),
not counts.

   `node --test --test-reporter=spec 'plugins/devflow/**/!(micro).test.cjs' 'plugins/devflow/**/*.test.js' 'scripts/**/*.test.cjs'`
   and write the output to a file in your session scratchpad (never the repo).
2. Extract failing names from the closing `✖ failing tests:` section: each entry gives
   `test at <file>:<line>:<col>` then `✖ <name> (<ms>)`; strip the duration.
3. A failure whose name is in the TSV's second column is **pre-existing**.
4. Any other failure is a candidate regression. Re-run just its file with `node --test <file>`.
   - Passes on re-run → **environment flake**, record the evidence.
   - Still fails and this TRD's diff (`git diff --stat <wave base>`) touched code it exercises →
     **regression, blocks**. Fix it before completing.
   - Still fails and plainly unrelated (PTY/handoff timing) → **environment flake**; record file,
     name, re-run output and why it's unrelated. Don't block.
5. **Never edit `baseline-failures.tsv`** to pass the gate. Tests added by this objective are not in
   the TSV and must pass.
