# TRD 43-10: Primary component and scope in multi-stack roots

<objective>
Fix root cause (ii), the wrong primary component or scope in a multi-stack root, on the real evidence shapes:
- eden-biz picks `flutter/` (one CI e2e step through its Makefile lifts it) over `go/`.
- politihub picks `flutter-navigators/` (most CI items) over `go/`, whose CI runs tools directly.
- aodex: a root release `docker build … ${{ }}` displaces the primary's `make build` and drafts `discover`.
- eden-libs: the root justfile's fan-out recipes are attributed to the first sub-dir they `cd` into and become sub_area notes, so a component leg (`dart test` in one package) wins `test`, and `just generate`, `just fmt` and `just build-flutter-explorer` are lost.

Purpose: closes eden-biz `build`/`test`, aodex `build` and eden-libs `build`/`test`/`codegen`/`format`. It may also close politihub, which is out of scope but recorded.
Output: three placement rules in stack-draft.cjs, one evidence field, and four realshape fixtures.
</objective>

<anti_patterns>
- Weighting by component profile (go over flutter) beyond the existing tie-break. The evidence decides; go-first only breaks ties.
- Exempting all root candidates from off_primary. Only a workspace root drops the gate, because it has no primary at all.
- Changing `scopeOf`'s effectiveArea for fan-out bodies. Placement reads `unitAreas` and the runner-file location instead, which keeps 42-15/43-05 sub_area behaviour for CI items.
- A fixture where the go component's CI calls `make build`. The 43-06 politihub fixture did that and passed while the real repo failed. Model the CI running tools directly.
</anti_patterns>
