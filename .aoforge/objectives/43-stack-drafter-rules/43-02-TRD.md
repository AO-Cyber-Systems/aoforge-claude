# TRD 43-02: Effect-based `stack verify --run` guard (D8, SDR-03)

<objective>
Make `stack verify --run` side-effect safe by effect, not by key name.

In objective 42's rollout, the "safe" lint key ran `flutter analyze --fatal-infos`. That command rewrote `analysis_options.yaml` (adding `analyzer.exclude`) and ran an implicit `pub get` that bumped `pubspec.lock` in aocore, aofamily and aoid. The rollout harness caught this only from outside. This TRD moves the guard into `runOne` and adds prevention: `--no-pub` for flutter analyze/test.

Purpose: SDR-03 hardening, and the prerequisite for the real fleet `--run` pass in 43-07 (SDR-08).
Output: snapshot/diff/restore around the spawn, the halt rule, the `--no-pub` rewrite, new skip reasons, and a real-spawn stub-flutter regression.
</objective>

<anti_patterns>
- Porcelain-line-only comparison (Pitfall 1). Use hashes.
- Copying the component to a temp dir. Research rejected it (large repos, relative path deps).
- Rewriting the stored STACK.md command for `--no-pub`. Rewrite only the executed text.
- Running `pub get` to satisfy `--no-pub`. Skip with `needs-pub-get` instead.
- A file watcher, or `fs.watch`. Use git (Don't Hand-Roll table).
- Snapshotting via the injected `opts.spawn`. Git calls must use real `spawnSync` (or a separately injectable `opts.git`), or the existing fake-spawn tests would get git calls routed into their fakes.
</anti_patterns>

<error_recovery>
- Restore order: for a path untracked before and present after → unlink. For a path present before (tracked or untracked) whose hash changed or that was deleted → write the saved bytes back and restore the mode. Paths over 1 MB before the run can't be restored from memory. Restore those via `git checkout -- <p>` only when they were clean before, otherwise `restored:false` with the path listed. Report `run.restored` as true only if every path was restored.
- If `git status` fails mid-run (lock contention), treat the after-snapshot as unknown: `run.mutated_unknown: true` and halt the root.
</error_recovery>
