# TRD 43-13: CI variants never displace the canonical build and test

<objective>
Fix the second half of root cause (i), "a CI variant beats the canonical command", on aocore's runner-less `go/` component:
- build: every CI build is a single-binary variant (`go build -tags dev -o /tmp/dev-edge ./cmd/dev-edge`, `go build -o /tmp/srv ./cmd/server`, `go build ./cmd/server`, plus a db-backed test script that builds three binaries). The first variant wins. The reviewed value is the tier default `go build ./...` (cwd go).
- test: the heavy lane `go test -short -p 1 ./... -race -skip "${SKIP}" -coverprofile=unit.out -timeout 35m` wins because its workflow sorts first. `${SKIP}` is assigned in the same step from a script. The reviewed value is the light lane.

Purpose: closes aocore.build. aocore.test closes, or narrows to a flag-only residual that is listed for the user in 43-15.
Output: `buildBreadth`, `step.runtimeVars`, two draft rules, and the build/test half of `ciVariantComponentShape`.
</objective>

<anti_patterns>
- Ranking by workflow file name or by the word "heavy". Use structure: a runtime-assigned variable, and breadth.
- Treating every `$VAR` as runtime. 43-09 substitutes workflow, job and step `env:` literals first. Only names assigned inside the run block (command substitution, `export`, a `read` loop variable) are runtime.
- Writing the fallback when the list was empty to begin with. With no build candidate, the existing behaviour (inherit, or the single-component fallback) is unchanged.
</anti_patterns>

<error_recovery>
- If the runtime-var rank changes a matching repo's test, look at what wins there. If the committed value is itself a runtime-var command, keep the rule only for `test`/`build` lanes where a same-source, same-area, non-runtime broad candidate exists.
- If buildBreadth calls a matching repo's CI `go build -o bin/app .` narrow and that repo's committed build is that line, limit "narrow" to explicit sub-package operands (`./cmd/x`, `./internal/...`) and keep `.`/no-operand builds broad. Record it.
</error_recovery>
