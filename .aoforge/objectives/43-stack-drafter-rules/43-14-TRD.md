## Binding rules

- Use the CHECKOUT df-tools: `DF=/Users/justin/dev/devflow-claude/plugins/devflow/devflow/bin/df-tools.cjs`, invoked as `node $DF --cwd ~/dev/<repo> …`. Never the mirror.
- Same per-repo write discipline as objective 42's rollout (42-11 TRD): write and commit ONLY `.planning/STACK.md` and `.planning/STACK-REPORT.md` on the CURRENT branch through `node $DF --cwd <repo> commit "<msg>" --files .planning/STACK.md .planning/STACK-REPORT.md`. Never a raw git commit, never `git add` of anything else, never stash or restore user files, never push.
- **Staged-index stop rule (user, 2026-10-03).** If `git diff --cached --name-only` in a repo is non-empty, STOP for that repo. Report the staged paths and write nothing. df-tools commit also refuses when something outside `--files` is staged; the preflight catches it first.
- A repo whose HEAD moves between the preview (Task 1) and the write (Task 3) is skipped and recorded, not re-previewed silently.
- No `--run`, no gates executed, no `.mcp.json`. Never port 8080. One plain command per Bash call (the worktree guard refuses compound commands).

<anti_patterns>

- Committing with `git -C <repo> commit -a` or adding the user's dirty files.
- "Fixing" the draft by hand to keep the old `extends: go` keys. The refresh accepts the drafter's output. If the preview looks wrong, the human says so at the checkpoint and the repo is skipped.
</anti_patterns>

<error_recovery>
- If `stack validate` fails after `--write`, restore the two stack files from HEAD (`git -C <repo> show HEAD:.planning/STACK.md` written back by df-tools, or `git -C <repo> restore --source=HEAD -- .planning/STACK.md .planning/STACK-REPORT.md`; these touch only the two files), record the failure, and do not commit.
- If the delta check shows any change outside the two stack files, restore only the two files and stop for that repo. Report the delta.
- If df-tools commit refuses (staged paths, gate), report its exact message and do not bypass it.
</error_recovery>
