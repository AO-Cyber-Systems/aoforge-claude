<anti_patterns>
- Comparing raw frontmatter with `deepEqual`. Compare only the defined scope, using effective commands.
- Reading the committed STACK.md from the work tree. A dirty or refreshed work tree would hide the committed value.
- Using a stub PATH or an empty HOME in the FLEET harness. It must use the real environment (`process.env`), because the 43-07 dry run did and the verifier's `resolved` answers depend on the real toolchain. (The golden and realshape suites use stubs; this one does not.)
- Seeding KNOWN_DRIFT by hand from 43-ROLLOUT.md without running the harness. Seed from a real run, then compare with the table above and explain each difference.
- Letting a KNOWN_DRIFT entry silently go stale. The ratchet must fail with "<repo>.<key> no longer drifts: remove it from KNOWN_DRIFT".
</anti_patterns>

<error_recovery>
- If a fleet repo's HEAD moved since 43-07 and its row changed, record the new HEAD and the changed row in the SUMMARY. Seed what the harness sees today. Do not re-pin.
- If `stack init` exits non-zero for a repo, the harness reports that repo as a failure with stderr, not a skip. Only absence skips.
- If the porcelain before and after differ for a repo, stop: the drafter wrote something. Report the delta and do not commit until the cause is understood.
</error_recovery>

## Test list

Helper (`stack-drift-compare.test.cjs`, hand-built frontmatter pairs, no fs):
1. Identical committed and draft: no rows.
2. Same key, different `run`: one `conflict`.
3. Committed has a command, draft says `discover`: `conflict`.
4. Committed `discover`, draft has a command: `more_specific`.
5. Draft-only key: `more_specific`. Committed-only key: `conflict`.
6. Committed `apply` the draft lacks: `conflict`. Different `cwd`: `conflict`.
7. Draft omits a key the committed file writes with the extends tier's exact value: no row (effective commands are equal through inheritance).
8. A HAND_ONLY key that differs: no row, and it is named in the result's `skipped`.
9. Committed `helm_lint` vs draft `lint_helm` with the same command: no row (alias).
10. Different `extends`: a `conflict` row with key `extends`. A different components set: a `conflict` row with key `components`.
11. Out-of-scope fields (`when`, `scoped`, `timeout_s`) differ: no row.

Harness (`stack-drafter-fleet.test.cjs`, real fleet):
12. Per repo: no conflict outside ACCEPTED and KNOWN_DRIFT; more-specific rows are reported with `t.diagnostic`, never failed.
13. Ratchet: every KNOWN_DRIFT key still drifts; a closed one fails with a "remove it" message.
14. Read-only: HEAD and porcelain equal before and after, per repo.
15. Table guards: ACCEPTED is exactly `{ devcluster: lint, test }` plus the imported HAND_ONLY keys; every KNOWN_DRIFT entry has `keys`, `closes` and `reason`.
