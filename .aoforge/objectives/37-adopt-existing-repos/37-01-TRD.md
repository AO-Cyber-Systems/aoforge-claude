# TRD 37-01: Fixture factory + the one repo-state detector

<objective>
Two foundations. First, the fixture factory every objective-37 test and simulated run uses to build
scratch git repos (Go service, Flutter app, Node CLI, empty, already-DevFlow, dirty tree). Second,
`lib/repo-state.cjs`: one detector that classifies a directory as `devflow | greenfield | brownfield
| scratch` and returns the raw signals plus the legacy derived flags. 37-04 then makes the three
existing heuristics delegate to it.

`fixture_strategy: generators` → Task 1 writes the builders first.

## Runtime model (binding, from OBJECTIVE.md)

- CommonJS `.cjs`, synchronous fs, **no new npm dependencies**. Node built-ins only.
- `userHome` is **injected**. Tests use `fs.mkdtempSync` fake homes. **Nothing may read or write the
  real `~/.claude`.** repo-state.cjs never calls `os.homedir()`.
- Fixture git repos set `commit.gpgsign=false` and `tag.gpgsign=false` with `git -C <fixture> config`
  — **on the fixture repo only**. Never on this repo, never `--global`. Every fixture git call uses
  `gitEnv(home)` so the user's global git config is never read.
- **Never touch any real user repository.** Fixtures live only under mkdtemp or the session scratchpad.
- Commits go through `node ~/.claude/devflow/bin/df-tools.cjs commit "<msg>" --files <paths>`. If
  signing fails (`1Password: agent returned an error`), STOP and report. Never bypass signing.
- One plain command per Bash call. No DevFlow gate is bypassed. Never use port 8080. No version bump,
  tag or push. Execution is serialized: one TRD at a time in the main checkout.
- Commits: `test(37-01): ...` (RED) → `feat(37-01): ...` (GREEN) → optional `refactor(37-01): ...`.

<gotchas>
- macOS `os.tmpdir()` is under `/var/folders/`, which the legacy scratch rule treats as scratch. Every
  signals test that expects `brownfield` must pass `scratchPrefixes: []`. That is also why 37-05's
  preflight treats `scratch` as adoptable (the user asked explicitly; scratch only suppresses
  UNSOLICITED offers).
- `isScratchDir` checks the path AS PROVIDED (no realpath), matching project-state.cjs :60-62. Keep
  that; 37-04's parity test depends on it.
- `gitAgeDays(cwd)` (project-state.cjs :254) takes no env and only runs `git log`; reuse it as is.
  A fixture committed now → `0`.
- The CLI's "inside a git work tree" guard: `git -C <parent> rev-parse --is-inside-work-tree` exit 0
  → refuse. Run it with `gitEnv(home)` when `--home` is given; a missing parent is created only
  after both guards pass.
- Deterministic commits: set `GIT_AUTHOR_DATE`/`GIT_COMMITTER_DATE` to the current time is fine;
  do not hard-code a past date (it would make `git_age_days` > 7 and flip `is_substantive`).
</gotchas>

<anti_patterns>
- Calling `os.homedir()` in repo-state.cjs or the factory.
- Letting the factory create anything outside `parent` (e.g. a default under `/tmp`).
- Generating fixture file contents with an LLM or at random. Literal strings only.
- Folding git cleanliness into `state`. Dirty/busy/detached are preflight concerns (37-05).
</anti_patterns>

<error_recovery>
- A test leaks files into the real home → stop, remove only the leaked path you created, and trace
  the call missing its `userHome`/`gitEnv(home)`. Never "clean up" anything else in `~/.claude`.
- A fixture commit fails with a signing error → the fixture's local `commit.gpgsign=false` was not
  set before `git commit`; fix the order. Never pass `--no-gpg-sign`.
</error_recovery>

## Regression gate (baseline-relative)

Test counts depend on the environment (1Password signing only hangs while 1Password is locked; the
daemon/PID tests fail in any git worktree). So this gate compares failing test **names** against
`.planning/objectives/37-adopt-existing-repos/baseline-failures.tsv` (21 lines, `file:line<TAB>name`),
not counts.

1. From the repo root, run
   `node --test --test-reporter=spec 'plugins/devflow/**/!(micro).test.cjs' 'plugins/devflow/**/*.test.js' 'scripts/**/*.test.cjs'`
   and write the output to a file in your session scratchpad (never the repo).
2. Extract failing names from the closing `✖ failing tests:` section: each entry gives
   `test at <file>:<line>:<col>` then `✖ <name> (<ms>)`; strip the duration.
3. A failure whose name is in the TSV's second column is **pre-existing**.
4. Any other failure is a candidate regression. Re-run just its file with `node --test <file>`.
   - Passes on re-run → **environment flake**, record the evidence.
   - Still fails and this TRD's diff (`git diff --stat <wave base>`) touched code it exercises →
     **regression, blocks**. Fix it before completing.
   - Still fails and plainly unrelated (PTY/handoff timing) → **environment flake**; record file,
     name, re-run output and why it's unrelated. Don't block.
5. **Never edit `baseline-failures.tsv`** to pass the gate. Tests added by this objective are not in
   the TSV and must pass.

In SUMMARY, record observed pass/fail totals (information only) and every failure's classification.
