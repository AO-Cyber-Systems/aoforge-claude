# TRD 35-02b: `renderCommand` and `contextFor` (per-agent slices)

<objective>
Add `lib/stack-render.cjs`: command rendering with `{files}`/`{packages}` placeholders, and the
proposal §5.3 per-agent context slice with a token cap. Split from the original 35-02 at the
job-checker's request. It runs in parallel with 35-02a (the loader) because it is a separate
module that consumes only the resolved-profile shape. 35-03 wires it into `stack-profile.cjs`
exports and the CLI.

Resolved intent: kind=plugin, work=feature, tdd=strict, test_list_first=required,
fixture_strategy=generators. The fixture here is a hand-built resolved-profile object
(`makeResolved()` inside the test file). This TRD does NOT touch `__fixtures__/stack-profile-fixtures.cjs`,
which 35-02a owns. Constraints honored: `no_llm_test_data`, `no_property_based_default`, `no_gherkin_layer`.
</objective>

## Runtime model (binding, from OBJECTIVE.md)

- CommonJS, synchronous, no new npm dependencies. **No filesystem access at all in this module.**
- **Neutrality:** stack-render.cjs names no specific stack.
- One plain command per Bash call. If a commit fails with `1Password: agent returned an error`,
  STOP and report it. Never use `commit.gpgsign=false`.
- Commits: `test(35-02b): ...` → `feat(35-02b): ...`.

## Input shape (from 35-02a — do not require that module)

```js
{
  id: 'x',
  frontmatter: { commands: { test: { run, scoped?, apply?, timeout_s?, cwd? }, ... }, loop: [], gates: { task: [], objective: [] },
                 generated: { globs: [], markers: [], regenerate? }, verification: { runtime, runtime_check? } },
  sections: { 'Principles': { text, sources }, 'Avoid': { text, sources }, ... },
  provenance: {...}, chain: [...], component: null, issues: [],
}
```

## Output contract

```js
renderCommand(profile, key, { files = [], packages = [], apply = false } = {}) →
  { key, status: 'ok'|'discover'|'none'|'undefined', form: 'run'|'scoped'|'apply'|null, command: string|null, timeout_s?, cwd? }
contextFor(profile, agent, { budget = 2500, ui = false } = {}) →
  { agent, profile_id, text, tokens, budget, truncated, included: [names], omitted: [names] }
// unknown agent → throw Object.assign(new Error('unknown agent "x"; valid: planner, executor, ...'), { code: 'UNKNOWN_AGENT' })
```

§5.3 matrix (✓ = included; `Commands` is rendered from the frontmatter):

| Section | planner | executor | verifier | debugger | mapper / researcher |
|---|:-:|:-:|:-:|:-:|:-:|
| Principles | ✓ | ✓ | ✓ | ✓ | ✓ |
| Commands | ✓ | ✓ | ✓ | ✓ | |
| Idioms | ✓ | ✓ | | | |
| Avoid | | ✓ | ✓ | ✓ | |
| Layout & architecture | ✓ | ✓ | | | ✓ |
| Testing | ✓ | | ✓ | | |
| Dependencies | ✓ | ✓ | | | ✓ |
| Generated code | | ✓ | | ✓ | |
| Security | | ✓ | ✓ | | |
| UI | ✓ (ui) | ✓ (ui) | ✓ (ui) | | |

Aliases: `codebase-mapper`→mapper, `integration-checker`→mapper, `objective-researcher`/`project-researcher`→researcher.

Commands block rendered into `text`:
```
## Commands (profile: <id>)
- test: <run>   (scoped: <scoped>)        # 'discover' / 'none' shown literally
loop: format → lint → test
gates.task: format, lint, test
gates.objective: build, test
generated: globs [..]; regenerate: <key>             # executor + debugger only
runtime: <verification.runtime> (runtime_check: <key>)   # verifier only
```
Each section renders as `## <Name>\n\n<text>`. Only sections present in `profile.sections` are included.

## Test list (copy into the header comment of stack-render.test.cjs)

- C1 `renderCommand(p,'build')` with run `make build` → `{status:'ok', form:'run', command:'make build'}`.
- C2 packages + scoped with `{packages}` → scoped form filled, space-joined.
- C3 files → `{files}` filled; a path containing a space is single-quoted.
- C4 scoped needs `{packages}` but only files are given → packages derived as unique `./<dirname>` (`.` for root files).
- C5 `run: discover` → `{status:'discover', command:null}`; `run: none` → `{status:'none', command:null}`.
- C6 unknown key → `{status:'undefined', command:null}`.
- C7 `apply:true` uses `apply` with placeholders; no `apply` → falls back to `run` (form `run`).
- C8 `contextFor(p,'executor')` on a general-shaped profile (Principles, Avoid, Testing, Dependencies) includes Principles, Commands, Avoid, Dependencies and excludes Testing.
- C9 verifier → Principles, Commands, Avoid, Testing, Security (only those present); excludes Idioms and Layout & architecture.
- C10 mapper → Principles, Layout & architecture, Dependencies; no Commands block.
- C11 `UI` only when `{ui:true}`, and only for planner/executor/verifier.
- C12 budget 300 → `truncated:true`, `tokens <= 300`, `omitted` non-empty, and `text` still starts with the Principles section.
- C13 unknown agent throws `UNKNOWN_AGENT` naming `planner`; each alias resolves.
- C14 neutrality: stack-render.cjs source does not match `/golang|gofmt|\bdart\b|flutter|pubspec|\bnpm\b|cargo|pytest|rails|gradle|swift|kotlin/i`.

<gotchas>
- **Token estimate:** `Math.ceil(text.length / 4)`. Truncation: build the agent's ordered list
  [Principles, Commands, then the matrix order] and drop from the END until it fits. If Principles +
  Commands alone exceed the budget, hard-cut the text at `budget*4 - 16` chars and append `\n…[truncated]`.
- Shell-quote a `{files}` token with single quotes when it doesn't match `^[A-Za-z0-9_./@:+=-]+$`.
- Pass `timeout_s` and `cwd` through from the command object when present.
- Test fixtures are plain objects inside the test file. Don't read `references/stack-general.md` here; that's 35-02a's positive control.
</gotchas>

</anti_patterns>

## Regression gate (baseline-relative)

Test counts depend on the environment. The 1Password signing hang only happens where
`op-ssh-sign` is reachable: a sandbox saw 3417 pass / 1 fail, while the user's machine sees 10
failures. So this gate compares failing test **names** against
`.planning/objectives/35-stack-profile-loader/baseline-failures.tsv`, not counts. That file
has one line per failure: `file:line<TAB>name`, from a real run of this exact command.

1. From the repo root, run
   `node --test --test-reporter=spec 'plugins/devflow/**/!(micro).test.cjs' 'plugins/devflow/**/*.test.js' 'scripts/**/*.test.cjs'`
   and write its output to a file in your session scratchpad (never the repo).
2. Extract the failing test names from the spec reporter's closing `✖ failing tests:` section.
   Each entry gives `test at <file>:<line>:<col>` and then `✖ <name> (<ms>)`; strip the duration.
3. A failure whose name appears in the TSV's second column is **pre-existing**, whether it passes
   or fails in your run.
4. A failure whose name is **not** in the TSV is a candidate regression:
   - Re-run just its file with `node --test <file>`.
   - If it passes on re-run, record it as an environment flake with the evidence.
   - If it still fails, check whether this TRD's changes (`git diff --stat` against your wave base)
     touched code that test exercises.
     - If they did, it is a **regression and blocks**. Fix it before completing.
     - If they plainly didn't (e.g. a PTY or handoff timing test), record it in SUMMARY as an
       **environment flake**, with the file, the name, the re-run output and why it's unrelated.
       Don't block.
5. **Never edit `baseline-failures.tsv`** to make the gate pass.

In SUMMARY, record the observed pass/fail totals (for information only) and every failure with its
classification: pre-existing, environment flake, or regression.
