# TRD 34-06: the review sheet and a `sheet_hash` that survives a template edit

<objective>
Build the Phase A review artifact (§8.3): a static, self-contained HTML **review sheet** showing
every declared state × theme × width beside its reference, plus the navigation graph, the
plain-language control table and the per-state content contract — and a `sheet_hash` that is the
sha256 of the **canonical model**, not of the HTML, so a template edit cannot invalidate a
human's approval.

A declared state with no render is a **`MISSING` cell**, never a dropped row.

Resolved intent: kind=plugin, work=feature, tdd=strict, depth=comprehensive,
test_list_first=required, fixture_strategy=generators. Constraints honored:
`no_llm_test_data`, `no_property_based_default`, `no_gherkin_layer`.
</objective>

<test_list>
Behaviour cases, written before any test code. Outside-in: the hash contract first (it is the

**The hash contract (H) — the load-bearing half**
- **H1 (the plan's first RED case)** — build the model, hash it, render the HTML; then EDIT
  `templates/ui-sheet.html` (insert a CSS rule and a comment), re-render, re-hash. The HTML
  differs; **`sheet_hash` is identical**. Implement the edit in the test by passing a mutated
  template STRING to `renderSheetHtml`, so the test does not write to the real template file.
- **H2** — change the spec (rename a state id), rebuild the model, re-hash: the hash CHANGES.
  The negative half; without it H1 passes on a constant.
- **H3** — canonicalisation: two models whose object keys were inserted in different orders hash
  identically. Serialise with sorted keys; `JSON.stringify` alone is insertion-ordered and would
  make the hash depend on parse order.
- **H4** — the hash covers the render/ref STATUS, not the render BYTES: replacing a render PNG
  with different pixels at the same path does not change the hash; a render appearing where there
  was none (`MISSING` -> `present`) DOES. State this rule in the SUMMARY — 34-07's re-lock rule
  is built on it, and getting it backwards means every re-render invalidates the lock.

**The grid (G)**
- **G1** — one row per capture-list entry from 34-05, in capture-list order, with
  `{capture_id, state_id, theme, width, render, ref, status}`.
- **G2 (the plan's second RED case)** — a declared state with no render file: `status: 'MISSING'`,
  `render: null`, and **the row is present**. Assert on the GENERATED HTML — `grep -c MISSING`
  ≥ 1 and the state's id appears — not only on the model. A model-only assertion passes on a
  template that silently skips null renders.
- **G3** — a state WITH a render and a ref renders both, side by side, with the ref labelled as
  mockup/donor/locked per which `--refs` subdirectory it came from.
- **G4 (the plan's third RED case)** — the sheet lists `design_read` and `mode`. Assert both
  strings appear in the HTML.
- **G5** — the sheet includes the nav graph (as a mermaid code block or a pre-rendered block —
  say which in the SUMMARY; a Claude Artifact renders mermaid, a file:// page does not) and the
  control table, both taken from `renderSurfaceSpec`, not re-derived.
- **G6** — the per-state content contract (`must_show` / `must_not_show` / `rule`) appears in
  each row.
- **G7 (self-containment)** — the generated HTML contains no `http://`, no `https://`, no
  `<script src=`, and no `<link rel="stylesheet" href=`. Images are referenced by relative path
  or inlined; say which in the SUMMARY. Asserted by regex over the output — §8.3 requires the
  sheet to work offline.

**The arm (A)**
- **A1** — `df-tools ui sheet <spec> --renders <dir> --refs <dir> --out <file>` writes the file

**Hashing with a builtin** — `node:crypto`:

```js
const crypto = require('node:crypto');
const hex = crypto.createHash('sha256').update(canonicalJson, 'utf-8').digest('hex');
```

No dependency. There is a `hashFrontmatter` precedent in `bin/lib/sync-state.cjs` — read it for

**Canonical JSON with sorted keys** — no library:

```js
function canonical(v) {
  if (Array.isArray(v)) return '[' + v.map(canonical).join(',') + ']';
  if (v && typeof v === 'object') return '{' + Object.keys(v).sort()
      .map(k => JSON.stringify(k) + ':' + canonical(v[k])).join(',') + '}';
  return JSON.stringify(v);
}
```

<gotchas>
- **Hash the model, never the HTML.** This is the whole point of the row. If `sheetHash` takes
  the rendered string, every CSS tweak invalidates a human approval, and within two weeks the
  lock is being re-approved without being read — which is worse than no lock. H1 and H2 together
  pin it; neither alone does.
- **Hash the render STATUS, not the render bytes.** H4. A re-render after a code change must not
  clear a look-lock — §4.1's re-lock rule says only `routes`/`controls`/`states` changes clear it.
  But a state moving from `MISSING` to `present` IS new information a human has not seen, so that
  transition must change the hash.
- **`Object.keys` order is insertion order.** H3. Canonicalise before hashing or the hash depends
  on how the YAML happened to parse.
- **Do NOT omit a row.** G2 asserts on the HTML precisely because a template `{{#if render}}`
  guard is the natural way to write this and the natural way to be wrong.
- **Mermaid in a `file://` page does not render** without a script, and a script is a network
  fetch, which G7 forbids. Decide: either embed the graph as a fenced code block (renders in a
  Claude Artifact, shows as text offline — recommended) or pre-render to inline SVG. Say which in
  the SUMMARY.
- **Image paths.** Relative paths break when the HTML is pasted into an Artifact; inlining as
  base64 makes the file large. Pick one, state the tradeoff in the SUMMARY, and keep G7 green.
- **The template must be `__dirname`-relative.** M1 is the guard. The W0 retrospective's headline
  defect was a lookup that passed every test and was dead on the mirror path.
</gotchas>

<anti_patterns>
- **Do NOT add a templating engine or an HTML builder.** Placeholder substitution over one
  template string. No handlebars, no ejs, no jsdom.
- **Do NOT hash the HTML.** See gotchas. If you find yourself wanting to "just hash the output",
  re-read §8.3 and 34-07's re-lock rule.
- **Do NOT re-derive the nav graph or the control table here.** Call `renderSurfaceSpec`. Two
  derivations of one artifact is the drift class objective 33 closed.
- **Do NOT let the sheet render from an invalid spec.** A3.
- **Do NOT fabricate a render.** If a file is not there, the cell is `MISSING` with the path that
  was looked for. Never a placeholder image that reads as a successful render.
</anti_patterns>

<error_recovery>
- If H1 fails, you are hashing something that contains the template or the HTML. Print the
  canonical JSON and look for markup in it.
- If G2 passes on the model but the HTML has no `MISSING`, the template is skipping null rows.
  Fix the template, not the assertion.
- If M1 passes trivially, the temp tree is not isolated — check there is no `package.json` or
  `.git` above it and that you are requiring the COPIED module.
- If the fixture sheet is enormous, you inlined base64 images. That is a legitimate choice, but
  commit a fixture with small placeholder PNGs (a few hundred bytes each, hand-made) rather than
  real screenshots.
</error_recovery>
