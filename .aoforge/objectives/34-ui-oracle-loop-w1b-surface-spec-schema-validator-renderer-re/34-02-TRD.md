## Runtime model

Binding for this TRD (OBJECTIVE.md; proposal §21 amendment 2). Trace every command under it.

- **Mirror, not checkout.** Skills and agents invoke `node ~/.claude/devflow/bin/df-tools.cjs` —
  the MIRROR at `~/.claude/devflow`, which the `sync-runtime` SessionStart hook copies from
  `plugins/devflow/devflow/`. It is NOT this checkout. `installed_plugins.json` is the registry

  There is no JSON Schema validator package in this repo and this TRD does not add one — 34-03
  implements the subset of schema checking it needs directly over the parsed schema object.
- **Honest output.** Every tool output carries `engine_version` and `schema_version`. A check

<gotchas>
- **`extractFrontmatter`'s lenient `{}` return is the bug this parser must not inherit.** P2
  asserts the throw explicitly. A spec that silently parses as `{}` then "passes" every
  invariant in 34-03 vacuously — the exact silently-absent class the W0 retrospective names.
- **A markdown `---` rule in the prose body is not a terminator.** P4 pins it. Split on the
  FIRST two `---` lines only, and only when the first is line 1 (after an optional BOM).
- **The schema file is data, not code.** JSON has no comments. Anything explanatory goes in a
  `description` field inside the schema, or in `ui-spec.cjs`'s header — not in a `//` that will
  make the file unparseable.
- **No JSON Schema validator exists in this repo and you are not adding one.** The schema file
  is a *declaration*; 34-03 reads it and implements the checks it needs directly. Do not
  `require('ajv')`. Do not hand-roll a general validator here either — this TRD only LOADS the
  schema.
- **`schemas/` must sit under `plugins/devflow/devflow/`**, not under `plugins/devflow/`. Only
  `devflow/` is mirrored to `~/.claude/devflow/`. A schema one level up is invisible to every
  skill at runtime — and a test run from the checkout would never notice. P5 is the guard.
- **Two routes, two controls.** It is tempting to transcribe only the one route and one control
  §4.2 spells out in full. Do not: I2 needs a declared root to satisfy "every route has a back
  or is the root", and I6 needs `rail.project.chevron` to exist because the header names it in
  `disjoint_from`. Transcribing only half the example makes the positive control fail 34-03 for
  reasons that are artefacts of the transcription.
</gotchas>
