<gotchas>
- **`output()` exits 0.** This is the single most likely way to ship a gate that never gates.
  C2 executes the real binary and asserts `status === 1`; a unit test on the library alone
  would not catch it.
- **`∩ ≠ ∅` vs "equal".** The plan says intersection; §4.4 says equal. Intersection is strictly
  stronger and satisfies both. Implement intersection, pin both I4b and I4c, and say so in the
  SUMMARY — this is a reconciliation, not a choice between the documents.
- **`undefined` patterns ≠ `[]` patterns.** I5c. The first means "I could not reach the pinned
  release" and must report `MISSING`; the second means "the release declares no patterns" and a
  referenced pattern is genuinely unknown. Collapsing them turns an unreachable catalogue into a
  silent pass, which is the exact class §2 goal 5 forbids.
- **`STATE003` must list ALL missing states in one error**, not one error per state — otherwise a
  new spec with two states produces five errors and the fixture-hygiene loop (H1) goes red for
  every fixture that happens to be minimal.
- **Six new fixtures, one edit each.** Same discipline as 34-03: `cp projects-rail.md`, change
  exactly one thing, add the `<!-- BROKEN: … -->` comment. `diff` against the positive control
  must show one hunk.
- **`ui-spec-cli.cjs` is a separate file from `ui-spec-validate.cjs`.** 34-05, 34-06 and 34-07
  all add arms; keeping the CLI plumbing in its own module means four TRDs edit one small file
  instead of four TRDs editing the validator.
</gotchas>

**The conflict.** Proposal §4.5 invariant 6 reads: *"no two controls declare overlapping hit
rects unless one lists the other in `disjoint_from` (which the probe then asserts)"*. The plan's
W1b RED-case list names a fixture "overlapping `hit_rect` without `disjoint_from`". But §4.2's
schema gives `hit_rect` exactly one field — `{disjoint_from: [<control-id>]}` — and no
coordinates. §7.5 then defines the runtime `disjoint` check as *"rects of `disjoint_from` pairs
overlap"*, i.e. `disjoint_from` is an **assertion the probe verifies**, not a declaration of
overlap. **There is therefore no field in §4.2 from which a static overlap can be computed.**
I6 as written is not statically evaluable against the schema as written.

**Three candidate resolutions.** Each is implementable in this TRD; they differ in what the spec
author has to write and in what W2's probe inherits.

- **(a) Declared containment.** Add an optional `hit_rect.within: <control-id>` to the schema.
  Declaring one control inside another IS the static overlap. `HIT001` fires when
  `A.hit_rect.within === B.id` and neither A nor B lists the other in `disjoint_from`. Fixture:
  the chevron declares `within: rail.project.header` and the header drops its `disjoint_from`.
  *Cost:* one schema field. *Benefit:* the nav defect this program exists to catch (a row-sized
  chevron node inside a header) becomes statically declarable and the probe gets a rect pair to
  assert. Recommended.
- **(b) Reciprocity only.** No schema change. I6's static half becomes "every `disjoint_from`
  reference resolves to an existing control AND is reciprocal" — `HIT001` fires when A lists B
  but B does not list A, or when the target does not exist. Fixture: delete the chevron's
  reciprocal entry. *Cost:* the invariant no longer matches its §4.5 wording; the real overlap
  check is deferred entirely to W2's probe. *Benefit:* zero schema churn.
- **(c) Defer.** Implement no I6, ship `hit_rect` as schema-declared-but-unchecked, and have the
  validator emit `HIT000 / MISSING` for every surface. *Cost:* the plan's fixture list loses one
  entry; W1★ dogfoods without the check. *Benefit:* nothing is invented.

**Ask the user which, and note that (a) and (b) can co-exist** — (b)'s reciprocity check is
cheap and correct under (a) as well.

Whichever is chosen, `HIT000` (MISSING) remains the answer for any surface where the check could
not run. A hit-rect check that did not run never reports `pass`.
