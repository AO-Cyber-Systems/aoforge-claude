# TRD 34-01: `yaml-lite` — the subset YAML parser, and everything it refuses

<objective>
Build `parseYamlLite(text)`: a minimal, dependency-free YAML subset parser for Surface Spec
front matter. It supports block maps, block lists, inline maps/lists, quoted and bare scalars,
and comments — and it **throws, with a line number, on every construct outside that subset**.

This TRD wires nothing. `parseSurfaceSpec` (34-02) is its first caller. The wave must end with
the focused suite green and no other file touched.

Resolved intent: kind=plugin, work=feature, tdd=strict (CLAUDE.md user playbook),
depth=comprehensive, test_list_first=required, fixture_strategy=generators.
Constraints honored: `no_llm_test_data` (every YAML string in the suite is hand-written),
`no_property_based_default` (named descriptive cases, no generators), `no_gherkin_layer`.
</objective>

<test_list>
Behaviour cases, written before any test code (CLAUDE.md habit 2). Every case is a hand-written
YAML string literal in the test file — no fixture files, no generated data. Inner-to-outer is
the wrong order here; there is no user-observable layer above a parser, so order by
"what breaks the most if wrong": structure first, then scalars, then the refusals.

**Structure**
- **Y1** — block map: `surface: projects-rail` plus a nested two-space-indented map
  (`references:` / `  mockup: refs/x.png`) -> `{surface: 'projects-rail', references: {mockup: 'refs/x.png'}}`.
  Includes a dedent back to top level after the nested map.
- **Y2** — block lists: (a) a list of scalars `patterns:\n  - a\n  - b` -> `['a','b']`;
  (b) a list of MAPS — `- id: x` with continuation lines indented to the `id` column -> an
  array of objects. (b) is the shape `routes`, `controls`, `states` and `flows` all use; if it
  yields strings instead of objects, everything downstream in this objective is wrong.
- **Y3** — inline (flow) collections: `a: {b: 1, c: [x, y]}` -> `{a:{b:1,c:['x','y']}}`;
  a flow map nested inside a flow list inside a block list item
  (`- {click: rail.header, expect: {route: project.conversations}}`). Flows use exactly this.

**Scalars**
- **Y4** — quoted strings: double- and single-quoted; a quoted value containing `: ` and a `#`
  (`title: "{project.name}: overview # 1"` -> that whole string). Escaped `\"` inside double
  quotes. A quoted string inside a flow list (`must_show: ["{project.name}"]`).
- **Y5** — bare scalar with an embedded colon NOT followed by a space:
  `locked_sheet: sha256:9f2b…` -> the string `'sha256:9f2b…'`. YAML's key separator is `': '`
  (colon-space) or a line-terminal colon; a colon glued to the next character is content.
- **Y6** — scalar typing: `1` -> `1` (number), `1.5` -> number, `true`/`false` -> boolean,
  `null` and `~` -> `null`, `2026-09-18` -> the STRING `'2026-09-18'` (no date type — the
  Surface Spec's `locked_at` must survive a round trip as text), `390x844` -> STRING,
  `""` -> empty string, and a quoted `"1"` -> the STRING `'1'`.
- **Y7** — comments: a full-line `# …`, a trailing ` # …` after a value, and a `#` inside a
  quoted string (preserved). A `#` that is not preceded by whitespace is NOT a comment
  (`color: #fff` -> the string `'#fff'`).

**Refusals — the load-bearing half. Each throws with `.line` and names the construct.**
- **Y8** — anchors and aliases (`base: &b {x: 1}` / `copy: *b`) and the merge key (`<<: *b`).
- **Y9** — block scalars (`prose: |` and `prose: >`) and tags (`when: !!str 1`).
- **Y10** — indentation faults: a TAB character used for indentation; and a dedent to a column
  that matches no open block. Both throw rather than guessing.
- **Y11** — two refusals that this objective specifically depends on:
  (a) a DUPLICATE key at the same level (`does: a` twice in one map) — silently keeping the
  last one would make 34-03's "two `does`" invariant unreachable;
  (b) an implicit single-pair map inside a flow sequence —
  `activation: [pointer, keyboard: [Enter, Space]]`. Real YAML accepts this; yaml-lite does
  NOT, and the error message must name the supported form
  (`[pointer, {keyboard: [Enter, Space]}]`). 34-02's `projects-rail` fixture is normalised to
  the supported form and the normalisation is recorded there.

**Regression guard**
- **Y12** — `require('./yaml-lite.cjs')` has no side effects and its `require(...)` list is
  limited to node builtins. Read the file and assert it, the same way
  `flutter-ui-eval-resolve.test.cjs`'s R1 case does.

Explicitly NOT in this TRD: front-matter/body splitting, the schema, the `projects-rail`
fixture, any `df-tools` arm. All of those are 34-02 or later.

<gotchas>
- **A subset parser must fail loudly, never approximately.** The single most damaging outcome
  of this TRD is a construct that is neither supported nor rejected — the author believes the
  spec is machine-checked and it silently is not. When in doubt between "support it" and
  "reject it with a clear message", reject.
- **`': '` is the key separator, not `':'`.** A line-terminal `:` also separates
  (`references:`). Anything else is content (Y5). Getting this wrong breaks `sha256:…`,
  `390x844` is unaffected but `path: /projects/:id/conversations` is NOT — that value contains
  `:id` with no following space and must survive as one string. Add it as a sub-assertion of Y5;
  it is the single most common value shape in `routes`.
- **Block-list-of-maps indentation.** `- id: x` opens a map whose column is the column of `i`
  in `id`, not the column of `-`. Continuation keys align to `i`. Getting this off by two
  produces arrays of one-key objects — which looks plausible in a `console.log` and breaks
  every consumer.
- **Do not strip `#` before tokenising quotes.** A comment stripper that runs over the raw line
  eats `must_show: ["#1 priority"]`. Strip comments during scalar scanning, when you know
  whether you are inside quotes.
- **Empty values are real.** `must_not_show: []`, `disabled_when: null`, and a key with nothing
  after the colon (`guards:` followed by an indented list) all appear in §4.2. A key with an
  empty value and no indented block below it is `null`, not `''`.
- **CRLF.** Normalise `\r\n` -> `\n` once at the top. Editors on this fleet produce both.
</gotchas>

<anti_patterns>
- **Do NOT add a YAML dependency.** Not `js-yaml`, not `yaml`, not a vendored copy of one.
  `package.json` carries only `node-pty` and this objective does not change that. The whole
  reason `yaml-lite` exists is written into `docs/IMPLEMENTATION-PLAN-ui-oracle-loop.md`'s
  Global Constraints.
- **Do NOT write a general YAML parser.** Anchors, merges, block scalars, multi-document files,
  complex keys and tags are OUT, permanently. The supported subset is exactly what §4.2's
  schema uses. Each omission is a test, not a TODO.
- **Do NOT use `eval`, `Function`, or a JSON coercion trick** to type scalars. Type them
  explicitly with regexes so `2026-09-18` and `390x844` stay strings.
- **Do NOT silently take the last duplicate key.** That is JS object semantics, not a decision.
  Y11(a) pins the throw.
</anti_patterns>

<error_recovery>
- If `node --test` reports the whole file failing to load, that is a `SyntaxError` in the test
  file, not a RED test. Read the runner output for `SyntaxError` before claiming RED.
- If a structure case passes but the value types are wrong, you have a scalar bug, not a
  structure bug — fix Y6 before re-debugging Y1-Y3.
- If you find yourself adding a fourth special case to the indentation logic, stop and
  restructure: tokenise into `{indent, content, line}` records first, then build the tree from
  the token stream. Mixed scanning and tree-building is where subset parsers rot.
- If a refusal case (Y8-Y11) passes for the wrong reason (it throws a `TypeError` from deep
  inside, not a `YamlLiteError`), the case is green and worthless. Assert on
  `err.name === 'YamlLiteError'` AND on `err.line`, not on `assert.throws` alone.
</error_recovery>
