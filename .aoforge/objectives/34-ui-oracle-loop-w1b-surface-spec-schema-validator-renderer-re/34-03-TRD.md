<gotchas>

**The behaviour-coverage model — the one interpretive decision in this objective.**

§4.3 requires `behaviors[].when` clauses to be *"mutually exclusive and together cover every
`visible_in` state"*. `when` is a map over `{control_state, viewport, theme, data_state, guard}`.
The model below is binding for this TRD, for 34-05's control table, and for W2's `effect`
check. Write it into `ui-spec-validate.cjs`'s header comment verbatim.

1. **A `when` key that is absent is a WILDCARD.** `{viewport: narrow}` matches every
   `control_state`, `theme`, `data_state` and `guard`.
2. **The domain of each dimension is closed-world, derived from the spec:**
   - `data_state` — the control's `visible_in` list.
   - `viewport` — `narrow` when the state declares a `viewport` whose width is `< 600`, or when
     the state's id is `narrow`; otherwise `desktop`. (600 is the single breakpoint constant;
     name it `NARROW_MAX_WIDTH` and put it at the top of the module.)
   - `theme` — the state's `theme`, defaulting to `light`.
   - `guard` — `denied` when the state is named as a route guard's denied state, else `allowed`.
   - `control_state` — **the union of every `control_state` value appearing in THIS control's
     own `behaviors[].when`, plus every value in its `a11y.announces`.** If that union is empty,
     the dimension has the single value `default`.
3. **A behaviour MATCHES a combination** when, for every key present in its `when`, the value
   equals the combination's value for that dimension.
4. **`CTRL003` (exclusivity)** fires when any combination is matched by two or more behaviours.
5. **`CTRL004` (coverage)** fires when any combination is matched by zero behaviours.

Worked against §4.2's `rail.project.header` — `visible_in: [populated, long-content, narrow]`,
`control_state` domain `{collapsed, expanded}` (from `a11y.announces` and the behaviours), six
combinations:

| data_state | control_state | viewport | matched by |
|---|---|---|---|
| populated | collapsed | desktop | B1 only |
| populated | expanded | desktop | B2 only |
| long-content | collapsed | desktop | B1 only |
| long-content | expanded | desktop | B2 only |
| narrow | collapsed | narrow | B3 only |
| narrow | expanded | narrow | B3 only |

Exactly one match everywhere -> `ok`. Drop B3 -> the last two rows are uncovered -> `CTRL004`.
Change B3 to `{control_state: collapsed}` -> it also matches rows 1 and 3 -> `CTRL003`. Case
I3g pins the passing table; the two broken fixtures pin the two failures.

**Other gotchas:**
- **`entry` is a heterogeneous list.** §4.2 has `entry: [{control: rail.project.header}, deeplink]`
  — a map and a bare string in one list. `ROUTE003` checks `{control: …}` entries only; a bare
  string (`deeplink`, `browser-back`) is a declared non-control entry and is valid. I2e pins it,
  and it will break the positive control if you forget.
- **Cross-surface entries resolve to `MISSING`, not to an error and not to silence.** §4.5 I2
  says entry controls may live "in another spec of the same repo". This TRD validates ONE spec
  with no repo scan, so an entry control not found locally and whose id is not prefixed by this
  surface's own id must produce a `ROUTE003` variant carrying `resolution: 'MISSING'` in the
  message — visible, not silently passed. Do NOT implement a repo scan here.
- **Every fixture is a MINIMAL edit of `projects-rail.md`.** Copy it, change exactly one thing,
  and put a `<!-- BROKEN: … -->` comment at the top of the prose body naming the invariant and
  the expected code. I3h enforces single-code failure; a fixture written from scratch will trip
  four invariants and the case will fail for the wrong reason.
- **`SPEC002` short-circuits.** I1c asserts the error list has length 1 even though the fixture
  has a second defect. Return immediately after a version mismatch.
- **Deterministic ordering.** Sort `errors` by `(code, path)` before returning. `Object.keys`
  order over a parsed YAML map is insertion order today and is not a contract.
</gotchas>

<anti_patterns>
- **Do NOT add a JSON Schema validator dependency.** I1 implements only what §4.2 declares:
  required keys, id pattern, enum membership, and type of each declared property. That is a
  ~60-line function, and the alternative is a package this repo's global constraints forbid.
- **Do NOT throw.** V3 pins it. 34-04's CLI arm turns `errors` into an exit code; a throw turns
  it into a stack trace and the arm's contract dies.
- **Do NOT encode I1-I8 inside the JSON Schema file.** The schema declares structure; the
  invariants live in code with fixtures. Two homes for one rule is how the two prose documents
  in objective 33 drifted.
- **Do NOT collapse codes.** Each invariant has its own code because §17's known-broken fixture
  contract is "fails with its own code". A shared `SPEC_INVALID` makes every fixture green
  against the wrong rule.
- **Do NOT implement the cross-surface repo scan.** Out of scope for W1b; `MISSING` is the
  honest answer here.
- **Do NOT edit the positive control to make a new invariant pass.** If `projects-rail.md`
  fails, the invariant or the transcription is wrong — diagnose which, and if it is the
  transcription, fix it in 34-02's fixture with a note in BOTH SUMMARYs.
</anti_patterns>
