# TRD 34-05: `renderSurfaceSpec` — manifest, nav graph, control table, capture list

<objective>
Derive everything downstream from the one hand-authored artifact (§4.1's one-file rule):
the ui-eval **manifest** the existing engine already consumes, the **mermaid navigation graph**
that answers "can the user get back from here" before code exists (§8.2), the **plain-language
control table** a human reads on the review sheet (§8.3), and the **capture list** the sheet grid
and W2's probe iterate.

Four pure functions and one CLI arm. No file I/O in the library; no rules that are not already in
the spec.

Resolved intent: kind=plugin, work=feature, tdd=strict, depth=comprehensive,
test_list_first=required, fixture_strategy=generators. Constraints honored:
`no_llm_test_data` (snapshots are generated by the code under test and reviewed once by a human,
never authored by a model), `no_property_based_default`, `no_gherkin_layer`.
</objective>

<test_list>
Behaviour cases, written before any test code. Outside-in: the CLI arm, then the manifest (the
artifact another engine consumes), then the two human-facing renders, then the capture list.

**The CLI arm**
- **R1** — `ui spec render <positive control> --manifest` exits 0 and prints JSON that
  `JSON.parse`s and has a `states` array.
- **R2** — `--graph` prints text beginning with `graph` or `flowchart`; `--table` prints
  markdown beginning with a heading. No flag at all prints all four under named keys (state the
  default in the SUMMARY).
- **R3** — `ui spec render <a broken fixture>` exits **1** and prints the validation errors,
  rendering nothing. Deriving a manifest from a spec nobody checked is the failure this guard
  exists for.
- **R4** — an unknown flag exits 1 naming `--manifest`, `--graph`, `--table`.

**Manifest (M)**
- **M1 (the load-bearing case)** — take the rendered manifest, write it to a temp file, and call
  `flutter-ui-eval.cjs`'s real `loadManifest()` on it. It must return without throwing and
  `parsed.states` must be an array. Executing the consumer is the only proof the shape is right;
  an assertion written from reading the source proves the reader's memory.
- **M2** — every `states[]` entry has `state_id`, `seed`, `as`, `fault`, `references` —
  ALL FIVE KEYS PRESENT ON EVERY STATE. `as` defaults to the primary identity (name the default
  in the SUMMARY); `fault` is `null`, not absent, when the state declares none; `references` is
  `[]`, not absent, when the state declares no `ref`. A consumer must never have to distinguish
  "absent" from "empty".
- **M3** — `states[]` order equals the spec's `states[]` order exactly (deep-equal on the id
  list). The sheet's rows and the probe's capture order both inherit it.
- **M4** — the manifest carries `surface`, `engine_version` (non-empty string) and
  `schema_version`.
- **M5** — a state carrying `ref: locked/populated.png` renders `references: ['locked/populated.png']`;
  a state with no `ref` renders `references: []` AND is still present in `states[]`. The
  never-drop rule.

**Nav graph (G)**
- **G1** — one node per route, labelled with the route's `title`; ids sanitised for mermaid
  (dots are not legal in bare mermaid node ids — state the sanitisation rule in the SUMMARY).
- **G2** — one SOLID edge per `entry`, labelled with the entry control's id (or `deeplink` for a
  bare-string entry), and one DASHED edge per `back`, labelled with its `via` list.
- **G3** — a route with a `guard` renders an additional edge to that guard's denied state,
  labelled with the guard name, using 34-04's linkage rule. A route with no guard renders no such
  edge.
- **G4** — the graph is a string with no trailing whitespace on any line and a single trailing
  newline. Byte-stability is asserted against the committed snapshot; whitespace drift makes that
  assertion useless.

**Control table (T)**
- **T1** — a single-`does` control renders ONE sentence naming the control, what it does, and its
  effect classes in plain language.
- **T2 (the plan's named case)** — a `behaviors[]` control renders **one line per `when` clause**,
  each naming the condition in words ("when collapsed, on desktop") and the behaviour's `does`.
  Assert the line COUNT equals the behaviour count, not merely that the text contains a keyword.
- **T3** — `must_not` items render as explicit negations appended to the control's block
  ("It never navigates on close."), including the control-level `must_not` that applies to every
  behaviour (§4.2's comment) as well as behaviour-level ones. A `must_not` carrying `manual: true`
  renders with a `[human-verify]` marker — §4.3 keeps free-text items on the human list.
- **T4** — the table names `design_read` and `mode` at the top (the sheet shows them; 34-06's
  case S3 asserts they reach the HTML).

**Capture list (C)**
- **C1** — `captureList` is an array of `{state_id, theme, width, capture_id}` triples covering
  every declared state; a state declaring `theme: dark` contributes a dark entry, a state
  declaring a `viewport` contributes that width, and every other state contributes the default
  theme and width (name both defaults in the SUMMARY).
- **C2** — `capture_id` is stable and filename-safe (`<surface>--<state_id>--<theme>--<width>`),
  because 34-06 uses it to look up renders on disk and W2's probe uses it to name captures.
- **C3** — the list's order is the spec's `states[]` order, then theme, then width. Deterministic.

**Determinism (D)**
- **D1** — `renderSurfaceSpec` called twice on the same spec returns deep-equal results, and
  `JSON.stringify(manifest)` is byte-identical across calls.
- **D2** — the three committed snapshots
  (`snapshots/projects-rail.manifest.json`, `.graph.mmd`, `.controls.md`) match the current
  render byte-for-byte. This is the regression net for every later TRD that touches rendering.

Explicitly NOT in this TRD: the HTML sheet, `sheet_hash`, the lock, any change to
`flutter-ui-eval.cjs`.

function loadManifest(manifestPath) {
  const raw = fs.readFileSync(manifestPath, 'utf-8');
  const parsed = JSON.parse(raw);           // throws SyntaxError on invalid JSON
  if (parsed === null || typeof parsed !== 'object' || Array.isArray(parsed)) throw ...

}

<gotchas>
- **`engine_version` in a committed snapshot is a trap.** `pluginVersion()` changes at every
  release, so a snapshot containing it goes red on 34-11. Either exclude `engine_version` from
  the snapshot comparison (replace it with a placeholder before comparing) or omit it from the
  snapshot file and assert its presence separately in M4. Decide once and say which in the
  SUMMARY — a snapshot that must be regenerated every release is a snapshot people regenerate
  without reading.
- **Mermaid node ids cannot contain dots.** `project.conversations` must be sanitised
  (`project_conversations`) while the LABEL keeps the real id. Pick one rule, apply it to nodes
  AND edges, and pin it in G1.
- **A bare-string `entry` (`deeplink`) still draws an edge.** From what? Draw it from a synthetic
  `external` node. §4.2's example has one; G2 must cover it or the graph silently under-reports
  reachability — the exact thing §8.2 says the graph exists to answer.
- **Never drop a state.** A state with no `ref`, no `fault` and no `as` is still a row in the
  manifest, still a line in the capture list, and becomes a `MISSING` cell in 34-06's sheet.
  Filtering it out is how a gate stops seeing the thing it was built to see.
- **The control table is prose for a human.** Its readability is the point — §8.3 quotes
  *"Clicking the project header toggles its children and selects the project. It never navigates
  on close."* Write the sentence templates so that output is what comes out, and commit the
  snapshot so a human can read it once and object.
- **Render must refuse an invalid spec.** R3. `ui spec render` on a spec that fails I1-I8 would
  generate a manifest, a graph and a table that look authoritative and are not.
</gotchas>

<anti_patterns>
- **Do NOT add a mermaid or markdown dependency.** Both outputs are string concatenation.
- **Do NOT touch `flutter-ui-eval.cjs`.** W2 owns `references[]` semantics and calibration. This
  TRD populates the field; it changes no judge behaviour. The objective's out-of-scope list says
  so explicitly.
- **Do NOT do file I/O in `ui-spec-render.cjs`.** It takes a parsed spec and returns four values.
  The CLI arm reads and writes. Pure functions are what make D1/D2 cheap.
- **Do NOT hand-author the snapshots.** Generate them with the code under test, then READ them
  once — especially `projects-rail.controls.md`, which a human will see on the review sheet — and
  commit. A snapshot nobody read is a snapshot that pins a bug.
- **Do NOT invent manifest fields.** If §4.2 does not carry it and `flutter-ui-eval.cjs` does not
  read it, it does not go in the manifest.
</anti_patterns>

<error_recovery>

- If D2 fails after an unrelated edit, diff the snapshot before assuming the snapshot is stale.

- If G2 produces more edges than expected, you are probably drawing one per `via` rather than one

- If T2's line count is off by one, check whether the control-level `must_not` is being emitted
  inside the per-behaviour loop instead of once per control (T3).
</error_recovery>
