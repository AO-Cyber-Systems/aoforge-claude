# TRD 44-05: Stop hook that auto-continues an announced-but-not-taken step

<objective>
81 of the 186 bare human nudges ("continue", "yes", "do it") followed the main loop announcing an
action ("Writing the predicate.") and then ending its turn. Another 58 followed an unneeded ask
("Ready for wave 4 on your word"). See 44-EVIDENCE §1 row 4 and §3.3.

This TRD adds a Stop hook that blocks such a stop once, with the announced step as the next
instruction. The verified harness fact it relies on: a blocked Stop continues with `reason`, and
the re-stop carries `stop_hook_active: true`. That bounds the hook to one auto-continue per stop
chain.
</objective>

<anti_patterns>
- Matching an announcement anywhere in a long message. Only the FINAL paragraph (the text after
  the last blank line, with trailing code fences stripped) counts; earlier "Now" sentences are
  narrative.
- Blocking when a background agent is `running`. The model legitimately ends its turn to wait
  for the task notification.
- Case-insensitive `now` inside words ("known", "snow"). Match at sentence start only:
  `(^|[.!]\s+|\n)(Now|Next,?|Running|Writing|Starting wave)\b`.
- Treating "Ready for wave N on your word" as a question. It has no `?` but IS a permission ask
  that should auto-continue.
</anti_patterns>

<error_recovery>
- `last_assistant_message` absent or not a string → no block.
- If the gate-edits require throws (a moved file), catch it → no block (fail open).
</error_recovery>
