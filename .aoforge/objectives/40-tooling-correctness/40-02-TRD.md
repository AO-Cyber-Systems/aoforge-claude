# TRD 40-02: `objective complete` writes the narrative log line and reports truthfully

<objective>
Defect 2 (TOOL-02): `cmdObjectiveComplete` (objective.cjs:696-869) correctly refuses to run the legacy
field rewrite on a narrative STATE.md, but it then does nothing at all. It also reports
`state_updated: fs.existsSync(statePath)` (true whenever the file exists). That is why objectives 37-39
never reached this repo's running `**Objective complete:** N — ...` log.

Fix both halves. Append one log line (additive, idempotent, and never touching `**Status:**`), and
report `state_updated` from whether a write actually happened.

**Planner decision (deliberate):** the research recommended only fixing the flag. The objective's stated
symptom is "leaves STATE.md unchanged", so this TRD also performs the additive append. The existing
narrative test currently asserts STATE.md is byte-identical. Its *intent* is "narrative content survives,
Status is not clobbered". It gets tightened to assert: the output equals the input plus exactly one inserted
line, and Status is unchanged. That is the only edit to an existing test. Record it in the SUMMARY.

Resolved intent: kind=plugin, work=bugfix → strict regression-test-first, test list required, inline fixtures.
</objective>
