# TRD 52-03: micro leaves STATE.md alone in store mode (item 52-3)

<objective>
Stop `df-tools micro commit` from appending a "Quick Tasks Completed" row to STATE.md in store mode, where STATE.md is a generated
view (`df-tools gh pull --all` rebuilds it). There the append shows up as W055 drift, and the second commit fails because the path is gitignored.

Purpose: 48-VERIFICATION and the v1.4 audit logged this. `/devflow:quick` already skips its STATE.md step in store mode
(workflows/quick.md:374-380); micro is the one writer left. The objective allows "route through a verb, or skip". Skip it: no verb
owns a STATE.md row, and in store mode the generated view comes from GitHub.

Output: the store-mode skip in `commitMicro`, regression tests in local and store mode, and updated micro prose.
</objective>

- Strict TDD: `test(52-03): ...` (failing) before `fix(52-03): ...`.

- Out of scope, do NOT change: micro's source commit goes through `_defaultGitRunner` (raw `git commit` with
  `DEVFLOW_ALLOW_RAW_COMMIT=1`), so it is not subject to the store-mode commit gate (GEN-01). TRD 52-06 records that as a known issue.
  Leave the runner alone.

## Test list

Outermost first.
1. CLI e2e, store mode (`.planning/config.json` `{github: {enabled: true, store: true}}` in a git fixture): `micro start` then
   `micro commit --files a.txt` -> exit 0, one new commit (HEAD~1 is the initial commit), STATE.md bytes unchanged, marker removed.
2. Store mode, `commitMicro` with a recording mock runner: the runner is called exactly once (the source files); the result is
   `{ok: true, state_commit_hash: null, state_row: 'skipped_store_mode', removed_marker: true}`.
3. Store mode, no STATE.md on disk: `commitMicro` succeeds (no `no-state-file`) and creates no STATE.md.
4. Store mode, drift: with a cache-index baseline recording STATE.md's hash (injected through
   `planning-drift._setDriftReaders({readIndex: () => ({'STATE.md': <hash>}), readLedger: () => ({version: 1, entries: {}, corrupt: false})})`),
   `findCacheDrift(root).drift` has no entry for `STATE.md` after the micro commit. The store fixture's STATE.md must start with
   planning-drift's `GENERATED_HEADER` (`<!-- generated by devflow; do not edit -->`), or it is reported as `hand-edited` whatever micro
   does. The baseline hash is `require('./gh-trd.cjs').contentHash(text)` (the cache index and the ledger both use it). Reset the seam in `afterEach`.
   Positive control: the same check on the pre-fix code (a row appended) reports `STATE.md` as `changed`.
5. Local mode regression: existing tests F1-6..F1-10, FS-1..FS-4 and e2e-1 pass unchanged (two commits, a row appended).
6. Local mode regression: STATE.md missing -> `no-state-file`, as today.

<anti_patterns>
- Writing STATE.md "through a verb" in store mode: no verb owns a generated view, and writing it is exactly the drift W055 reports.
- Skipping `endSkill` or the `.micro-description` cleanup in store mode. Marker cleanup is the user-meaningful unit and must always happen.
- Calling `isStoreMode(planningDir)`. Pass the project root (`path.dirname(planningDir)`); the function resolves the main checkout itself.
</anti_patterns>
