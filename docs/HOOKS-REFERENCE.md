# Hook reference

The per-hook detail that used to sit in the root `CLAUDE.md` `### Hooks` section. Registrations live in
`plugins/aoforge/hooks/hooks.json` (and `plugin.json` for the status line); `CLAUDE.md` keeps one line per hook and
the hook-inventory test pins that list to the registrations.

**One process for PreToolUse(Bash).** `hooks/pre-bash.js` is the only registration for the event: it reads stdin
once and runs `gate-commits.js`, `changelog-on-tag.js`, `gate-interactive.js`, `gate-bash-writes.js` and
`guard-no-progress.js` in-process, each through its exported `main()`, then merges the outputs the way Claude Code
merges parallel hooks (exit 2 wins, then deny over ask with every reason kept, additionalContext concatenated,
stderr passed through). Each of those files still runs standalone (its own tests spawn it) and carries a
`DISPATCHED-BY: pre-bash.js` line in its first 40 lines, the marker doctor check 12, the hook inventory test and the
docs generator read to count it as registered. guard-no-progress keeps its own registration for every tool but
Bash, so a Bash call is counted once. Measured: five processes (~435 ms CPU, ~130 ms wall on Linux) became one
(~80 ms). `hooks/pre-bash-equivalence.test.js` (TRD 79-03) proves the one process decides what the five decide as
separate processes: over a hand-built corpus (`hooks/__fixtures__/bash-corpus.js`) it spawns both sides with their
own fixture project, scratch HOME and progress-guard directory, and compares exit code, decision, reasons, context,
output and three side effects (queued handoff records, the progress guard's counters, the edit-override marker).

Node.js hooks declared in `plugins/aoforge/hooks/hooks.json` and auto-registered when the plugin is enabled. All hook commands use `${CLAUDE_PLUGIN_ROOT}` for path resolution. Since 3.1.0 no hook reads the pre-rename environment prefix or trusts the pre-rename agent namespace (objective 78); `coexistence-guard.js` reports leftovers instead.

**Runtime sync:**
- `sync-runtime.js` — SessionStart; mirrors `${CLAUDE_PLUGIN_ROOT}/aoforge/` to `~/.claude/aoforge/` when the bundled plugin version differs from the cached `.plugin-version`, or when a same-version content change alters the bundle digest (`.plugin-digest`, from `lib/runtime-digest.cjs`). After a successful mirror, it runs the global upgrade (`lib/global-upgrade.cjs`). That moves the pre-plugin (v1) install's prefixed skills and agents under `~/.claude` to a backup and maintains the managed `~/.claude/CLAUDE.md` AOForge block; a pre-rename block or routing heading there is left untouched with one notice (no move, no outside-text rewrite). The first adoption over a hand-written section waits for `aof-tools upgrade --global --confirm`. Since 3.1.0 it no longer carries the pre-rename runtime home's state over (objective 78); the coexistence notice and doctor check 16 report a home that 3.0.x never migrated.

**Session context (SessionStart / UserPromptSubmit; handoff delivery on PostToolUse / Stop):**
- `awareness-cache-populate.js` — SessionStart; warms the cross-repo awareness cache, kept out of the repo at `~/.claude/aoforge/state/awareness/<repo-key>.json` (`lib/awareness-store.cjs`; override `AOFORGE_AWARENESS_DIR`)
- `classify-session.js` — SessionStart; classifies the session for routing/telemetry (a routing directive for an AOForge project)
- `route-results.js` — UserPromptSubmit; the catch-all for queued handoff results: delivers every fresh one no other hook took, whatever session or agent queued it, through `lib/handoff-results.cjs`, exactly once (O_EXCL claim); also emits queued notices once. Escapes: `AOFORGE_SKIP_HANDOFF_RESULTS=1` (results), `AOFORGE_SKIP_NOTICES=1` (notices)
- `inject-handoff-results.js` — PostToolUse(`*`) + Stop (objective 73); delivers completed handoff results addressed to the session and agent that queued them (after the next tool call, or by blocking the stop, waiting up to `AOFORGE_HANDOFF_STOP_WAIT_MS` (120 s, `0` disables) while a command this session's main loop queued is still running) through `lib/handoff-results.cjs`, exactly once (O_EXCL claim); route-results stays the catch-all on the next prompt. The Stop registration carries `"timeout": 150`, above the wait. Escapes: `AOFORGE_SKIP_HANDOFF_INJECT=1`, `AOFORGE_SKIP_HANDOFF_RESULTS=1`
- `upgrade-project.js` — SessionStart; upgrades a behind project in place (bundled aof-tools; applies auto migrations, background-commits only the changed files; skip rules, though runtime-state paths (migration 0008) are exempt from the dirty-before skip; fast path when the stamp matches; notices via route-results). A project holding only the pre-rename planning directory gets one global notice (`legacyLayoutMessage`) and nothing written. Also runs the throttled backup prune (once per 24h, AOForge project or not) as the first step of `main()`, then starts a detached background `aof-tools transcript-export` at most once per 24h (step 0b, `lib/transcript-export-schedule.cjs`, stamp under `~/.claude/aoforge/state/transcript-export/`). Escapes: `AOFORGE_SKIP_UPGRADE=1` (upgrade only), `AOFORGE_SKIP_PRUNE=1` (prune only), `AOFORGE_SKIP_TRANSCRIPT_EXPORT=1` (export only)
- `coexistence-guard.js` — SessionStart; queues one global notice per session for every global leftover of the rename that 3.1 no longer reads (`lib/coexistence.cjs`, objectives 72 and 78): the pre-rename plugin still enabled (its version and the exact `claude plugin disable` command; an installed pointer release gets an info-level line), pre-rename env variables (each with its `AOFORGE_*` form), the pre-rename runtime home never migrated by 3.0.x, and files 3.0.0 left in `~/.aoforge/`; several findings make one line plus one detail line each. Reports only: never edits settings or moves a file. Escape: `AOFORGE_SKIP_COEXISTENCE=1`

**Observability (warn-only):**
- `statusline.js` — StatusLine (declared in plugin.json `statusLine`); renders model, task, context usage and, while an objective builds, estimated time remaining from the estimate run state
- `verify-completion.js` — Stop; checks SUMMARY.md evidence
- `verify-commits.js` — SubagentStop; warns on no commits in last 10min, and in autonomous mode blocks an `aoforge:executor` (`compat.isOwnExecutor`; the pre-rename namespace is not trusted since 3.1.0) stop once per agent (top-level `{decision, reason}`, objective 70)
- Their autonomous retry and resume markers live in `~/.claude/aoforge/state/hook-markers/<repo-key>/` (`lib/hook-marker-store.cjs`; override `AOFORGE_HOOK_MARKER_DIR`). `hooks/planning-writes.audit.test.js` fails CI if any hook writes a runtime dotfile into `.aoforge/`; the allowlist is `.skill-active`, `.edit-override` and `.aoforge-notices.json`.
- `gh-flush.js` — PostToolUse(Bash) + Stop; store mode only: flushes the outbox after `aof-tools commit` and at Stop, reports pending/halted writes on both and cache drift (W055) at Stop only; never blocks, fails open. Escape: `AOFORGE_SKIP_GH_FLUSH_HOOK=1`
- `todo-sync.js` — Stop; merges the session's `/aoforge:todo` items (TaskCreate/TaskUpdate or TodoWrite calls in the transcript) into the todo archive with `todo sync`'s library (`.aoforge/todos/`, or queued for the GitHub store); idempotent, never blocks, keeps no state, fails open. Escape: `AOFORGE_SKIP_TODO_SYNC=1`

**Enforcement (active gates):**
- `pre-bash.js` — PreToolUse(Bash); the one registration for the event (perf #133, described above). A throwing hook is skipped.
- `route-intent.js` — UserPromptSubmit; injects skill-routing reminders when AOForge project is detected
- `gate-commits.js` — PreToolUse(Bash) via pre-bash; blocks raw commit invocations. Detection is invocation-aware (TRD 27-04): heredoc bodies and quoted arguments are stripped first, so text that merely *mentions* the command is not gated. Allows merge/rebase/cherry-pick completion (MERGE_HEAD, REBASE_HEAD, rebase-merge/-apply, CHERRY_PICK_HEAD in the per-worktree git dir) and an inline `AOFORGE_ALLOW_RAW_COMMIT=1 git commit …` prefix; an exported variable never reaches the hook (objective 44). Escape: `AOFORGE_ALLOW_RAW_COMMIT=1` in the env Claude Code was launched from
- `gate-edits.js` — PreToolUse(Edit/Write/MultiEdit); **strict DENY by default** in ambient mode (AOForge project + no skill active). Allows edits when a live `.aoforge/.skill-active` marker exists — resolved from **both** the local `.aoforge/` and the MAIN checkout's, so worktree-isolated agents are not denied by a gitignored marker they can never see (TRD 27-01) — or the PreToolUse payload's `agent_type` starts with `aoforge:` (objective 44, `compat.isOwnAgentType`; the pre-rename agent namespace is not trusted since 3.1.0), or the user prompt contains an override phrase (`skip aoforge`, `just edit`, `bypass aoforge`, `force edit`), or `AOFORGE_SKIP_EDIT_GATE=1` is set in the environment Claude Code was launched from. Markers carry `expires_at` (8h default). Targets outside the project root (session scratchpad, `/private/tmp`) are never gated (TRD 27-02). Severity is per-project via `.aoforge/config.json` → `gates.editGate`: `strict` (default) | `warn` | `off`. In store mode, cache/generated `.aoforge/` paths are denied for everyone (skill markers and aoforge agents included) with the verb to use; config.json, STACK.md and runtime files are allowed (needs an installed plugin carrying objective 48). Bash writes to the same files are gated by `gate-bash-writes.js`.
- `gate-bash-writes.js` — PreToolUse(Bash) via pre-bash; denies a Bash write to a tracked source file in ambient mode (redirect, `tee`, `sed -i`, `perl -i`, `cp`/`mv`, inline python/node), the same as Edit/Write (DECISION-001, objective 60). Mentions (heredoc bodies, quoted args) and writes to `.aoforge/`, `*.md`, untracked files, paths outside the project and unresolvable targets are never gated. Same escapes as gate-edits (live skill marker, `aoforge:*` agent, override phrase); the override marker is consumed only by a write that would be gated. Severity is the least of `gates.editGate` and `gates.bashEditGate` (`strict` deny | `warn` ask | `off`). With no `bashEditGate` key the default is `warn` (`BASH_EDIT_GATE_DEFAULT`), measured at 633/17,957 = 0.035251 of ambient Bash calls (an upper bound, above the 0.02 threshold), so `strict` is opt-in; `gates.editGate` `warn` softens it to ask and `off` disables it. Escape: `AOFORGE_SKIP_EDIT_GATE=1` only in the environment Claude Code was launched from, never as an inline command prefix (a hook runs in Claude Code's own process); needs an installed plugin carrying objective 60
- `gate-skill-requires.js` — UserPromptExpansion + PreToolUse(Skill); refuses a `/aoforge:<skill>` whose SKILL.md `requires:` names a tool that is not on PATH (block on a typed command, deny on a Skill call), naming the install hint and `/aoforge:doctor` (check `skill-requires`). Not project-scoped; fails open. Escape: `AOFORGE_SKIP_SKILL_REQUIRES=1`, only in the environment Claude Code is launched from; needs an installed plugin carrying objective 61
- `gate-interactive.js` — PreToolUse(Bash) via pre-bash; denies a TTY-requiring or shell-env command and queues it to `aoforge-watch` as a pending record carrying the payload's `session_id` and `agent_id`; with the daemon live the reason tells Claude to say in one line that the command waits in the user's aoforge-watch terminal (attended `start --foreground`, objective 73) and that the result returns by itself, else to ask for `! cmd`. Invocation-aware (TRD 73-10): matches each simple command from `shell-words.parseCommand`, so quoted text and heredoc bodies are data while a heredoc fed to a shell is read (one level); flags and the deny reason are per call (a compound command's reason names the matching call); `ssh-keygen` read-only forms (`-l`, `-F`, `-R`) pass and `-y` without `-P` is handed off. The matcher lives in `lib/interactive-commands.cjs` (loaded fail-open) and the watch daemon's built-in allowlist uses it too, so the daemon accepts exactly what the hook hands off (TRD 73-12); the daemon is read through `watcher-state.cjs`, and its pid file and logs live under `~/.claude/aoforge/state/watch/` (`compat.watchStateDir`). Not matched: a quoted or path-qualified command name, `env`/`time`/`command`/`exec`/`sudo`/assignment prefixes and shell keywords, `$( )` inside double quotes, backticks, `bash -c` string bodies. Escape: `AOFORGE_SKIP_INTERACTIVE_GATE=1`
- `guard-no-progress.js` — PreToolUse on every tool (Bash via pre-bash, the rest registered directly with `^(?!Bash$).*`); detects the same tool called with identical arguments repeatedly. Warns on stderr at 3 repeats, escalates to `ask` at 5, resets whenever the agent varies its approach. Step limits cannot do this — they fire only after the budget is spent. Deliberately **not** wired to tool errors: those run 3.6–4.3% at every model tier and are dominated by environment friction (TRD 28-04). State is per-session under `~/.claude/aoforge/state/progress-guard/` (never in the repo; override `AOFORGE_PROGRESS_GUARD_DIR`). Escape: `AOFORGE_SKIP_PROGRESS_GUARD=1`
- `changelog-on-tag.js` — PreToolUse(Bash) via pre-bash; blocks `git tag -a vX.Y.Z` if `CHANGELOG.md` lacks `## [X.Y.Z]`. Escape: `AOFORGE_SKIP_CHANGELOG_GATE=1`
- `gate-executor-stop.js` — SubagentStop; blocks an `aoforge:executor` natural stop once when its TRD (read from the agent transcript's first prompt) has no `<id>-SUMMARY.md` in any checkout, or its final SUMMARY has no `tokens_input`/`tokens_output` (objective 66). Never when `stop_hook_active`; fails open. Escape: `AOFORGE_SKIP_EXECUTOR_STOP_GATE=1`
- `auto-continue.js` — Stop; blocks once when a skill marker is live, no background task is running, and the last sentence announced the model's own next step without asking (questions, `/aoforge:` hand-offs, waits and reports are ignored). Escape: `AOFORGE_SKIP_AUTOCONTINUE=1`

**Draft (not registered in hooks.json):** this file ships in `hooks/` with a `DRAFT` header (v1.1 coordination-layer work) but no event fires it.
- `inject-org-context.js` — would inject org/initiative context at planning time

**Not an AOForge hook:** the worktree-isolation guard ("This agent is isolated in the worktree…") is a Claude Code harness guard. It refuses compound Bash commands it cannot statically verify — including ones with no git in them — and no `AOFORGE_*` escape hatch applies. Agents mitigate it by emitting one plain command per Bash call (see `agents/executor.md` → `worktree_command_discipline`).
