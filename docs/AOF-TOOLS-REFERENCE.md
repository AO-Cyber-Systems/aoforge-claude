# aof-tools command reference

The command catalog that used to sit in the root `CLAUDE.md` `### Core Tool` section, kept here so the file that
is resident on every turn stays short. `node ~/.claude/aoforge/bin/aof-tools.cjs --help` lists every command and
`aof-tools <command> --help` prints one command's usage; `docs/USER-GUIDE.md` is the user-facing guide. The
dispatch-completeness test pins the short list in CLAUDE.md to the dispatcher; this file is prose.

The central CLI utility used by ~50 skill and agent files. CommonJS module invoked as `node ~/.claude/aoforge/bin/aof-tools.cjs <command> [args]` (skills resolve the path via the home mirror). A global `--cwd <dir>` flag, valid before any command name, `chdir`s before dispatch so a command can target a path other than the caller's cwd (used by `/aoforge:adopt [path]`). Provides:

- **State operations** — `state load` (config plus the STATE.md digest), `state digest`, `state get`, `state update`, `state patch`, `state-snapshot`, `state advance-job [--objective N]` (with `--objective`, position and Status come from the objective's TRD and SUMMARY files on disk; it also rotates decisions past the newest 10 into STATE_ARCHIVE.md), `state rotate-decisions`; `state update-progress` rewrites or adds the Progress line under `## Current Position`, else exits 1; `state rekey --from <old checkout path> [--to <new path>] [--dry-run] [--raw]` copies repo-keyed runtime state (KEYED_STATE: estimate run state and history, awareness, hook markers, outbox journal without its `.lock`, backups plus the registry entry, planning drafts) from a moved checkout's old key to its new one, merging and never deleting (`lib/state-rekey.cjs`, TRD 72-07). STATE.md is a digest, not an archive: W068 reports an oversized decision log. A SUMMARY whose frontmatter `status:` is `deferred` or `checkpoint`, or whose `## Progress` has an unticked task and no `## Self-Check` (a mid-TRD progress checkpoint), does not count as complete in roadmap reconcile, `roadmap update-job-progress` and `analyze`, `objective complete` and `state advance-job`/`update-progress`.
- **Objective operations** — `objective next-decimal|add|insert|remove|complete|put|set-status`; `milestone complete <v> --dry-run` previews and a re-run keeps the existing entry and archives; `milestone put`. Every writing command rejects an unknown flag with exit 1 before it runs (`lib/flag-guard.cjs` + `lib/flag-spec.cjs`, kept complete by `flag-spec.repo.test.cjs`).
- **Roadmap operations** — `roadmap get-objective`, `roadmap analyze`, `roadmap digest`, `roadmap update-job-progress`
- **Compound init commands** — `init execute-objective`, `init plan-objective`, `init new-project`, etc.
- **Model resolution** — `resolve-model <agent-type> [--objective N]` returns the model for an agent from `references/model-profiles.json`. Precedence: an OBJECTIVE.md/TRD `model_profile` override, then config `model_profile` (quality / balanced / budget; `auto` opts into the (kind, work) defaults table per objective, an unset key stays balanced); a stack pack agent takes its tiers from its pack manifest (objective 76/77). `--focus` applies `focus{}` tiers (`mapper_models`, `researcher_models`); `verdict_floor` keeps verifier and job-checker at Sonnet+; `--escalate-from` gives the next rung for `## ESCALATION REQUESTED` (TRDs 76-06, 76-07).
- **Mechanical verbs** (TRD 76-04) — one call each for work agents did by hand: `trd finalize <obj>-<trd>` (post-SUMMARY bookkeeping), `verify objective-evidence <obj>`, `validate roadmap-coverage`, `codebase facts [--focus]`, `security sweep [--focus]`.
- **Validation** — `validate consistency`, `validate health [--repair]`, `validate docs`, `validate requirements [--objective N]` (read-only W065 scan, `lib/requirements-agreement.cjs`), `validate roadmap-coverage` (every v1 requirement maps to exactly one ROADMAP objective; exit 1 on a gap, TRD 76-04). Health checks report E0xx/W0xx codes: W040 behind, W050-W054 docs, W055-W061 store, W062-W069 pins, markers, layout and the decision log. `validate health` Check 19 reports E006/W064 (tracked or stale `.aoforge/.skill-active`, `lib/skill-marker-health.cjs`, `--repair` untracks only it) and Check 20 W065. W068 is the oversized STATE.md decision log (migration 0015 rotates it). The pre-rename layout (objective 78), from `lib/planning-layout.cjs`, never repaired: W066 legacy-planning-dir is the one broken result when only the pre-rename planning directory exists (Check 0 runs no other check and writes nothing, `--repair` included; convert with AOForge 3.0.x, or `git mv` the directory by hand as `docs/MIGRATING-TO-AOFORGE.md` describes), and a warning when both directories exist (the old one ignored); W067 legacy-config-key (`.aoforge/config.json` has the pre-rename stamp key: alone, rename it to `aoforge`; beside `aoforge{}`, delete it); W069 legacy-claude-md-block (Check 23: a project CLAUDE.md block under the pre-rename markers; rename the two markers by hand). W069 and not W068 because `main` already used W068 for the decision log.
- **Config & commit** (Unreleased) — `config-get <key>` returns the documented `templates/config.json` default (exit 0) for a known-but-unset key, never overriding a legacy or alias form the user set; unknown keys still error. `commit --files` records a staged removal of a now-ignored path (git rm --cached) with a whole-index commit, and refuses if anything outside `--files` is staged.
- **GitHub integration** (1.29+, opt-in via `github.enabled` in `.aoforge/config.json`) — `gh sync`, `gh pull`, `gh outbox`, `gh trd`, `gh pr`, `gh orphans`, `gh setup`, `gh status`, `gh rebrand [--repo o/r] [--apply|--dry-run] [--raw]` (TRD 72-16, `lib/gh-rebrand.cjs`: dry run by default; renames one repository's pre-rename labels (merged into an existing AOForge label with a destructive delete), managed issue/PR/comment markers and wording (only the product name outside managed sections; PRESERVE tokens and the repo slug never), wiki pages, ruleset check contexts (repository admin, else the section reports "needs admin") and, in a checkout, the managed caller, docs backend, PR template block and config labels; `--apply` stops at the first failure and resumes by re-planning, refreshes outbox bases in store mode, never commits; flush the outbox first and set `AOFORGE_APP_*` by hand). **Store mode** (`github.store: true`, default false) makes GitHub the system of record: issues, TRD sub-issues, comments and wiki pages hold the planning state, every verb queues its write in the outbox, and `.aoforge/` is a cache that `gh pull --all` rebuilds. Store off is a one-way mirror. In store mode each objective runs on one linked branch and PR, and `aof-tools commit` refuses the default and unlinked branches. Since 3.1.0 a repository still carrying a pre-rename default label is refused by every label lookup until `gh rebrand --apply` (`lib/gh-legacy-labels.cjs`), and `gh setup` refuses a PR template holding the pre-rename block (fix: `gh rebrand --apply`). Escapes: `AOFORGE_SKIP_GH_GATE=1` (logged as gate gh), `AOFORGE_SKIP_GH_FLUSH_HOOK=1`. Module families: `lib/gh*.cjs` (client, mirror, store and outbox, PR, gate and checks, setup, backfill). `/aoforge:gh-sync migrate` moves a project onto the store. Detail (outbox and PR exit codes, setup payloads, W057-W061, App keys, open items): `docs/USER-GUIDE.md` → GitHub is the system of record.
- **Planning verbs** (Unreleased) — every planning write goes through one verb taking `--from <path|->`: `plan put-trd|push`, `summary post|checkpoint [--tick <n|text>]`, `verification post`, `doc put`, `objective put|set-status`, `todo add|complete|sync`, `debug put|resolve`, `quick put|summary`, `decision open|answer`, `milestone put|complete` (`todo sync` merges a session's task-list todos into the archive; the todo-sync Stop hook runs it); plus `planning mode`, `planning draft <rel>` (reseeds a stale draft and keeps `<draft>.stale`; `doc put` refuses one, `lib/planning-drafts.cjs`) and `planning import [--dry-run]` (with the store off, a preview of the backfill and its request estimate). D-01 invariant: with `github.store` off every verb writes today's `.aoforge/` file byte for byte with zero `gh` calls and `.aoforge/` stays tracked, in the checkout that runs it when that checkout has its own planning directory, else in main (`planning-mode.resolveVerbRoot`, quick 36), so a worktree commits its own SUMMARY; in store mode (set in the main checkout's config) it writes main's cache, records the ledger and queues the GitHub write. A worktree still on the pre-rename planning directory is refused, never written (`planning-verbs-worktree.legacy.test.cjs`, TRD 79-04). `validate health` Check 15 reports W055 and W056. `planning-writes.repo.test.cjs` fails CI on any direct planning-write instruction.
- **Telemetry & audit** (2.5+) — `context` (context composition), `session-audit` (blocking-event classification), `transcript-export` (compact per-session index before retention deletes transcripts), `telemetry [--scan [--limit N] [--since YYYY-MM-DD] [--root dir]]` (one status-facing view with advisories, including documentation staleness; `--scan` adds a transcript session audit of blocking events and rejects an unknown flag), `override --gate <g> --reason <why>` (structured, logged gate override; `override --list` reads the log). Implemented in `lib/context-audit.cjs`, `lib/session-audit.cjs`, `lib/transcript-export.cjs`, `lib/telemetry.cjs`, `lib/override.cjs`, fronted by `lib/audit-cli.cjs`.
- **Documentation correctness** (Unreleased) — `DEPRECATION_MAP` + `REMOVED_COMMANDS` (`lib/skill-route.cjs`) are the only rename source; `lib/doc-refs.cjs` resolves them. `doc-refs.repo.test.cjs` fails CI on stale command references. Migration 0007 fixes them in a project's CLAUDE.md AOFORGE block and STATE.md. `validate health` Check 14 / `aof-tools validate docs` report W050-W054 (advisory, never repaired).
- **Changelog** (1.30+) — `changelog update --version vX.Y.Z [--from <ref> --to <ref>] [--dry-run]`, `changelog check <version>`. Implemented in `lib/changelog.cjs`; generates Keep-a-Changelog entries from conventional-commit history.
- **Upgrade** (Unreleased) — `upgrade [--check|--apply] [--only id] [--confirm] [--path dir] [--kind k] [--default-work w] [--global] [--prune] [--register]`. Brings a project forward in place and stamps `.aoforge/config.json` `aoforge{version, migrations_applied, upgraded_at}`. The migrations are detection-based and idempotent (`lib/migrations/NNNN-*.cjs`, `auto` | `confirm`), with backups under `~/.claude/aoforge/backups/`. Migration 0008 (auto) gitignores and untracks `.aoforge/.progress-guard.json` / `.awareness-cache.json` / `.dup-detect-log.jsonl` / `.check-todos-cache.json` / `.deprecation-log.jsonl` / `.override-log.jsonl`, keeping the working copies; it covers nested `**/.aoforge/` runtime state too. Migration 0009 (auto) converts `.aoforge/.gh-mapping.json` to v3 and normalises `.gh-sync-state.json` keys. Migration 0010 (confirm, store mode only) gitignores and untracks the planning cache, and skips while a backfill is pending. Migration 0011 (confirm, resumable) backfills the planning history onto GitHub, turns store mode on and hands off to 0010; a stop on the hourly budget is resumed by re-running it. The 3.0.0 rename's migrations 0012 (planning-dir move), 0013 (config-key rename) and 0014 (CLAUDE.md rebrand) were retired in 3.1.0 (objective 78): their ids stay reserved in `RETIRED_MIGRATIONS`, so `--only 0012|0013|0014` exits 1 naming AOForge 3.0.x and the migration guide; the stamp is read from `aoforge{}` only and the writer never touches the pre-rename key; in a project holding only the pre-rename planning directory, apply and check write nothing and report `legacy_layout` as their one failure. Migration 0015 rotates the STATE.md decision log into STATE_ARCHIVE.md. The runner's generic deferred path stays. `--global` upgrades `~/.claude` instead; a pre-rename block or routing heading there is left untouched with one notice (no move, no outside-text rewrite). `--prune [--dry-run]` runs the backup pruner unthrottled and prints its report; `--register [--path dir]` registers a repo for pruning without a full upgrade. Implemented in `lib/upgrade.cjs`, `lib/upgrade-cli.cjs`, `lib/migrations/`, `lib/managed-block.cjs`, `lib/global-upgrade.cjs` and `lib/backup-prune.cjs`. `validate health` reports W040 when a project is behind.
- **Estimation data** (Unreleased) — `tokens trd|stamp|backfill|coverage` reads per-TRD executor token usage from transcripts (the backfill form is a dry run unless `--write`; `tokens coverage [--milestone|--objective]` reports forward-stamp coverage, live over counted, floored and read-only); `calibrate [--paths] [--out] [--rates] [--window <N|all>] [--minutes <task_sum|trd_level>] [--through <N>] [--dry-run]` writes per-task-class p50/P90 minutes, tokens and dollars to `~/.claude/aoforge/calibration.json` (override `AOFORGE_CALIBRATION_PATH`), byte-identical on unchanged inputs. `calibrate` also measures agent overhead (`--root`, `--no-overhead`); calibration version 2 adds `agent_overhead` and `objective_level`, version 3 adds the method block (minutes, window, cutoff). `estimate task|trd|objective|milestone` prints median/P90 minutes, tokens and dollars with sample count and confidence (correlated-sum composition, wave max, gap-closure mixture); `estimate start|wave|finish` keep the run state in `~/.claude/aoforge/state/estimates/` (override `AOFORGE_ESTIMATE_STATE_DIR`) that the status line reads and archive finished runs to `history/<repo-key>/` beside it; `estimate backtest <N[,N...]> [--calibration f] [--raw]` compares estimates with measured minutes and priced tokens and prints the EST-08 verdict (objective 64: not met, `64-ACCURACY-REPORT.md`). `calibrate` keeps the 10 most recent objectives with samples per project by default and `--window all` keeps all history; default changed but EST-08 is still not met (minutes median ratio 1.348 to 1.238 on 59-63, five leave-future-out objectives, cost P90 coverage 78%, not prospective). Objective 67 froze the minutes method for EST-11 (DECISION-003: trd_level, window 10, through 66; validation in `67-VALIDATION.md`). Rates live in `references/model-rates.json`. Implemented in `lib/token-usage.cjs`, `token-backfill.cjs`, `tokens-cli.cjs`, `token-coverage.cjs`, `calibration-inputs.cjs`, `calibrator.cjs`, `calibrate-cli.cjs`, `trd-identify.cjs`, `agent-overhead.cjs`, `estimate-math.cjs`, `estimate.cjs`, `estimate-rollup.cjs`, `estimate-milestone.cjs`, `estimate-format.cjs`, `estimate-cli.cjs`, `estimate-run-store.cjs`, `estimate-backtest.cjs`. Detail: `docs/USER-GUIDE.md` → Estimation data, Estimates.
- **Adopt** (Unreleased) — `adopt preflight|begin|scaffold|report [--cwd dir]`. Unattended bootstrap of an existing repo into an AOForge project: preflight checks state/cleanliness/branch, scaffold writes config/STATE/`state.json`/ROADMAP and the CLAUDE.md managed block then stamps via `upgrade --apply`, report writes `.aoforge/ADOPT-REPORT.md`. Idempotent — a half-finished adopt resumes. Implemented in `lib/adopt.cjs`, `lib/adopt-cli.cjs` and `lib/repo-state.cjs` (the one aoforge/greenfield/brownfield/scratch detector shared with `project-state.cjs` and `init new-project`). Driven end-to-end by `skills/adopt/SKILL.md` + `workflows/adopt.md`.
- **Doctor** (Unreleased) — `doctor [--fix] [--json] [--path dir] [--global]`. Read-only by default. Checks live in `lib/doctor-checks/NN-<id>.cjs` (10-19 global install, 20-29 project, 30-39 state hygiene, including 13 (model-profiles, which also flags a superseded model id), 14 (skill-requires), 26 (checks-workflow-pin), 23 (skill-markers, which also catches a tracked marker and owns E006/W064, check 22 defers them) and 33 (decision-resolution, which repairs decisions flattened by the pre-52 writer); for the 3.0.0 rename (report-only since 3.1.0: the conversions belong to 3.0.x or the manual steps), 15 (legacy-df-install: legacy-prefixed skills/agents under `~/.claude`; names the global upgrade, `fix_command` `aof-tools upgrade --global --apply`), 16 (legacy-plugin-runtime, detection from `lib/coexistence.cjs`: the old plugin still enabled, the old runtime home never migrated (3.0.x or a manual copy) or left over (the printed move into `backups/legacy-<old runtime dir>-runtime-<date>/`), legacy env vars), 27 (legacy-planning-layout: owns W066/W067/W069, check 22 defers them; a legacy-only root resolves no project and the layout message is a doctor note) and 26's legacy branch (a pre-rename managed caller gets W062 with `gh rebrand --dry-run`, never a re-pin); for what 3.0.0 left behind, 17 (user-dot-dir, objective 73, the one rename check that keeps its fix in 3.1, because 3.0.0 wrote those files under the AOForge name and no 3.0.x release moves them: a leftover `~/.aoforge/`; fix moves its known files to `~/.claude/aoforge/` (watch files to `state/watch/`) or into `backups/aoforge-dot-dir-<ts>/` when a newer copy exists or the pid is stale, never deletes or overwrites, removes the directory only once empty; report-only while a daemon there is live, an installed service still logs there or it holds planning files; unknown files such as `.DS_Store` are listed and left)); `validate health` Check 17 reports W062 (stale checks-workflow pin) and Check 18 W063 (superseded model id); the contract is in `doctor-checks/README.md`. `--fix` applies only safe, reversible fixes and re-runs every check; it refuses index-changing fixes while unrelated changes are staged (`lib/doctor-git.cjs`) and never commits. It composes validate health / upgrade / backup-prune / the stores rather than re-implementing them. Plugin cache dirs are report-only. Implemented in `lib/doctor.cjs`, `lib/doctor-cli.cjs`, `lib/doctor-git.cjs`, `lib/doctor-checks/`. Driven by `skills/doctor/SKILL.md`.
- **Merge driver** (Unreleased) — `merge-driver install [--check]|uninstall|resolve <path>|state-json`. Per-clone, nothing committed: a JSON-aware 3-way merge for `.aoforge/state.json` and union for `STATE_ARCHIVE.md` so parallel wave merges do not conflict. The recorded driver is a fail-safe wrapper (a missing binary degrades to an ordinary conflict) pointing at the main checkout's or the mirror's aof-tools; the execute-objective workflow installs it and falls back to `merge-driver resolve <path>`. Implemented in `lib/state-merge.cjs`, `lib/merge-driver-cli.cjs`. Detail: `docs/USER-GUIDE.md` → Parallel wave merges.
- **Stack profile** (2.11+, drafter Unreleased) — `stack resolve|context|validate|command|init|verify [--run [--allow-services]]|report|mcp [--write]|discover|doctor`. `.aoforge/STACK.md` resolves over bundled general → tier-2 → project → component (an active pack's profiles resolve as a tier, objective 77). `stack init` drafts from CI/runner/manifest evidence (writes only with `--write`; a gate's `--self-test` step never beats the gate; a lint target adding linters such as buf lint is kept); `stack verify` checks each command, `--run` executes safe keys only and is effect-based (snapshot/restore around each gate; Dart/Flutter gates halt after a mutation; Flutter runs with `--no-pub`; a gate with a service signal (its text, the CI job that runs it, or for test/e2e a `.env.test` file) is skipped `env_required` unless `--allow-services`; a build gate's new files under bin/build/dist/out/target are removed and listed as `build_outputs` without halting); `stack report` proposes to `.aoforge/STACK-REPORT.md`; `stack mcp --write` is the only writer of the opt-in `.mcp.json`. The bundled tier-2 profile (go) lives in `aoforge/stack-profiles/` (mirrored by sync-runtime; flutter and dart ship in their pack); user/org overrides in `~/.claude/aoforge/stacks/<id>.md` are never mirrored over. Modules: `lib/stack-profile.cjs` + `stack-evidence|ci|shell|classify|runners|detect|draft|verify|report|mcp|render.cjs`. Guide: `templates/stack.md`.
- **Stack packs** (objective 77, `docs/PROPOSAL-stack-packs.md` §5A) — stack-specific procedure lives in pack plugins (`plugins/aoforge-stack-flutter`, `plugins/aoforge-stack-web`), never core: a pack ships `aoforge-stack.json` (schema `schemas/stack-pack.schema.json`) and a SessionStart hook that mirrors it to `~/.claude/aoforge/stacks/<name>/`. A pack is active when its plugin is enabled and the project selects it (`extends:` one of its profiles, config `stacks.enabled`, a matching `verification.runtime`, or an active pack's `soft_depends` platform rule, such as Flutter → web for platform web); `stack discover` only proposes. `stack context <agent>` appends a Read pointer per active fragment; `stack verify --changed|--all [--task id]` merges pack results (error > missing > fail > pass); `stack doctor` checks an active pack's tools and warns on an absent soft dependency. Manifest hooks `gate_policy` (stack verify --run), `awareness` (org-awareness exports) and `ui.pattern_catalogue` keep the rest of a stack in its pack. `stack-neutrality.repo.test.cjs` fails CI on a pack-owned stack named in core outside its allowlist.
- **Rename leftovers** (3.0.0, objective 72; shims removed in 3.1.0, objective 78) — 3.1.0 reads only AOForge names. `lib/legacy-names.cjs` is the only module that spells the pre-rename names: `NAMES`, `LEGACY`, `PRESERVE` (other products and the docs domain, never rewritten), `SHIM_RELEASE` (`3.0.x`, the conversion path every legacy message names) and `SHIM_REMOVAL` (`3.1.0`); everything else builds them from it, `legacy-names.legacy.test.cjs` fails on a `LEGACY` key nothing reads, and `rename-guard.repo.test.cjs` fails CI on a legacy name outside its ALLOW list and the ignore regions of `IGNORE_REGION_FILES` (USER-GUIDE, the migration guide and its site page, the site `_redirects`). 3.1 reads an old name only to detect and report it (`lib/planning-layout.cjs`, `lib/coexistence.cjs`, `lib/legacy-layout-guard.cjs`, managed-block, global-upgrade, gh-setup, `lib/gh-legacy-labels.cjs`, checks-pin, stack-mcp, doctor 15/16), to convert it on request (`gh rebrand` with `lib/legacy-rewrite.cjs`), or to read history (session-audit, agent-overhead; benchmark and token-usage count `.aoforge/` paths only). `lib/compat.cjs` keeps its name but holds no shim and imports nothing from legacy-names: `planningDirName`/`planningRoot`/`planningRel`/`PLANNING_DIR_NAMES` name `.aoforge/` alone, `findProjectRoot` finds `.aoforge/` only and never returns `$HOME` or searches above it (planning-mode's lookups refuse it too, objective 73), `isOwnAgentType`/`isOwnExecutor` accept `aoforge:` only, `userDotFile` is the runtime home with no fallback, `watchStateDir` (`~/.claude/aoforge/state/watch/`: the watch daemon's pid file and log and the service logs; the watch daemon's start refuses while a 3.0.0 daemon in `~/.aoforge/` is alive, `watcher-state.interimDaemon()`), `runtimeHome`. The pre-rename env prefix is not read (the coexistence notice names each variable). A project holding only the pre-rename planning directory gets one message (`legacyLayoutMessage`): `validate health` broken W066, a doctor note, the CLI refusing every planning-tree write and `init` (`lib/legacy-layout-guard.cjs`, exemptions with reasons), one global notice from `upgrade-project.js`, and no `.aoforge/` created. A repository with a pre-rename default label is refused by every label lookup until `gh rebrand --apply` (`lib/gh-legacy-labels.cjs`). The pointer plugin (the final 3.0.0 release of the pre-rename plugin) was removed in 3.1.0 with its generator, marketplace entry, package.json test glob and rename-guard ALLOW entries (TRD 78-02); `lib/coexistence.cjs` still recognises an installed copy (`POINTER_MAJOR`) to soften its notice. Every per-check decision: `.aoforge/objectives/78-remove-the-rename-shims/78-12-SUMMARY.md`. User-facing guide: `docs/MIGRATING-TO-AOFORGE.md` ("Upgrading from 2.x").
- **Repo guard tests** — `reconcile-guard.repo.test.cjs` (TRD 79-02) reads compat.cjs's real export list and fails, with `file:line name`, on any compat reference in tracked source that names no current export, on any of the five exports objective 78 removed coming back, and on a tracked path under the pre-rename planning directory: git merges text, not imports, so a reconcile with `main` cannot reintroduce a removed shim silently. `rename-guard.repo.test.cjs` (above), `doc-refs.repo.test.cjs` (stale command references), `dispatch-completeness.test.cjs` (every command named in CLAUDE.md dispatches), `hook-inventory.test.cjs` (CLAUDE.md's hook list equals the registrations) and `context-budget.repo.test.cjs` (CLAUDE.md at most 200 lines and 20,000 characters, each skill's resolved footprint, each agent body) keep the resident docs true.
- **Built-in sweep** (Unreleased) — `builtin-sweep.repo.test.cjs` fails CI on a discrete-choice prose prompt outside AskUserQuestion, an AskUserQuestion schema break, missing TaskCreate/TaskUpdate progress in micro/quick/build/debug/plan-objective/verify-work, a missing plan-mode draft review in plan-objective/new-project/milestone complete, or an undeclared built-in (ExitPlanMode is never pre-approved). Inventory: `docs/built-in-sweep.md`; rules: `references/built-ins.md`.

Model profiles are loaded from `plugins/aoforge/aoforge/references/model-profiles.json` (via `bin/lib/helpers.cjs`), which maps each agent to its opus/sonnet/haiku assignment per profile tier. The JSON also pins the concrete model id for each tier — keep those ids current when models ship; a stale id resolves to a model that never runs. Doctor check 13 and `validate health` W063 flag a pin that `references/model-rates.json` shows superseded.
