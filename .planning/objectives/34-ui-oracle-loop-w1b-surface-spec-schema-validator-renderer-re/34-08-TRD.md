# TRD 34-08: `frontend-design` build mode step 0 — no composition without a valid, locked spec

<objective>
Put Phase A on the composition path. `eden-flutter:frontend-design` build mode gains a **step 0**
that locates or drafts the Surface Spec, validates it, and stops for look-lock — and **refuses to
compose** against a spec that does not validate or whose lock is cleared.

The plan calls this row "prose". It ships with executable contract tests anyway: proposal §21
amendment 1 makes an executable check mandatory for agent prose that encodes runtime semantics,
and "this command exists" is exactly such a claim.

Resolved intent: kind=plugin, work=feature, tdd=strict (CLAUDE.md user playbook),
depth=comprehensive, test_list_first=required, fixture_strategy=generators.
Constraints honored: `no_llm_test_data`, `no_property_based_default`, `no_gherkin_layer`.
</objective>

rules with the reason attached (the house style in this file):

- A control's semantics identifier **is** its Surface Spec control id. `eden-nav-<id>` style
  prefixes are part of the id, not decoration — the probe finds controls by identifier, and a
  mismatch reads as `present` failing, i.e. "the control does not exist".
- **Exactly one tap action per identified control.** The `ExcludeSemantics` outside +
  `Semantics(onTap:)` inside combination declares two, and the result fires twice per activation.
  This is a real defect class from the nav work; `must_not: ["fire twice per activation"]` in a
  spec is the assertion, and this is the composition rule that avoids it.
- **Sibling control hit rects are disjoint.** A chevron rendered inside a header row that takes
  the row's rect swallows the header's hit target. Where two controls genuinely nest, the spec
  declares `hit_rect.disjoint_from` and the probe asserts it.
- **Read a `SemanticsNode.rect` from the node itself**, walked through its `transform` — not from
  the parent. A nested `Semantics` without `container: true` reports the parent's rect, which
  makes two controls look coincident when they are not.
