## Runtime model

Binding for this TRD (OBJECTIVE.md; proposal §21 amendment 2). Trace every command under it.

- **Mirror, not checkout.** Skills invoke `node ~/.claude/devflow/bin/df-tools.cjs` — the MIRROR
  at `~/.claude/devflow`, copied from `plugins/devflow/devflow/` by the `sync-runtime` hook when
  the bundled version differs from the cached `.plugin-version`. **This release is what makes
  everything in objective 34 reachable from a skill**: until 2.9.0 is installed and a new session
  starts, `ui spec`, `ui sheet` and `ui lock` exist only in this checkout. Say so in the release
  notes — W1★ will hit it.

  command per call under the worktree guard. Every path below is absolute or repo-root-relative

  unreachable (`PAT000` MISSING on every real spec until W1a ships a pinned release), and the

<codebase_examples>
**The changelog generator** — `df-tools changelog update --version vX.Y.Z [--from <ref> --to <ref>] [--dry-run]`
(`bin/lib/changelog.cjs`, shipped 1.30+). It generates Keep-a-Changelog entries from

an explanation.

**The house entry style** — `CHANGELOG.md`'s 2.8.0 section. Each bullet is bold-led, explains the
defect or the capability in a sentence or two of plain English, and ends with the commit
short-shas in parentheses. It says what was WRONG, not only what changed:

Match it. Ten terse bullets in that style beat one paragraph.

**The release workflow** — `.github/workflows/release.yml` fires on `push` of a `v*` tag and
titles the release from the ANNOTATED tag's subject (re-fetching the tag object, per the 2.7.1
fix). So `git tag -a v2.9.0 -m "<the release title>"` — the `-m` text becomes the GitHub release
title. Write it deliberately.
</codebase_examples>

<gotchas>
- **`marketplace.json` has six `version` fields.** Only two move: the marketplace's own (line 4)
  and the `devflow` plugin entry's (line 14). The other four belong to sibling plugins
  (`eden-ui-flutter`, `eden-ui-web`, `monorepo-standards`, `aosentry-mcp`,
  `social-media-generator`) and must not be touched. A blanket `sed 's/2.8.0/2.9.0/'` happens to
  be safe today only because none of them read 2.8.0 — do not rely on that.
- **Tag the release commit.** The gate reads the tagged commit's tree. Tagging `HEAD~1` reads the
  old CHANGELOG and is denied, correctly.
- **Do not use the escape hatch.** `DEVFLOW_SKIP_CHANGELOG_GATE=1` exists for emergencies. Using
  it here would mean the release is going out with an unverified changelog, which is the one thing
  this gate is for.
- **The baseline must be UNCHANGED, not "green".** A release that reports 2974 passing and 0
  failing means someone fixed nine unrelated tests inside a release, or the suite did not run.
  Both are findings. Report the number and the three file names.
- **The pattern catalogue is unreachable in W1b.** Every real spec will carry `PAT000 / MISSING`
  until W1a ships a pinned `eden-ui-flutter` release. That is correct behaviour, and it will look
  like a bug to the first person who runs `ui spec validate` on a real surface. Put it in the
  release notes.
- **Merge runbook applies.** `~/.claude/CLAUDE.md`'s three stages — mechanical preflight,
  composition review (ownership transfer, last writer), approval — run before merging to `main`,
  and `/code-review <PR> high` is mandatory after the final branch review. Wave 0 found eight
  findings that way, after clean SDD reviews.
</gotchas>

<anti_patterns>
- **Do NOT ship a generated changelog unedited.** The generator lists commits; a reader needs to
  know what changed for them.
- **Do NOT bump a sibling plugin's version** in `marketplace.json`.
- **Do NOT fix code inside the release.** A failing release check routes back to the owning TRD.
- **Do NOT claim W1b closes the loop.** It ships the spec, the validator, the renderer, the sheet,
  the lock, the skill gate and the prose harness. The probe, the checks and the executor CONFORM
  loop are W2; the dogfood is W1★.
- **Do NOT skip the interface-list check.** Three downstream objectives are planned against those
  exact names.
</anti_patterns>

<error_recovery>
- If the tag gate denies, read its message — it names the commit it resolved and the four file
  versions it found there. The usual cause is tagging the wrong commit.
- If the `npm test` fail count is not 9, run the three known files individually to see whether the
  delta is in them or elsewhere, and bisect from the objective's first commit. Do not tag until it
  is explained.
- If the interface probe fails because a function lives in a sibling module, add a re-export to
  `ui-spec.cjs` with a comment naming the W1b interface list — that is a legitimate, additive
  release-time fix with its own commit.
</error_recovery>
