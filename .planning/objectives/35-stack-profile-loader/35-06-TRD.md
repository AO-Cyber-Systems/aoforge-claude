# TRD 35-06: Planner and executor read the stack profile

<objective>
Replace prose-scraped gates and hard-coded loops with profile-driven ones. The planner fills
`<validation_gates>` from `stack command`; the executor runs the profile's `loop` and
`gates.task`, protects generated files, and proposes discovered commands in SUMMARY.

This TRD is prose (`type: standard` — the OBJECTIVE's "execute" type; TRD types are
standard/tdd/ui). Verification is rg/grep on exact new wording and absence of removed wording,
plus the existing agent-prose test suites.
</objective>

## Runtime model (binding, from OBJECTIVE.md)

- Agents invoke the MIRROR `node ~/.claude/devflow/bin/df-tools.cjs`. Until the mirror carries
  this release, `stack` exits 1 with an unknown-command error — **every new instruction must say
  what to do then: fall back to today's behaviour.**
- With no STACK.md, the resolved profile is `general`: every command is `discover`, so the
  executor/planner behave as today (Principle 1 discovery).
- `run: discover` that can't be found, or a command that fails to launch → `not_available`, never PASS. `run: none` → skipped.
- **Out of scope:** the Flutter sections (`## Flutter UI bootstrap detector`, `## Flutter UI per-task verification`, `## Flutter UI post-all-tasks verification` in executor.md; the Flutter UI scope sub-procedure in planner.md). Do not edit them.
- One plain command per Bash call. 1Password signing failure → STOP and report.

executor.md — new section right after execute_tasks item 3 (before `## Flutter UI per-task verification`):
```markdown
## Stack loop, task gates and generated files

**Generated-file guard (before every edit).** If the target path matches a `generated.globs` pattern, or any of its first 5 lines matches a `generated.markers` regex, do NOT edit it. Edit its source, then run `node ~/.claude/devflow/bin/df-tools.cjs stack command <generated.regenerate> --raw` and execute the printed command. Record this as a deviation if the TRD asked for a direct edit.

**Inner loop (after each edit).** For each key in `loop`, in order: `node ~/.claude/devflow/bin/df-tools.cjs stack command <key> --files <changed files, comma-separated> --raw` and run the printed command. Empty output means `discover` (find the command per general Principle 1; if you can't, record `not_available`) or `none` (skip). Fix failures before moving on.

**Task gates (before each commit).** Same procedure for each key in `gates.task`; results go in the SUMMARY "Validation Gate Results" table. A gate you could not run is `not_available`, never PASS.

**Discovered commands.** Any command you discovered (because the profile said `discover`) goes in the SUMMARY `## Discovered commands` section. Never write `.planning/STACK.md` yourself — the user reviews the proposals in SUMMARY and adopts them.
```
