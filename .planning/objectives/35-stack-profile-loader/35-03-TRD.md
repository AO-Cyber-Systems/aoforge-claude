## Runtime model (binding, from OBJECTIVE.md)

- Skills/agents invoke the MIRROR `~/.claude/devflow/bin/df-tools.cjs`. **Tests run the checkout's
  `plugins/devflow/devflow/bin/df-tools.cjs`** via `execFileSync('node', [TOOLS_PATH, ...])` with
  `env: {...process.env, HOME: fakeHome}` and `cwd: project` — `os.homedir()` honours `HOME`, so the
  CLI reads the fake org tier. **Never read the real `~/.claude` in a test.**
- CommonJS, synchronous fs, no new npm dependencies. Neutral lib code.
- One plain command per Bash call. 1Password signing failure → STOP and report; never disable signing.

## Validation codes (stable — 35-05 maps them)

| Code | Severity | Rule |
|---|---|---|
| STK001 | error | schema violation (json-schema-lite) — `path` + `msg` + `file` |
| STK002 | error | `extends` does not resolve (from resolve issue `EXTENDS_UNRESOLVED`) |
| STK003 | error | extends cycle (`EXTENDS_CYCLE`) |
| STK004 | error | extends chain deeper than 4 (`EXTENDS_DEPTH`) |
| STK005 | error | `loop`, `gates.task`, `gates.objective`, `generated.regenerate` or `verification.runtime_check` names a key absent from the RESOLVED `commands` |
| STK006 | error | an H2 section name outside `SECTION_NAMES` |
| STK007 | warning | profile body over 150 lines |
| STK008 | error | parse failure (StackProfileError / YamlLiteError) |
| STK009 | error | a `components[].profile` file/id that cannot be found (`COMPONENT_MISSING`) |

```js
validateProfileText(text, { projectRoot, userHome, file }) → { ok, target, errors: [{code, path, msg, file}], warnings: [...] }
validateProfile({ projectRoot, userHome, profilePath = null }) → same shape
// default target: <projectRoot>/.planning/STACK.md; absent → validates bundled general, target 'general (bundled; no .planning/STACK.md)', ok true
```
Schema check runs on EACH file's own frontmatter in the chain (errors carry that file); cross-field
rules run on the resolved profile. `ok === errors.length === 0`.

## CLI surface

```
df-tools stack resolve [--file <repo-path>] [--provenance] [--raw]
    JSON {id, chain, component, frontmatter, sections:[names], issues[, provenance]}; --raw → id
df-tools stack context <agent> [--files a,b] [--budget N] [--ui] [--raw]
    JSON = contextFor result; --raw → text
df-tools stack validate [--profile <path>] [--raw]
    JSON {ok, target, errors, warnings}; exit 1 when !ok; --raw → 'ok' | 'invalid'
df-tools stack command <key> [--files a,b] [--packages a,b] [--apply] [--raw]
    JSON = renderCommand result; --raw → the command, or empty output for discover/none;
    exit 1 for status 'undefined'
```
`--files`/`--packages` are comma-separated single argv tokens. `--file` (resolve/context/command)
selects the component. Unknown/missing subcommand → `error('Unknown stack subcommand. Available: resolve, context, validate, command')`
(35-04 appends `init`). Use `output(result, raw, rawValue, exitCode)` and `error()` from helpers.cjs.
