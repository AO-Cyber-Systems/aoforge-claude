# TRD 35-04: Drafting — `df-tools stack init`

<objective>
Implement `stack init [--from codebase|research] [--extends <id>] [--write] [--force]`: pick
`extends` from installed org profiles' `detect`, lift commands from repo evidence, preview by
default, write only on `--write`. Give map-codebase's `codebase/STACK.md` a Commands section as
evidence, and wire a human-confirmed draft step into map-codebase and new-project.

Resolved intent: kind=plugin, work=feature, tdd=strict (Tasks 1–2), test_list_first=required,
fixture_strategy=generators. Task 3 is prose (grep-verified). Constraints honored:
`no_llm_test_data`, `no_property_based_default`, `no_gherkin_layer`.
</objective>

## Runtime model (binding, from OBJECTIVE.md)

- Workflows invoke the MIRROR `node ~/.claude/devflow/bin/df-tools.cjs`. Until the mirror carries
  this release, `stack` is an unknown command there — the workflow steps must skip gracefully.
- Tests run the checkout's df-tools with `HOME` = mkdtemp fake home. Never read the real `~/.claude`.
- CommonJS, sync fs, no new npm dependencies.
- **Neutrality:** stack-profile.cjs stays stack-free (35-02a's P11 test keeps running). The
  evidence readers live in `stack-evidence.cjs`; they read file FORMATS (GitHub workflow, Makefile,
  justfile, package.json). The only tool name they may emit is the runner implied by the file
  (`make`, `just`, `npm`) — no language/framework names.
- One plain command per Bash call. 1Password signing failure → STOP and report; never disable signing.

## Design (locked here)

```js
// stack-evidence.cjs
STANDARD_KEYS = ['build','test','lint','format','fix','typecheck','audit','codegen','deps']
classifyCommand(cmd, hint) → key|null
  // hint (target/script/recipe name) first, then command tokens. Token map:
  // test:/\btests?\b/  lint:/\blint\b/  format:/\b(fmt|format)\b/  build:/\bbuild\b/
  // typecheck:/\btype-?check\b/  audit:/\baudit\b/  codegen:/\b(generate|codegen)\b/  fix:/\bfix\b/
collectEvidence(projectRoot, { from = 'codebase' }) → [{ key, command, source }]
  // priority (first per key wins; all kept for display):
  // 1 explicit table: .planning/<codebase|research>/STACK.md `## Commands` rows `| key | `cmd` | … |`
  // 2 CI: .github/workflows/*.yml|*.yaml — `run: <cmd>` lines and the indented lines of `run: |` blocks (line-based; NOT yaml-lite)
  // 3 Makefile targets `^([A-Za-z0-9_.-]+):(?!=)` except .PHONY/.DEFAULT → `make <t>`
  // 4 justfile/Justfile recipes → `just <r>`
  // 5 package.json scripts → `npm test` for "test", else `npm run <name>`; malformed JSON → skipped
  // 6 .planning/codebase/TESTING.md (from=codebase) — lines inside ```bash/```sh/``` fences
// stack-profile.cjs
listOrgProfiles({ userHome }) → [{ id, extends, detect: [], languages: [], path }]   // [] when userHome null or dir absent
pickExtends({ projectRoot, userHome, explicit }) → { id, reason, alternatives: [] }
  // marker match: literal filename at projectRoot, or `*.ext` against root entries
  // among matches, drop any id that is an ancestor (via extends) of another match; tie → alphabetical, rest → alternatives; none → 'general'
draftProfile({ projectRoot, userHome, from, extendsId }) → { frontmatter, body, evidence, extends }
  // id = basename(projectRoot) lowercased, [^a-z0-9.-] → '-', leading non-alnum stripped
  // commands: evidence keys whose parent-resolved command is discover or absent → { run }
  // provenance: { reviewed: today YYYY-MM-DD, sources: [] }; body = '# Stack Profile: <id>\n\n<!-- guidance comment, NO H2 -->\n'
serializeProfile(frontmatter, body) → text   // '---' fences, JSON-quoted strings, flow maps for commands, flow lists; round-trips through parseProfile
initProfile({ projectRoot, userHome, from, extendsId, write, force }) →
  { action: 'preview'|'written'|'refused', path, text, extends, evidence, validation }
```
CLI: `stack init [--from codebase|research] [--extends <id>] [--write] [--force] [--raw]` — JSON
result; `--raw` prints `text`; `refused` → exit 1 (`error` naming `--force`); draft failing
`validateProfileText` → print it with `validation` and exit 1 without writing.

## Regression gate (baseline-relative)

Test counts depend on the environment. The 1Password signing hang only happens where
`op-ssh-sign` is reachable: a sandbox saw 3417 pass / 1 fail, while the user's machine sees 10
failures. So this gate compares failing test **names** against
`.planning/objectives/35-stack-profile-loader/baseline-failures.tsv`, not counts. That file
has one line per failure: `file:line<TAB>name`, from a real run of this exact command.

1. From the repo root, run
   `node --test --test-reporter=spec 'plugins/devflow/**/!(micro).test.cjs' 'plugins/devflow/**/*.test.js' 'scripts/**/*.test.cjs'`
   and write its output to a file in your session scratchpad (never the repo).
2. Extract the failing test names from the spec reporter's closing `✖ failing tests:` section.
   Each entry gives `test at <file>:<line>:<col>` and then `✖ <name> (<ms>)`; strip the duration.
3. A failure whose name appears in the TSV's second column is **pre-existing**, whether it passes
   or fails in your run.
4. A failure whose name is **not** in the TSV is a candidate regression:
   - Re-run just its file with `node --test <file>`.
   - If it passes on re-run, record it as an environment flake with the evidence.
   - If it still fails, check whether this TRD's changes (`git diff --stat` against your wave base)
     touched code that test exercises.
     - If they did, it is a **regression and blocks**. Fix it before completing.
     - If they plainly didn't (e.g. a PTY or handoff timing test), record it in SUMMARY as an
       **environment flake**, with the file, the name, the re-run output and why it's unrelated.
       Don't block.
5. **Never edit `baseline-failures.tsv`** to make the gate pass.

In SUMMARY, record the observed pass/fail totals (for information only) and every failure with its
classification: pre-existing, environment flake, or regression.
