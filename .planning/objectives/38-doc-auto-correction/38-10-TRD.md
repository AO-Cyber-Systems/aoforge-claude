# TRD 38-10: Health Check 14 and `df-tools validate docs`

<objective>
Put the doc-staleness advisories where users already look (`/devflow:status check` →
`validate health`), and add a cheap, read-only `validate docs` for the default `/devflow:status` view.
Full health does a best-effort `git fetch` in Check 11, which is too slow for every status call.

Resolved intent: kind=plugin, work=feature, tdd=strict, test_list_first=required,
fixture_strategy=generators. Constraints honored: `no_llm_test_data`, `no_property_based_default`,
`no_gherkin_layer`.
</objective>

## Runtime model (binding)

- CommonJS, sync, no new dependencies. Health tests use the existing `runHealth` helper and a fake `homeDir` (see `validate.test.cjs:48-120, 533`). CLI tests spawn `node plugins/devflow/devflow/bin/df-tools.cjs --cwd <fixture> validate docs` with `HOME=<fake>`.
- Fixture repos come from `adopt-fixtures.makeFixture` + `makeFakeHome` (real git, local config, gpgsign off). Never touch this repo's git or a real repo.
- Commit via `node ~/.claude/devflow/bin/df-tools.cjs commit "<msg>" --files <paths>`. If signing fails, STOP; never bypass. One plain command per Bash call. Never use port 8080. No version bump, tag or push.

## Test list

`validate.test.cjs`, in a new `describe('Check 14: documentation staleness', …)`:
1. A fixture with STACK.md `reviewed: "2025-01-01"` → the health warnings include W051 with `repairable === false`.
2. A Go fixture with `languages: [python]` → W052.
3. A fixture with committed maps and a threshold of 2 exceeded (via `.planning/config.json` `docs.codebase_map_stale_commits: 2`) → W053.
4. STATE.md naming `/devflow:update` → W050.
5. A clean fixture (fresh STACK.md, matching languages, no maps) → no W05x.
6. Force a throw (`doc-staleness._setRunGit` cannot make collect throw, so stub `require.cache` for `./doc-staleness.cjs` with a module whose `collect` throws, and restore it in `after`) → exactly one W054.
7. `--repair` on the fixture with W051 + W053 → STACK.md and `.planning/codebase/*` byte-identical, and no repair action mentions W05x.

CLI (same file, spawned):
8. `validate docs` on the case-1 fixture → exit 0, and the JSON `issues[0].code === 'W051'`.
9. `validate docs --raw` on the clean fixture → stdout `no documentation advisories`.
10. `validate docs` in a mkdtemp dir with no `.planning/` → exit 0, `note: 'no .planning/'`.
11. `validate bogus` → non-zero exit, and stderr names `consistency, health, docs`.

`help.test.cjs` (existing):
12. It passes unchanged, since the `validate` entry already exists and only its usage text changes.
