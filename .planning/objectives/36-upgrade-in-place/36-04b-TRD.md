# TRD 36-04b: Migrations 0004 (objective backfill) and 0006 (kind/work, confirm)

<objective>
Two registry migrations that wrap code that already exists:

| Id | Safety | Detects | Does |
|---|---|---|---|
| 0004 objective-md-backfill | auto | NN-named objective dirs with no OBJECTIVE.md | creates them via the revived `backfillAllObjectives` |
| 0006 kind-work | confirm | PROJECT.md without `kind` | runs the existing kind/work migration with a human-chosen kind |

`backfillAllObjectives` (project-bootstrap.cjs:194) has been dead code since TRD 18-01. `migrate.cjs`
works, but it needs `--kind`, and it backs up inside the repo, which this objective removes for the
upgrade path.

Resolved intent: kind=plugin, work=feature, tdd=strict, test_list_first=required,
fixture_strategy=generators (36-01's `upgrade-fixtures.cjs`, read-only).
Constraints: `no_llm_test_data`, `no_property_based_default`, `no_gherkin_layer`.
</objective>

## Runtime model (binding, from OBJECTIVE.md)

- CommonJS, sync fs, no new deps. Migrations export `{ id, title, since: '2.11.0', safety, detect, apply }`.
- mkdtemp projects only; the real `~/.claude` is never touched.
- Commits via `df-tools commit --files`. 1Password failure → STOP and report. Never bypass signing.
- One plain command per Bash call. Never port 8080.
- Commits: `test(36-04b): ...` → `feat(36-04b): ...`.

const migrate = require('../migrate.cjs');
module.exports = {
  id: '0006', title: 'Set PROJECT.md kind (and default work) for the intent model', since: '2.11.0', safety: 'confirm',
  detect(ctx) { const p = migrate.plan({ projectRoot: ctx.projectRoot }); /* errors → {applies:false} */ return { applies: !!p.project && p.project.needsKind, reason: '...' }; },
