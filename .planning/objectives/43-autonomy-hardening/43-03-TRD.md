# TRD 43-03: Gates stop blocking DevFlow's own agents and merge completions

<objective>
DevFlow's gates block its own work (43-EVIDENCE §2.1):

- **DF-03, 114 denials.** The edit gate denies DevFlow's own agents because it only looks for a
  `.skill-active` marker and never at the payload's agent identity.
- **DF-02(b), 32 cases.** The commit gate refuses merge/rebase completions (`git commit --no-edit`
  after merging agent branches), which `df-tools commit` can't do.
- **DF-02(c), 23 cases.** The commit gate's own error text suggests an `export` escape that
  cannot work: the hook decides before the command runs and never sees the command's environment.

Fix all three with TDD.
</objective>

## Binding rules

- Strict TDD per task: a RED commit (the failing test) comes first, then GREEN. Use the repo's
  commit route: `node plugins/devflow/devflow/bin/df-tools.cjs commit "<msg>" --files <paths>`.
- Fixtures are hand-built by the builders in `hooks/__fixtures__/gate-fixtures.js` (Task 1). No
  generated data. Git state is simulated by creating the marker files/dirs inside a hand-made
  `.git` dir (and a `.git` FILE with `gitdir:` for the worktree case). There is no need to run
  real merges.
- Hooks stay dependency-free and cheap: no `git` spawn in gate-commits; resolve the git dir with
  fs only, like `gate-edits.sharedPlanningDir`.
- Fail open on any error (exit 0, no output). Hook I/O is JSON on stdin.
- Don't rename or change the signatures of gate-edits exports `hasSkillActiveMarker`,
  `findPlanningDir` and `sharedPlanningDir`; 43-05 imports them.
- Per task: `node --test plugins/devflow/hooks/gate-edits.test.js plugins/devflow/hooks/gate-commits.test.js`.
- Never port 8080. No version bump, tag or push. One plain command per Bash call.

<anti_patterns>
- Allowing on `agent_id` presence alone. Only the `devflow:` agent_type prefix is trusted.
- A substring test for the inline prefix, e.g. `/DEVFLOW_ALLOW_RAW_COMMIT=1/.test(cmd)`. That
  accepts `export ...=1; git commit` and `echo DEVFLOW_ALLOW_RAW_COMMIT=1 && git commit`. The
  assignment must sit in the SAME simple command, directly before `git` (only other `NAME=value`
  assignments or a leading `env` may sit between).
- Allowing only one of several commit invocations to carry the prefix. EVERY invocation needs it.
- Spawning `git rev-parse --git-dir` in the hook (hot path; keep fs-only).
- Mentioning `export` anywhere in the new deny text. The test asserts `!/\bexport\b/`.
</anti_patterns>
