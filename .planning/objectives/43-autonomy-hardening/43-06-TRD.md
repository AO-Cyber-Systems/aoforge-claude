# TRD 43-06: Migration 0008 untracks DevFlow runtime state files

<objective>
`guard-no-progress.js` writes `.planning/.progress-guard.json` on every tool call. That file and
`.awareness-cache.json` are git-tracked in aodex, eden-biz, aocore and opsCluster, so they show
as modified in 791 transcripts and trip dirty-tree refusals (43-EVIDENCE DF-10). Migration 0008
gitignores them and untracks them.

Two traps make a naive migration fail silently, and this TRD closes both:

1. **Pathspec commit re-adds the file.** `df-tools commit` commits with a pathspec
   (`git commit -m msg -- <paths>`). For an `--only` pathspec commit, git re-stages each listed
   path from the WORKING TREE. A file that was just `git rm --cached` but still exists on disk
   would be re-tracked.
2. **The upgrade hook would never commit.** upgrade-project.js skips its auto-commit when any
   changed file was dirty before the upgrade, and the guard file is essentially always dirty.
</objective>

<anti_patterns>
- Deleting the working copies. The files are live state for running hooks; untrack only.
- String-matching `.gitignore` lines to decide "already ignored". Use
  `git check-ignore --no-index`, so a `.planning/` or glob rule counts (the 42-14 D5 lesson).
- Letting cmdCommit fall back to a bare whole-index `git commit` when unrelated paths are staged.
  That sweeps in other executors' work (issue #87). Refuse with a clear reason instead.
- Making 0008 apply to every git fixture (e.g. "`.gitignore` lacks the entries"). That changes
  `changed_files` in dozens of unrelated upgrade/adopt tests. Apply only when a file is tracked
  or present-and-unignored.
</anti_patterns>

<error_recovery>
- Not a git work tree (`git rev-parse --is-inside-work-tree` fails): detect → `{applies:false, reason:'not a git work tree'}`.
- If an existing upgrade/adopt test changes because its fixture happens to contain one of the
  files, fix the fixture expectation and justify it in SUMMARY. Don't weaken 0008's detect rule.
</error_recovery>

## Test list

Outermost (the hook) to innermost.

1. (hook e2e, upgrade-project.test.js) A stamped-behind git fixture where
   `.planning/.progress-guard.json` is tracked AND modified before the hook runs → the hook
   applies 0008 and its detached commit lands. HEAD's tree no longer contains the file, the file
   still exists on disk, and `git status --porcelain` does not list it.
2. (commit, commit-staged-removal.test.cjs) Git fixture: the file is tracked; 0008 apply has run
   (the file is ignored and `rm --cached`); `df-tools commit "chore: x" --files .gitignore .planning/.progress-guard.json`
   → `committed:true`. `git ls-tree -r HEAD --name-only` lacks the file; the working file exists;
   `.gitignore` is committed.
3. (commit) The same, plus an unrelated staged file `src/other.js` → exit 1, reason
   `staged_removal_with_foreign_index`, HEAD unchanged, `src/other.js` still staged.
4. (commit, regression) A normal pathspec commit of modified tracked files behaves exactly as
   before. The existing commit-failure.test.cjs suite stays green.
5. (migration) detect:
   - tracked guard file → applies;
   - an untracked, unignored awareness cache on disk → applies;
   - both absent → not;
   - both ignored and untracked → not;
   - non-git dir → not;
   - dryRun apply writes nothing.
6. (migration) apply:
   - `.gitignore` absent → created with the comment and both entries;
   - `.gitignore` with `.planning/` → no entries added, but the tracked file is still `rm --cached`;
   - a `.gitignore` with only one entry → only the missing one is appended;
   - changed = ['.gitignore', <untracked paths>] (omit `.gitignore` when it didn't change).
7. (migration) Idempotency: apply → detect → applies:false; a second apply leaves `.gitignore`
   byte-identical and changed = [].
8. (runner) 0008 is present in the registry in id order, and passes contract validation
   (upgrade.test.cjs's registry test).
