# TRD 43-04: SubagentStop completion gate for devflow:executor

<objective>
Add a SubagentStop hook that gives a `devflow:executor` which stops naturally, with no
SUMMARY.md for its TRD, exactly one more turn to finish or checkpoint. Verified harness facts:

- SubagentStop `decision:block` on a natural stop makes the subagent continue, with `reason` as
  its next instruction.
- The re-stop carries `stop_hook_active: true`.
- A `maxTurns` stop does not fire SubagentStop at all (43-01 handles that path).

Registration in hooks.json happens in 43-09 (hooks.json is a shared hot spot).
</objective>

## Binding rules

- Strict TDD: fixture builders (Task 1), then RED commits before GREEN. Commit via
  `node plugins/devflow/devflow/bin/df-tools.cjs commit "<msg>" --files <paths>`.
- Hand-built fixtures only: invented plan ids like `77-02` and invented paths. Don't copy real
  transcripts.
- The block output is TOP-LEVEL `{"decision":"block","reason":"..."}`. That is the verified
  shape. Do NOT copy verify-commits.js's `hookSpecificOutput`-nested form.
- Every I/O dependency is injectable for unit tests: `readFile`, `exists`, `glob`/`readdir`, and
  `gitWorktrees(repoRoot) -> [paths]`. `main()` wires the real ones.
- Bounded transcript read: at most the first 1 MiB (fs.openSync + readSync). Parse only complete
  JSONL lines and stop at the first `type:'user'` record.
- Don't edit hooks.json, verify-commits.js or any other hook.
- Per task: `node --test plugins/devflow/hooks/gate-executor-stop.test.js`.
- Never port 8080. No version bump, tag or push. One plain command per Bash call.

<anti_patterns>
- Blocking when `stop_hook_active` is true. That could loop the agent forever.
- Keeping a marker/counter file for "block once". `stop_hook_active` is the verified once-guard,
  and a file would dirty `.planning/` (the exact problem AUT-05 fixes).
- Scanning the whole transcript for plan ids. Later tool output mentions other TRDs, so only the
  first user prompt is authoritative.
- Picking the "first match" when the chosen source names two different ids. Ambiguous means
  fail open.
- Requiring `## Self-Check` in the SUMMARY. The requirement is only "has no SUMMARY.md"; a
  `## Progress`-only checkpoint counts as present. INCOMPLETE handling of checkpoints is 43-01's job.
</anti_patterns>

<error_recovery>
- `git worktree list` fails, or git is absent: skip the worktree roots and still check the others.
- A glob over `.planning/objectives/*/` fails on an unreadable dir: skip that root.
</error_recovery>

   (unit-level), or in the dir named by REPO_ROOT when payload.cwd is elsewhere (e2e) → no block.
6. (e2e) No `.planning/` anywhere up from cwd → no output. `DEVFLOW_SKIP_EXECUTOR_STOP_GATE=1` → no output.
7. (e2e) `agent_transcript_path` missing, nonexistent, or containing garbage lines → no output (fail open).
8. (e2e) `last_assistant_message` starting with `## CHECKPOINT REACHED`, or containing `WRONG REPOSITORY` → no output.
9. (unit) identifyTrd:
   - `PLAN_ID: 77-02` → `77-02`
   - `--id 77-02` only → `77-02`
   - `.planning/objectives/77-x/77-02-TRD.md` only → `77-02`
   - decimal objectives: `PLAN_ID: 12.1-03` → `12.1-03`
   - frontmatter-only `objective: 77-foo` + `trd: "02"` → `77-02`
   - `PLAN_ID: 77-02` plus a `--id 77-03` → ambiguous → null
   - nothing → null
10. (unit) readFirstUserPrompt returns the first user record's text:
    - string content and array content both work;

    - a 2 MiB file whose first user line lies within the first 1 MiB works, and reads no more than 1 MiB (spy on readSync bytes).
11. (unit) summaryExists over injected roots (true/false). A root without `.planning/objectives` is skipped.
