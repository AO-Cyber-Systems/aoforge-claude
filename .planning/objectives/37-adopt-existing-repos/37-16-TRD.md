# TRD 37-16: Human check — install from this checkout, `/devflow:adopt` in a fresh session (E2E proof b)

<objective>
The last proof is a real session, which only the user can run: the plugin installed from this
checkout, a fresh Claude Code session opened in a scratch fixture, `/devflow:adopt` typed by hand.
Build the fixture, hand the user exact steps and a checklist, record their verdict, and leave the
post-completion ROADMAP/STATE check for the orchestrator.

Not autonomous: Task 2 is a `checkpoint:human-verify`. It changes the user's plugin configuration,
reversibly, and the user performs every such step.
</objective>

## Runtime model (binding, from OBJECTIVE.md)

- **Never touch any real user repository.** The fixtures are factory-built under a fresh mkdtemp dir.
- The executor never runs `/plugin` commands, never edits `~/.claude`, never deletes
  `.plugin-version`; it only prints the steps. The user's own session writes the real
  `~/.claude/devflow/backups/<fixture-key>/` and `.registry.json` entry — expected, and covered by
  the cleanup step.
- Commits via `node ~/.claude/devflow/bin/df-tools.cjs commit "<msg>" --files <paths>`; signing
  failure → STOP and report. One plain command per Bash call. Never port 8080. No version bump, tag
  or push.

## Regression gate (baseline-relative)

This TRD changes no code (fixtures live outside the repo; only a SUMMARY is committed). The gate was
run as the final automated gate by 37-15; SUMMARY cites that run. If any fix lands as a result of the
human check, run the gate below before completing.

Test counts depend on the environment (1Password signing only hangs while 1Password is locked; the
daemon/PID tests fail in any git worktree). So this gate compares failing test **names** against
`.planning/objectives/37-adopt-existing-repos/baseline-failures.tsv` (21 lines, `file:line<TAB>name`),
not counts.

1. From the repo root, run
   `node --test --test-reporter=spec 'plugins/devflow/**/!(micro).test.cjs' 'plugins/devflow/**/*.test.js' 'scripts/**/*.test.cjs'`
   and write the output to a file in your session scratchpad (never the repo).
2. Extract failing names from the closing `✖ failing tests:` section: each entry gives
   `test at <file>:<line>:<col>` then `✖ <name> (<ms>)`; strip the duration.
3. A failure whose name is in the TSV's second column is **pre-existing**.
4. Any other failure is a candidate regression. Re-run just its file with `node --test <file>`.
   - Passes on re-run → **environment flake**, record the evidence.
   - Still fails and this TRD's diff (`git diff --stat <wave base>`) touched code it exercises →
     **regression, blocks**. Fix it before completing.
   - Still fails and plainly unrelated (PTY/handoff timing) → **environment flake**; record file,
     name, re-run output and why it's unrelated. Don't block.
5. **Never edit `baseline-failures.tsv`** to pass the gate. Tests added by this objective are not in
   the TSV and must pass.
