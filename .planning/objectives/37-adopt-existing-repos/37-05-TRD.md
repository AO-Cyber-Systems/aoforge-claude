# TRD 37-05: `adopt preflight` and `adopt begin` — route, refuse, branch, resume

<objective>
The deterministic front door of `/devflow:adopt`. `preflight` answers "what should adopt do here?"
without writing anything; `begin` creates the `devflow/adopt` branch and an out-of-tree progress
marker so a half-finished adopt can resume. Every refusal (LOCKED: refuse, don't guess) leaves the
repo exactly as it was — no stash, no reset, no branch.

Resolved intent: kind=plugin, work=feature, tdd=strict, test_list_first=required,
fixture_strategy=generators (`adopt-fixtures.cjs`, import only). Constraints honored:
`no_llm_test_data`, `no_property_based_default`, `no_gherkin_layer`.
</objective>

## Runtime model (binding, from OBJECTIVE.md)

- CommonJS `.cjs`, synchronous fs, **no new npm dependencies**. git via `execFileSync('git', ['-C',
  root, ...], {env})`; adopt.cjs takes `env` (default `process.env`) so tests pass `gitEnv(home)`.
- `userHome` is injected into adopt.cjs; only adopt-cli.cjs calls `os.homedir()`. Spawned tests set
  `HOME=<fake home>`. **Nothing may read or write the real `~/.claude`.**
- **Never touch any real user repository.** Fixtures under mkdtemp only. Fixture git config is local
  (`commit.gpgsign=false`), set by the factory.
- Commits via `node ~/.claude/devflow/bin/df-tools.cjs commit "<msg>" --files <paths>`; signing
  failure → STOP and report; never bypass. One plain command per Bash call. Never port 8080. No
  version bump, tag or push.
- Commits: `test(37-05): ...` → `feat(37-05): ...`.

<gotchas>
- Untracked files count as dirty (a new untracked file could collide with what adopt writes, and
  "leave the tree unchanged" includes not burying the user's untracked work in a branch switch).
  Ignored files do not count.
- `git switch -c` carries untracked files; begin only runs on a clean tree, so there are none.
- Porcelain paths are relative to the top level; with `-z`, a rename record is `R  new\0old\0`.
- The `.planning/` owned-path check must treat `.planning` itself and anything under it; do not
  count `.planning-other/`.
- Marker read failures (bad JSON) → treat as no marker AND add a `warnings` entry; never delete it.
- Hooks and the edit gate are irrelevant here: no Edit/Write happens, only df-tools and git reads.
</gotchas>

<anti_patterns>
- `git stash`, `git reset`, `git checkout -- .` or any cleanup of the user's tree. Refuse instead.
- Writing the marker into `.planning/` (it would be dirty and committed).
- Guessing a monorepo package root: a non-top-level target is refused, not re-rooted.
</anti_patterns>

<error_recovery>
- A refusal test finds the tree changed → the write happened before the route decision; move every
  write after `decideRoute` and re-run.
</error_recovery>
