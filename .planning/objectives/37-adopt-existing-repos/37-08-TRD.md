# TRD 37-08: `adopt report` + the E2E structural checker

<objective>
Finish the deterministic half: `adopt report` turns the LLM's confidence records and the
scaffold's own findings into `.planning/ADOPT-REPORT.md`, redacts any secret the mappers quoted,
and hands the workflow the exact file list to commit. Then prove the whole deterministic pipeline
end to end on three fixtures with a reusable structural checker — the same checker the simulated
agent runs (37-11..13) use, so their assertions are structure and validity, not prose.

Resolved intent: kind=plugin, work=feature, tdd=strict, test_list_first=required,
fixture_strategy=generators. Constraints honored: `no_llm_test_data` (inference records, maps and
the fake AWS-style key `AKIAABCDEFGHIJKLMNOP` are hand-written literals), `no_property_based_default`,
`no_gherkin_layer`.
</objective>

## Runtime model (binding, from OBJECTIVE.md)

- CommonJS, synchronous fs, **no new npm dependencies**.
- `userHome`, `now`, `pluginVersion`, git `env` injected into adopt.cjs; spawned tests and the
  checker set `HOME=<fake home>`. **Nothing may read or write the real `~/.claude`.**
- **Never touch any real user repository.** Fixtures under mkdtemp only.
- Fixture commits in the E2E test go through the checkout's `df-tools --cwd <fixture> commit
  --files` (the fixture's LOCAL `commit.gpgsign=false` applies; never pass `--no-gpg-sign`).
  This repo's commits go through `node ~/.claude/devflow/bin/df-tools.cjs commit "<msg>" --files
  <paths>`; signing failure → STOP and report; never bypass.
- One plain command per Bash call. Never port 8080. No version bump, tag or push.
- Commits: `test(37-08): ...` → `feat(37-08): ...`.

<gotchas>
- The report is written into `.planning/`, so compute `commit_files` AFTER writing it.
- Redaction runs before rendering (so the report never quotes a secret) and before commit_files.
- The inference file is deleted only after the marker holds its content (write marker first).
- `rev-list` base: use `marker.base_sha`, never `main` by name (the base branch may not be `main`).
- In adopt-e2e.test.cjs, `skill-active --start adopt` writes `.planning/.skill-active`; the report
  must exclude it and the pipeline must `--end` it before commit, or `tree_clean` fails.
- health warnings may legitimately include the marker-less W-codes of a fresh project; the report
  lists them — that is the point — but health ERRORS must be 0 for the E2E test.
</gotchas>

<anti_patterns>
- Asserting prose in the report beyond headings, table rows' field names and fixed phrases.
- Printing or storing a matched secret anywhere (report, marker, SUMMARY, test output).
- Committing inside `adopt report` — the workflow commits with `df-tools commit`.
</anti_patterns>

<error_recovery>
- The E2E pipeline fails `health_no_errors` on one stack → the scaffold literal or stack draft is at
  fault (37-07). Fix it there with a failing test first, then re-run this file.
</error_recovery>
