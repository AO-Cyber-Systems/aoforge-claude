# TRD 37-14: Simulated `/devflow:adopt` routing cases — DevFlow, empty, dirty, non-git (E2E proof a)

<objective>
Prove the locked routing rules from the agent's side: an already-DevFlow repo goes to upgrade (never
re-scaffolded), an empty repo is pointed at new-project, and a dirty tree or a non-git path is
refused with the reason and left exactly as it was.

`type: standard`; verified by `adopt-e2e-assert.cjs compare` and git reads.
</objective>

## Runtime model (binding, from OBJECTIVE.md)

- **Never touch any real user repository.** All four targets live under YOUR session scratchpad.
- **Never read or write the real `~/.claude`**: prefix every `node` and `git` command with
  `HOME=<fake home>`; the only real-home access is the read-only before/after `ls`.
- The DevFlow fixture's upgrade commit goes through the checkout's `df-tools --cwd <fixture> commit
  --files`; the fixture disables signing locally; never `--no-gpg-sign`. This repo's commits go
  through `node ~/.claude/devflow/bin/df-tools.cjs commit "<msg>" --files <paths>`; signing failure →
  STOP and report.
- One plain command per Bash call. Never stash or reset anything. Never port 8080. No version bump,
  tag or push.

## Regression gate (baseline-relative)

Test counts depend on the environment (1Password signing only hangs while 1Password is locked; the
daemon/PID tests fail in any git worktree). So this gate compares failing test **names** against
`.planning/objectives/37-adopt-existing-repos/baseline-failures.tsv` (21 lines, `file:line<TAB>name`),
not counts.

1. From the repo root, run
   `node --test --test-reporter=spec 'plugins/devflow/**/!(micro).test.cjs' 'plugins/devflow/**/*.test.js' 'scripts/**/*.test.cjs'`
   and write the output to a file in your session scratchpad (never the repo).
2. Extract failing names from the closing `✖ failing tests:` section: each entry gives
   `test at <file>:<line>:<col>` then `✖ <name> (<ms>)`; strip the duration.
3. A failure whose name is in the TSV's second column is **pre-existing**.
4. Any other failure is a candidate regression. Re-run just its file with `node --test <file>`.
   - Passes on re-run → **environment flake**, record the evidence.
   - Still fails and this TRD's diff (`git diff --stat <wave base>`) touched code it exercises →
     **regression, blocks**. Fix it before completing.
   - Still fails and plainly unrelated (PTY/handoff timing) → **environment flake**; record file,
     name, re-run output and why it's unrelated. Don't block.
5. **Never edit `baseline-failures.tsv`** to pass the gate. Tests added by this objective are not in
   the TSV and must pass.

In SUMMARY, record observed pass/fail totals (information only) and every failure's classification.
