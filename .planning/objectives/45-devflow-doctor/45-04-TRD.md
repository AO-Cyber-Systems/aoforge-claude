# TRD 45-04: Doctor core, check registry, CLI and dispatch (DOC-04)

<objective>
Build the `df-tools doctor` engine. It loads check modules from `lib/doctor-checks/`, runs them
read-only by default, applies only the fixes the checks mark safe under `--fix`, re-runs, and
reports JSON or text. The core owns no check logic. Waves 2 (45-05/06/07) drop check files into the
directory against the contract this TRD writes down. This TRD also creates the shared fixture
builders the check TRDs use.
</objective>

### Check contract (write this verbatim into `doctor-checks/README.md`, and as a JSDoc typedef in doctor.cjs)

```
module.exports = {
  id: 'kebab-id',                 // unique; also the result id
  title: 'Human title',
  scope: 'global' | 'project',    // project checks only run when ctx.projectRoot is set
  run(ctx) -> {
    severity: 'ok' | 'warn' | 'error',
    finding: string,              // one line
    fixable: boolean,             // true only if fix() is safe + reversible NOW (DOC-06 considered)
    fix_command?: string,         // exact command for report-only / refused cases
    details?: object,
  },
  fix?(ctx, result) -> { applied: boolean, refused?: string, changed?: string[], backup?: string, notes?: string },
};

ctx = {
  projectRoot: string|null,   // absolute realpath of the DevFlow project root, or null
  userHome: string,           // absolute; CLI passes os.homedir(); tests pass a fake home
  env: object,                // process.env or injected (DEVFLOW_* overrides live here)
  now: Date,
  pluginVersion: string,      // running engine version (helpers.pluginVersion())
  dfToolsPath: string,        // absolute path to df-tools.cjs (for checks that spawn it)
  changedThisRun: Set<string>,// project-relative posix paths changed by EARLIER fixes in this --fix run;
                              // safety guards (DOC-06) treat these as the doctor's own, not foreign work
  paths: {                    // all derived from userHome/env — single place to override
    claudeDir, mirrorDir, installedPluginsJson, pluginCacheRoot,   // <home>/.claude/plugins/cache/aocyber/devflow
    progressGuardDir,        // env.DEVFLOW_PROGRESS_GUARD_DIR || <mirrorDir>/state/progress-guard
    awarenessDir,            // env.DEVFLOW_AWARENESS_DIR || <mirrorDir>/state/awareness
    backupsDir,              // <mirrorDir>/backups
  },
}
```
File naming ranges (reserved so parallel TRDs never collide): 10-19 global install checks (45-05), 20-29 project checks (45-06), 30-39 state-hygiene checks (45-07).

### Report shape
```
{ engine_version, schema_version: 1, mode: 'report'|'fix', scope: {project: <root|null>, global: true},
  status: 'healthy'|'degraded'|'broken',     // error → broken, else warn → degraded, else healthy
  summary: {ok, warn, error, fixable},
  checks: [result...],                        // post-fix when mode = 'fix'
  fixes: [ {id, applied, refused?, changed?, backup?, notes?} ]   // [] in report mode
}
```
Text rendering: one line per check, `[ok]   id — finding`, `[warn] id — finding (fixable)` or `(run: <fix_command>)`. Then the fixes section, then `status: <status>`.
Exit code: 0 for any completed run (the status is in the report). 1 only for usage errors, through `error()`.
</context>

## Test list

doctor.test.cjs (in-process, stub checks in temp dirs):
1. `loadChecks` returns the modules sorted by filename, skips `*.test.cjs`, `README.md` and non-matching names.
2. A module missing `run` or with a bad `scope` becomes one error result `{id: <file-derived>, severity:'error', finding: 'invalid doctor check: …'}`, and the other checks still run.
3. Report mode: `fix()` is never called, even for fixable results (spy counter), and `fixes: []`.
4. Fix mode: `fix()` is called only for fixable results, in registry order. The checks are re-run and `checks` reflects the post-fix state (a stub whose run() flips after fix).
5. A `run()` that throws becomes an error result with `finding` naming the exception. A `fix()` that throws becomes `{applied:false, refused:'fix threw: …'}`. Both continue.
6. `scope:'global'` runs only global checks. With `projectRoot:null`, project checks are skipped (absent from `checks`, counted nowhere).
7. `status`/`summary` roll-up: error → broken, warn → degraded, else healthy. `fixable` counts results with fixable:true.
8a. Fix mode: the second fixable stub's fix() sees `ctx.changedThisRun` containing the first fix's `changed` paths.
8. `buildContext` derives all `ctx.paths` from userHome and honors the `DEVFLOW_PROGRESS_GUARD_DIR` / `DEVFLOW_AWARENESS_DIR` env overrides.

doctor-cli.test.cjs:
9. `parseDoctorArgs`: `--fix`, `--json`, `--global`, `--path <dir>` (relative resolves against cwd). An unknown flag or a `--path` without a value gives `{ok:false, message}`.
10. Project resolution: with `--path` pointing at a dir without `.planning/`, projectRoot is null plus an info note. Without `--path`, it walks up from cwd to the nearest `.planning/`.
11. `renderText(report)` contains one line per check and the status line.
12. Spawned end-to-end: `node df-tools.cjs doctor --json` with `HOME=<makeDoctorHome()>`, cwd = a fixture project, and `DEVFLOW_DOCTOR_CHECKS_DIR=<temp stub dir>` (a test-only env override of checksDir) exits 0 and prints valid JSON with `schema_version:1`.
13. `df-tools help doctor` / `doctor --help` prints the usage (help.cjs entry). help.test.cjs parity passes.
