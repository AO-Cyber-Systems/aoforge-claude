<anti_patterns>
- Don't string-match `.gitignore` lines to decide what is ignored. Always use `git check-ignore --no-index` (the 42-14 D5 lesson).
- Don't walk the filesystem with `fs.readdirSync` recursion to find nested files. Use git pathspecs (`:(glob)**/.planning/.progress-guard.json`) so nested repos and submodules are skipped naturally and ignored dirs such as node_modules cost nothing.
- Don't delete or rewrite working files. Removing dead copies is the doctor's job (45-06).
- Don't append duplicate ignore entries on a re-run.
</anti_patterns>

<gotchas>
- `**/` in a glob pathspec matches zero or more directories, so `:(glob)**/.planning/X` also returns the root `.planning/X`. Dedupe against the root list.
- Untracked-present discovery: `git ls-files -z --others -- <glob pathspecs>` WITHOUT `--exclude-standard` lists untracked files including ignored ones. Classify them with check-ignore afterwards.
- A gitignore pattern with a slash in the middle is anchored to the .gitignore's directory. For nested coverage, append `**/.planning/.progress-guard.json` / `**/.planning/.awareness-cache.json`. Root misses keep the existing root-form entries so the current tests hold.
</gotchas>

<error_recovery>
If a glob pathspec behaves differently across git versions, fall back to `git ls-files -z` (plus `--others` for untracked) with no pathspec and filter in JS with `isRuntimeStatePath`. That is correct, only slower. Note the fallback in the SUMMARY.
</error_recovery>
