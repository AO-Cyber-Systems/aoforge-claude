# TRD 45-06: Doctor project checks + DOC-06 safety guard (DOC-05 part 2, DOC-06)

<objective>
These are the project-level checks behind the aodex evidence: tracked runtime state at the root and
in `flutter/.planning/`, pending migrations, validate-health findings, and stale skill markers. The
index-changing fix (untracking) must never mix with a user's staged work. This TRD adds a small git
guard module, and every fix here consults it.
</objective>

<anti_patterns>
- Don't `git add` or commit anything. Don't `git stash`. Don't touch any path the fix doesn't own.
- Don't treat "no git repo" as a crash. The index-changing fix is n/a there (report-only), and worktree fixes may proceed.
- Don't let pending-migrations re-apply 0008 behind the legacy check's guard. It must use the same `indexChangeGuard` when 0008 is pending.
- Don't parse validate health's human output. Parse its JSON.
</anti_patterns>

<gotchas>
- Every guard call passes `{exclude: ctx.changedThisRun}` (45-04 engine). Within one `--fix` run, the legacy fix's own staged removals and `.gitignore` edit must not block the pending-migrations fix that follows (the SC4 convergence in 45-08).
- The order matters and is fixed by filenames: 20-legacy runs (and fixes) before 21-pending-migrations. So after a successful legacy fix, 0008 is no longer pending at re-run.
- After `m0008.apply`, the index holds the doctor's OWN staged removals. The re-run's guard must not call those "foreign". The legacy check's run() looks at discover() (now clean), so no fix is needed and the guard isn't consulted. Keep it that way. Don't compute fixable from the guard when there is nothing to fix.
- upgrade.apply stamps `.planning/config.json`. That is why pending-migrations uses worktreeGuard over `.planning`, `CLAUDE.md` and `.gitignore`.
</gotchas>

## Test list

doctor-git.test.cjs:
1. `stagedPaths` lists staged adds, mods and deletes. A clean repo gives `[]`. A non-repo gives `[]` with `isGitRepo:false`.
2. `dirtyPaths(root, ['.planning', '.gitignore'])` reports unstaged and staged changes under those pathspecs only.
3. `indexChangeGuard`: something staged → `{ok:false, reason:'staged changes present: <paths>'}`. `.gitignore` dirty → `{ok:false}`. Clean → `{ok:true}`.
3a. Both guards ignore paths in `{exclude}`: staged removals of `.planning/.progress-guard.json` + modified `.gitignore` with `exclude` holding exactly those paths → `{ok:true}`. One extra foreign staged path → `{ok:false}` naming only the foreign path.

20-legacy-runtime-state.test.cjs:
4. The aodex-shaped fixture (tracked `.planning/.progress-guard.json` + `flutter/.planning/.progress-guard.json` + untracked unignored `.planning/.awareness-cache.json`) → error, finding names all three, fixable:true.
5. The fix on (4): all three are untracked and ignored, the working copies are deleted, and a backup dir exists under `<home>/.claude/devflow/backups/<repo-key>/` containing the root `.planning/` copy plus `nested/flutter/.planning/.progress-guard.json`. The result `notes` contain the exact commit command. A re-run gives ok.
6. **SC5**: (4) plus an unrelated staged file `src/app.txt` → run gives fixable:false with fix_command. Calling fix() directly returns `{applied:false, refused:/staged changes/}`. Afterwards `git ls-files` still lists both guard files, `git diff --cached --name-only` is exactly `src/app.txt`, and .gitignore and the working files are byte-identical.
7. `.gitignore` with unstaged user edits → refused the same way.
8. The legacy file ignored and untracked but present (dead) → warn, fixable. The fix deletes it and a re-run gives ok (no index change, so no guard needed).
9. Not a git repo with a dead file present → warn. The fix deletes the file (no index involvement).

21-22-project.test.cjs:
10. pending-migrations: a stamped project at 2.0.0 with an applicable auto migration → warn fixable. The fix calls upgrade.apply, and a re-run gives ok (`up_to_date`).
11. pending_confirm 0006 (no kind) → warn, not fixable, with fix_command `node ~/.claude/devflow/bin/df-tools.cjs upgrade --apply --only 0006 --confirm --kind <kind>`.
12. `.planning/ROADMAP.md` modified in the working tree → fixable:false with the refusal reason in the finding, and nothing is written.
13. validate-health: a fixture with a health warning (for example a missing STATE.md section, the executor picks a real warning code) → warn, and details list the codes. A fixture whose only issue is W040 → ok with `deferred:['W040']`.
14. The validate-health spawn uses `HOME=ctx.userHome` (assert via an injected `ctx.exec` spy or an env echo).

23-skill-markers.test.cjs:
15. An expired `.skill-active` → warn fixable. The fix removes it and a re-run gives ok.
16. A live marker (expires_at in the future) → ok and never removed.
17. A garbage marker, or a no-expires_at marker with started_at older than DEFAULT_TTL_MS → warn fixable.
18. `.edit-override` 10 minutes old → warn fixable; 1 minute old → ok.
