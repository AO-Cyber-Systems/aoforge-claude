# TRD 45-07: Doctor state-hygiene checks (DOC-05, part 3)

<objective>

cache, upgrade backups), so it accumulates in `~/.claude/devflow/`. This TRD adds three doctor
checks that report stale or oversized state and prune it safely. Every one of them composes the
existing store and prune modules.

## Test list

30-31-state.test.cjs:
1. guard-state: 3 session files (2 aged 2 days, 1 fresh) → warn "2 stale guard session files", fixable. The fix removes the 2 and keeps the fresh one, and a re-run is ok.
2. guard-state: a missing dir → ok "no guard state". Non-json files are untouched by the fix.
3. The guard-state TTL equals `SESSION_TTL_MS` from hooks/guard-no-progress.js.
4. awareness-state: entries for (a) an existing fresh project, (b) a project path that doesn't exist (orphan), (c) an existing project aged 10 days, (d) an existing fresh project whose file is 2 MiB → warn listing b, c and d with reasons, fixable. The fix leaves only (a), and a re-run is ok.
5. awareness-state: the legacy-shaped 640KB file for an existing fresh project → ok (under the 1 MiB single-file cap). Details report totalSize.
6. awareness-state: a missing dir → ok.

32-backups.test.cjs:
7. The backups root has one repo with 5 timestamped backup dirs older than retention (literal names in backup-prune's timestamp format, `keep_min` respected) → warn "N backups past retention", fixable. The fix removes exactly the dry-run set, and a re-run is ok.
8. No backups dir → ok, and nothing is created.
9. All backups within retention but total > threshold (use `ctx.env.DEVFLOW_DOCTOR_BACKUP_WARN_BYTES` as the test override, with a 500 MiB default) → warn, not fixable, and fix_command names `.claude/devflow/config.json` retention keys (whatever readRetention reads; cite the real key names).
