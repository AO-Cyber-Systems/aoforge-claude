## Binding rules

- Work from `/Users/justin/dev/devflow-claude` or the worktree, and use the REPO df-tools. The mirror is stale.
- Intent: plugin/bugfix, strict TDD. The golden suite is the RED. Fixtures are **hand-built and modelled** on each override's sources list (Makefile/justfile/Taskfile targets, CI steps, manifests), with invented names, paths and contents. **Never copy fleet repo files.** Read each override for the expected output and its `provenance.sources` for what kind of evidence to invent. Do not open the real repos for content.
- **No repo-name special cases** in any drafter module. A divergence is fixed by a rule that is explainable without naming the repo, or the key goes to HAND_ONLY.

- **Comparison scope:** `extends`, the set of `components` (path + profile), and per command key `run`, `apply` and `cwd`. `when`, `scoped`, `timeout_s`, `loop` and `provenance` are out of scope. KEY_ALIASES maps a golden key to the drafter's canonical name where the hand file used a different spelling (`helm_lint` → `lint_helm`). Document each alias.
- Never port 8080. Commits via `df-tools commit --files`. One plain command per Bash call.

- Making a golden pass by matching the fixture to the drafter's current output. The fixture models the REAL repo's evidence shape (per `provenance.sources`), and the expected output is the override.
- Silently growing HAND_ONLY. Every addition needs a reason and goes on the checkpoint list.
- Editing an override file. Those are frozen goldens from objective 42.
</anti_patterns>
