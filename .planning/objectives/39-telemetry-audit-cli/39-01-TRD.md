# TRD 39-01: Wire `df-tools context` and `df-tools session-audit`

<objective>
`lib/context-audit.cjs` (TRD 29-04) and `lib/session-audit.cjs` (TRD 31-03) are implemented and
unit-tested but unreachable: the dispatcher prints `Error: Unknown command`. This TRD adds a small
CLI front-end module, `lib/audit-cli.cjs`, which parses flags, resolves the transcript root and
formats `--raw` text. It then adds the two thin dispatcher cases and help entries. 39-02 extends the
same module with `transcript-export` and `override`.

Why a front-end module instead of logic inline in the `case` blocks: `output()`/`error()` call
`process.exit`, so inline logic can only be tested by spawning. Pure `run*` functions that return
`{ok, result, text}` or `{ok:false, message}` are unit-testable in-process. The dispatcher then only
maps them onto `output`/`error`.

Resolved intent: kind=plugin, work inherited as `feature` from PROJECT.md `default_work` (OBJECTIVE.md
says `bugfix`, but the resolver did not read it; the posture is identical for plugin: strict TDD).
tdd=strict, test_list_first=required, fixture_strategy=generators. Constraints honored:
`no_llm_test_data` (hand-built transcript rows only), `no_property_based_default`, `no_gherkin_layer`.

Decision (recorded here, objective scope item 4): `telemetry.collect()` does NOT consume
context-audit. telemetry is the cheap status view. Scanning transcripts reads ~150 files (~1s) from
the whole `~/.claude/projects` corpus on every call, which is too heavy to add implicitly. The CLI is
context-audit's real caller: its `targets.read_share_ok` IS objective 29's acceptance signal, and
`references/context-discipline.md` documents running it by hand. `telemetry --scan` stays out of
scope; it is recorded as a follow-up.
</objective>
