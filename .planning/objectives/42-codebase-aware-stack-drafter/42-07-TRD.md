# TRD 42-07: Drafter integration — grounded, verified `stack init`

<objective>
Wire 42-03 through 42-06 into `stack init` / `adopt`, so a draft is grounded in the codebase:
- detected areas and tiers
- structured CI plus runner evidence, classified by tool semantics
- a preference order per key
- verification before proposing a command

This TRD proves ROADMAP criterion 1 end-to-end on fixtures shaped like every observed fleet
failure, plus the draft half of criterion 3: drafts carry `agent_tooling` by extending tier-2.

Design decision, made in planning for the rollout constraint: components reference a tier id
(`profile: go`), and `stack init` never writes `.planning/stacks/*.md`. Repo-specific per-component
commands that can't be represented go to draft.notes, the body HTML comment and STACK-REPORT. The
rollout (42-11) must commit exactly `.planning/STACK.md` and `.planning/STACK-REPORT.md`.

Output: stack-draft.cjs, rewired stack-evidence, the draftProfile/initProfile integration, adopt
integration, and an e2e failure-shape suite.
</objective>

<anti_patterns>
- Emitting a mutating command as `run` (`gofmt -w`, `dart format .`, `just fmt` whose body mutates).
- Lifting a command out of its cwd. The CI `defaults.run.working-directory: svc` means `go test` runs
  in `svc`, not at root (research Pitfall 4).
- Silently upgrading `--no-fatal-infos` to `--fatal-infos`. Keep the repo's flag and note it as weak
  (Pitfall 5).
- Re-emitting a key whose tier-2 parent already defines an equivalent non-discover run, when the
  best candidate IS the tier default (redundant noise). Re-emit only when the repo's verified
  candidate differs, or when a cwd is needed.
- Fabricating commands for unsupported areas (Tauri/Rust/Python/C++). Use runner commands only, plus a note.
- Writing `.planning/stacks/*.md`.
</anti_patterns>

<research_context>
Drafting algorithm (per area; the root is area `''`):
1. `areas = detectAreas(root)`. The language areas are those with `tier` or `unsupported`.
2. Extends and components:
   - 0 language areas: `extends: general`.
   - 1 area at root: `extends: <tier or general>`.
   - 1 area at a non-root dir: `extends: <tier>`, and re-emitted keys carry `cwd: <dir>`.
   - 2+ areas: root `extends` is the root area's tier if the root is a language area, else `general`.
     `components` lists each non-root area with a tier (`{path: '<dir>/', profile: '<tier>'}`).
     Unsupported areas are not components; they get a note.
3. Candidates per (area, key) from `collectEvidence`. Normalise runner bodies with `normalizeScript`
   and classify them. The runner target's own invocation (`make -C svc test`) is the candidate, and
   its body decides the key and form. The hint is the target name, used only when the body is opaque.
4. Rank by source: declared > runner > ci > manifest. Within a source, rank high confidence above low
   and non-weak above weak. Then take the first candidate whose `verify` gives `resolved`.
5. No resolved candidate, but candidates exist: `run: discover`, plus one note per candidate
   `{area, key, candidate, status, detail, source}`.
6. Custom keys: `sast` (gosec) collapses into `audit` when no audit candidate exists anywhere.
   `lint_helm`/`lint_docker` attach to the root. `e2e` is maestro only if `.maestro/` exists; else
   playwright/cypress from CI/runners.
7. Loop and gates: leave them to the tier. For a `general` extends with emitted keys, emit
   `loop: [<format?>, <lint?>, <test?>]` from what resolved.
8. `provenance: { reviewed: localDate(now), sources: [evidence files] }`.
</research_context>

**e2e (stack-drafter-e2e.test.cjs, via df-tools CLI with fake PATH/HOME)**
1. aocore-shaped (multi-area, workflow default working-directory `svc`, gosec continuation, govulncheck wrapper script, `uses: golangci-lint-action`, helm lint, playwright): `extends: general`, `components` includes `{path:'svc/', profile:'go'}` and the Flutter areas. There is no `format: -fmt ...`. `lint_helm` is present (or discover plus a note). `e2e` is not `test`. No value ends in `\`.
2. eden-biz-shaped (`flutter build ipa \` + `--build-number="${{ }}"`, a Makefile at `svc/` and `app/`, a pure-Dart `api-dart/`): the api-dart component is `dart`, not `flutter`. No command contains `${{`. The build is either the full joined command (verified) or discover plus a note.
3. devflow-shaped (root go.mod, CI with a `# run tests` comment line then `go vet`, `gofmt`, and `gopls version | head -1`): `test` is never a comment. `extends: go`. `lint` is resolved `go vet ./...` or inherited.
4. aoinference-shaped (`control-plane/Makefile` with lint/vet/test/build, release CI with only `echo "Published ..."`): `extends: go`, and keys come from `make -C control-plane <t>`, not echo.
5. eden-circle-shaped (root go.mod + Makefile, CI with the `test -f x || {` fragment): no control fragment anywhere, and `test` comes from the Makefile or CI `go test -race`.
6. aodex/politihub continuation shape (`\`-continued `go test` plus a `sed -i 's|a|b|'` step): the joined go test, with sed never classified.
7. Manifest-only Flutter app with `.maestro/` (no CI, no runner): `extends: flutter`. Commands are empty or only `e2e: maestro test .maestro`. The resolved chain inherits flutter's `agent_tooling.mcp`.
8. Empty repo and docs-only repo: `extends: general`, `commands: {}`, an info note, exit 0.
9. Binary missing: CI `ginkgo -r -p` with ginkgo absent from the fake PATH gives `test: discover`, a note with status binary_missing, and the body comment naming `ginkgo -r -p`.
10. Every fixture: `validation.ok === true`, `provenance.reviewed === localDate()`, and no `.planning/stacks/` dir is created by `--write`.

11. Preference: a runner candidate beats a CI candidate for the same key. A declared candidate beats both.
12. An apply-only format gives `{run:'discover', apply:'just fmt'}`.
13. gosec plus no audit gives `audit`. gosec plus govulncheck gives `sast` and `audit`.
14. Weak marker kept: `flutter analyze --no-fatal-infos` becomes lint.run verbatim, and a weak note is recorded.
15. Tier default equal to the best candidate means the key is not re-emitted. A non-root single area re-emits with cwd.

**collectEvidence (stack-evidence.test.cjs)**
