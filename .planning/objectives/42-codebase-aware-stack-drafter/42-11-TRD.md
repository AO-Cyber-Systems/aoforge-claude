<anti_patterns>
- Committing in a dirty repo. The default is skip, and only the user can flip it at the checkpoint.
  Even then, the per-repo delta check still applies.
- Treating a `.git` FILE dir as a repo, or descending into nested `.planning` dirs.
- Overwriting an existing STACK.md without `force`. The default for `has-stack` is `skip (has-stack)`.
- `--include test` without an explicit per-repo `+test` from the user.
- Deleting build outputs that `verify --run` produced. List them and don't touch them; only our two
  files are ever reverted.
</anti_patterns>

- A porcelain delta, or anything unexpected: STOP that repo and follow the revert rule. Continue with
  the next repo only if the stop was cleanly contained; otherwise stop the whole loop and report.
