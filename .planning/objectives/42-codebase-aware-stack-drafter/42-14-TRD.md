# TRD 42-14 (gap cycle 2): Command cwd hygiene and the file-level ignore check

<objective>
Close D1, D2, D4 and D5 from the regenerated 42-11 dry run. 42-15 then closes D3 and re-runs the
fleet preview. Every fix is TDD, with hand-built fixtures modelled on the observed shapes.

- **D1.** eden-biz commands got cwd `eden-biz/go` / `eden-biz/flutter`, and eden-circle lint got
  cwd `eden-circle`. Those dirs don't exist. The cause: CI checks out with
  `actions/checkout … path: <repo>`, so `working-directory: <repo>/go` is taken literally. Other
  steps point into sibling checkouts (`path: eden-libs/<pkg>`, with `repository:`).
- **D2.** quanta-local drafted `test` at cwd `.baseline/api`, a gitignored or untracked dir.
- **D4.** Nested git repos (eden-libs `eden-platform-go/`, `eden-ui-flutter/`, each with its own
  `.git`) leak in as command cwds (`cwd: eden-platform-go` from CI). Re-check shows current code
  already keeps them out of `components`, so this TRD pins that with a regression test and closes the
  cwd leak.
- **D5.** justin-donnaruma-us-go: the rollout's file-level check says the stack files are ignored,
  but `stack init`'s `ignored` said no. Cause: `initProfile` only checks with `--write`, so the preview
  the dry run uses always reports `[]`, and it uses an index-aware check.
</objective>

<anti_patterns>
- Stripping a leading segment that IS a real dir in the repo (e.g. a repo named `go` with a `go/`
  subdir). Strip only when it matches the self-checkout `path:`, or when it's the repo basename AND
  `<root>/<segment>` doesn't exist.
- Dropping `${{ github.workspace }}` handling by rejecting the whole command. Normalise it.
- Treating `cwd_missing`, `cwd_ignored` or `cwd_nested_repo` as a pass anywhere.
- Using the index-aware check for D5. Tracked files under an ignored `.planning/` mask it. Use `--no-index`.
- Making the D5 result fatal. It stays a reported `ignored` field; the rollout decides.
</anti_patterns>

## Test list

Outermost to innermost.

1. (draft) An evidence item from a CI step at `working-directory: svcrepo/go` (self-checkout
   `path: svcrepo`), in a repo with `go/`, is placed with cwd `go`. An item at `libs/pkg-a`
   (sibling checkout) becomes a `cwd_external` note, never a command.
2. (draft) An item whose cwd is `.snapshot/api` (gitignored) becomes a `cwd_ignored` note. An untracked
   dir with no tracked files becomes `cwd_untracked`. An item inside `vendored-sdk/` (has `.git`)
   becomes `cwd_nested_repo`. None of them reach `commands`.
3. (draft) An item whose verify returns `cwd_missing` gives `discover` plus a note, when it's the only candidate.
4. (verify) `verifyCommand('go vet ./...', { root, cwd: 'nope' })` gives `cwd_missing`. An existing cwd
   gives the normal path. `stack verify --raw` counts `cwd_missing` under `missing` and exits 1.
5. (ci) normaliseWorkingDirectory, table-driven:
   - `${{ github.workspace }}/go` gives `go`
   - `./go` gives `go`
   - `svcrepo/go` with self path `svcrepo` gives `go`
   - `<basename>/go` with no self path and no `<root>/<basename>` dir gives `go`
   - `go` with a real `go/` dir gives `go` (unchanged)
   - `libs/pkg-a` with a sibling checkout at that path gives external
   - a repo named `go` with a real `go/go/` dir: `go/go` stays unchanged
6. (ci) parseWorkflows records per-job checkouts `{ path, repository }` and the normalised step cwd.
7. (detect) `cwdHygiene(root)` answers ok, ignored, untracked, nested_repo or missing for fixture dirs,
   with one `check-ignore` and one `ls-files` spawn (spy). Regression: `detectAreas` never returns
   `vendored-sdk/`, whether its `.git` is a dir or a file.
8. (evidence) Items carry `cwdStatus` from cwdHygiene. Root-cwd items are `ok`.
9. (init) A git fixture with a `.planning/` rule in `.gitignore`, with `.planning/config.json` AND
   `.planning/STACK.md` force-tracked: `stack init --raw` (PREVIEW, no write) gives
   `ignored: ['.planning/STACK.md', '.planning/STACK-REPORT.md']`. `--write` gives the same. A clean
   fixture gives `ignored: []` in both modes.
10. P11 neutrality is still green.
