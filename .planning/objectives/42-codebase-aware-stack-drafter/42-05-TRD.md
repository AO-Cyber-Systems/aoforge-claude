# TRD 42-05: Codebase detection, Dart-vs-Flutter, and usable components

<objective>
This TRD covers SDR-01, plus the flutter `detect` fix left over from SDR-04. It has three parts.

1. `stack-detect.cjs` finds language areas and their flags up to depth 3. Examples: aocore-shaped
   `svc/` + `admin/` + `chart/`, aofamily-shaped `product/go/`, and eden-libs-shaped siblings.
2. Pure Dart vs Flutter selection. It uses an object-form `detect` marker (locked decision Q1:
   flutter.md only; `markerMatches` handles it).
3. Monorepo `components` become actually usable. A component profile file follows its own
   `extends`, and component commands run in the component dir.

Output: stack-detect.cjs, a schema change, flutter.md detect, and loader/render fixes, all with tests.
</objective>

<anti_patterns>
- Writing a new pubspec regex. Reuse detectPubspecFlutter.
- Emitting helm/docker/proto/sqlc as components. They are flags on the nearest language area (or root).
- Treating `example/`, `test_support/` or platform dirs (`android/`, `ios/`, `web/`...) inside a Flutter
  package as areas.
- Descending into a nested dir whose `.git` exists (file or dir). That's a worktree or nested repo, not an area.
- Joining cwd when there's no component (root commands keep `cwd` as-is).

## Test list

Outermost (detectAreas over repo shapes) to innermost (marker/loader/render units).

**detectAreas**
1. Multi-area shape (invented `svc/` go.mod + .golangci.yml, `admin/` Flutter pubspec + `.maestro/`, `portal/` Flutter, `chart/app/Chart.yaml`, `sdk/python/pyproject.toml`, no root manifest) gives areas `svc/`(go), `admin/`(flutter, flags maestro), `portal/`(flutter), and `sdk/python/` (python, tier null, unsupported). The helm flag is attached to root.
2. Pure-Dart sibling: `api-dart/pubspec.yaml` without `sdk: flutter` is dart (tier `dart`).
3. Depth 3: `product/go/go.mod` and `ai/flutter/pubspec.yaml` are found. Depth 4 is not.
4. Skip list: `node_modules/x/go.mod`, `.worktrees/b/go.mod`, `vendor/`, `flutter_app/example/pubspec.yaml`, `flutter_app/ios/` and `third_party/lib/go.mod` are all ignored. A subdir holding a `.git` FILE is ignored.
5. Single root area: root go.mod + `buf.yaml` + `sqlc.yaml` + a file with `//go:generate` gives one area `''` (root) with flags buf, sqlc, go_generate.
6. Tauri shape: package.json + `src-tauri/Cargo.toml` gives tier null, unsupported `tauri`. A C/C++-only repo (CMakeLists.txt, *.cpp) gives zero language areas plus a root `unsupported: cpp` note. An empty repo or docs-only repo gives `[]`, with no throw.
7. Flutter integration: `integration_test/` gives flag `integration_test`. `build_runner` in dev_dependencies gives flag `build_runner`.

**markers / pickExtends**
8. Schema: `detect: [pubspec.yaml, {file: pubspec.yaml, contains: "sdk: flutter"}]` validates. `{file: 1}` fails.
9. `markerMatches({file:'pubspec.yaml', contains:'sdk: flutter'}, entries, root)` is true only when the file content contains the text.
10. pickExtends with the bundled tier: a pure Dart package gives `dart`; a Flutter app gives `flutter` (dart dropped as ancestor); a go.mod repo gives `go`.
11. Regression: `matchMarkersAt(root, [{marker:{file:'x',contains:'y'}}])` doesn't throw, and repo-state detectManifest on a Flutter repo with a fake home still returns without error.

**components**
12. A STACK.md with `components: [{path: "svc/", profile: ".planning/stacks/svc.md"}]`, where svc.md is `extends: go`: `resolveProfile({file: 'svc/x.go'})` has chain [go, (component)] and inherits go's `test`.
13. `renderCommand` with resolved.component `svc/` and cmd `{run: 'go test ./...'}` gives `cwd: 'svc'`. With cmd.cwd `internal`, cwd is `svc/internal`. With no component, cwd is unchanged.
14. P11 and C14 neutrality stay green.
