## What This Is

AOForge is a meta-prompting, context engineering and spec-driven development system for Claude Code. It ships as a Claude Code plugin (`aoforge@aocyber`) installed via `/plugin` or the Claude Desktop plugin UI. Fork of GSD v1.20.4, maintained by AO Cyber Systems.

## Commands

```bash
npm test                # Run tests (Node native test runner, ~6.5 min)
```

There is no lint command. Tests are `*.test.cjs` / `*.test.js` files beside their sources under `plugins/aoforge/`, `plugins/aoforge-stack-*/` and `scripts/`.

## Publishing

Distribution is the Claude Code plugin marketplace: `.claude-plugin/marketplace.json` and `plugins/aoforge/.claude-plugin/plugin.json` declare the plugin; users add the marketplace by repo slug (`AO-Cyber-Systems/aoforge-claude`). No npm publish. Tags follow `v*` so the changelog gate works. A `v*` release also pushes `aoforge--vX.Y.Z`, the tag the stack packs resolve core from, and a pack releases from `<pack>--vX.Y.Z` with its own CHANGELOG, never marked Latest (`scripts/release-tag.cjs`). `workflow_dispatch` with `dry_run` pushes and deletes a throwaway `aoforge--v0.0.0-dryrun-<run id>` tag to prove the token can push one, and `node scripts/tag-rules.cjs <tag>` lists the tag rulesets that match (read-only).

## Architecture

### Plugin Layout (`plugins/aoforge/`)

```
plugins/aoforge/
├── .claude-plugin/plugin.json    # plugin manifest (name, version, statusLine)
├── skills/<name>/SKILL.md        # 32 user-invocable slash commands
├── agents/<agent>.md             # 12 subagent prompts
├── hooks/
│   ├── hooks.json                # event registrations (auto-loaded)
│   ├── sync-runtime.js           # SessionStart: mirrors aoforge/ → ~/.claude/aoforge/
│   └── *.js                      # the other hooks (gates, verifiers, statusline)
└── aoforge/                      # runtime mirrored to ~/.claude/aoforge/ on session start
    ├── bin/aof-tools.cjs          # central CLI invoked by skills/agents
    ├── bin/lib/*.cjs             # aof-tools internals
    ├── workflows/<name>.md       # workflow bodies referenced via @~/.claude/aoforge/workflows/...
    ├── references/<name>.md      # static reference docs read during execution
    ├── templates/<name>.md       # files copied into user projects' .aoforge/ dirs
    └── stack-profiles/<id>.md    # bundled tier-2 profile (go); flutter/dart ship in their pack
```

The `sync-runtime` SessionStart hook mirrors `${CLAUDE_PLUGIN_ROOT}/aoforge/` to `~/.claude/aoforge/` whenever the version or the content digest differs (`.plugin-version`, `.plugin-digest`). Skills and agents reach the runtime at that fixed home path in Bash and in `@` references.

**How Claude Code loads this plugin (verified on 2.1.301):** a skill body expands `@path` for absolute, `~` and `${CLAUDE_PLUGIN_ROOT}` paths and runs `` !`command` `` lines under the skill's Bash grant, and the whole body stays in the conversation. An agent body is the subagent's system prompt verbatim and a Task prompt is plain text: neither expands `@`, so an agent must `Read` a reference itself. Every command hook is its own `node` process; all hooks for one event run in parallel. Skill descriptions and agent descriptions sit in context at all times.

### Core Tool: `plugins/aoforge/aoforge/bin/aof-tools.cjs`

The CLI every skill and agent calls as `node ~/.claude/aoforge/bin/aof-tools.cjs <command> [args]`. A global `--cwd <dir>` flag precedes the command. Full catalog: `docs/AOF-TOOLS-REFERENCE.md`; `aof-tools --help` lists every command. Families:

- **State operations** — `state load` (config plus the STATE.md digest), `state digest`, `state get`, `state update`, `state patch`, `state-snapshot`, `state advance-job [--objective N]` (with `--objective`, position and Status come from the objective's TRD and SUMMARY files on disk; it also rotates decisions past the newest 10 into STATE_ARCHIVE.md), `state rotate-decisions`; `state update-progress` rewrites or adds the Progress line under `## Current Position`, else exits 1; `state rekey --from <old checkout path> [--to <new path>] [--dry-run] [--raw]` copies repo-keyed runtime state (KEYED_STATE: estimate run state and history, awareness, hook markers, outbox journal without its `.lock`, backups plus the registry entry, planning drafts) from a moved checkout's old key to its new one, merging and never deleting (`lib/state-rekey.cjs`, TRD 72-07). STATE.md is a digest, not an archive: W068 reports an oversized decision log.
- **Objective operations** — `objective next-decimal|add|insert|remove|complete|put|set-status`; `milestone complete <v> --dry-run` previews and a re-run keeps the existing entry and archives; `milestone put`. Every writing command rejects an unknown flag with exit 1 before it runs (`lib/flag-guard.cjs` + `lib/flag-spec.cjs`, kept complete by `flag-spec.repo.test.cjs`).

### Skills (`plugins/aoforge/skills/<name>/SKILL.md`)

YAML frontmatter (`name`, `description`, `argument-hint`, `allowed-tools`) and an XML body (`<objective>`, `<execution_context>` with `@` references, `<process>`, `<context>`). Skills are thin orchestrators: load context, then spawn agents with the Task tool. Project context comes from `` !`aof-tools state digest --raw` `` and `` !`aof-tools roadmap digest --raw` `` injections, never a whole `@.aoforge/STATE.md`. A skill with subcommands (status, milestone, workstreams, todo, objective) resolves the one workflow with `skill-route` and Reads only that file.

### Agents (`plugins/aoforge/agents/*.md`)

12 subagent prompts (planner, executor, verifier, debugger, ...; stack packs ship their own) with frontmatter `name`, `description`, `tools`, `color` and an XML body of `<role>`, `<philosophy>`, `<execution_flow>` steps. Spawned by skills with the model the active profile resolves. A reference is named with the moment it is needed (checkpoints.md only before a checkpoint task, tdd.md only for a TDD TRD) because the agent has to Read it.

### Templates, References, Hooks, Marketplace

- `aoforge/templates/` — `config.json`, `state.md`, `project.md`, `roadmap.md`, `requirements.md`, `milestone.md`, `job-prompt.md`, `summary*.md`: copied into projects' `.aoforge/`.
- `aoforge/references/` — model profiles, verification patterns, TDD, git conventions, checkpoints, UI branding, the design set (`design-*.md`, `full-output.md`; taste-skill under MIT, see `NOTICE.md`), `context-discipline.md`.
- `hooks/hooks.json` — every hook uses `${CLAUDE_PLUGIN_ROOT}`; detail per hook in `docs/HOOKS-REFERENCE.md`.
- `/.claude-plugin/marketplace.json` — the marketplace: core, the stack packs `aoforge-stack-flutter` and `aoforge-stack-web`, and the sibling plugins. Users add it via `/plugin marketplace add AO-Cyber-Systems/aoforge-claude` (or by absolute path for development). The pointer plugin (the final 3.0.0 release of the pre-rename plugin, with one forwarding skill per command) was removed in 3.1.0 with its generator, marketplace entry, package.json test glob and rename-guard ALLOW entries (objective 78, TRD 78-02); `lib/coexistence.cjs` still recognises an installed copy (`POINTER_MAJOR`) to soften its notice.

**Enforcement (active gates):**
- `pre-bash.js` — PreToolUse(Bash); the one registration for the event (perf #133). Runs the five Bash hooks below (gate-commits, gate-bash-writes, gate-interactive, guard-no-progress, changelog-on-tag) in one process with the same stdin and merges their decisions (deny over ask, every reason kept; a throwing hook is skipped). Each dispatched hook carries `DISPATCHED-BY: pre-bash.js` in its header, which doctor check 12 and the hook inventory read.
- `route-intent.js` — UserPromptSubmit; injects skill-routing reminders when AOForge project is detected
- `gate-commits.js` — PreToolUse(Bash) via pre-bash; blocks raw commit invocations. Detection is invocation-aware (TRD 27-04): heredoc bodies and quoted arguments are stripped first, so text that merely *mentions* the command is not gated. Allows merge/rebase/cherry-pick completion (MERGE_HEAD, REBASE_HEAD, rebase-merge/-apply, CHERRY_PICK_HEAD in the per-worktree git dir) and an inline `AOFORGE_ALLOW_RAW_COMMIT=1 git commit …` prefix; an exported variable never reaches the hook (objective 44). Escape: `AOFORGE_ALLOW_RAW_COMMIT=1` in the env Claude Code was launched from
- `gate-edits.js` — PreToolUse(Edit/Write/MultiEdit); **strict DENY by default** in ambient mode (AOForge project + no skill active). Allows edits when a live `.aoforge/.skill-active` marker exists — resolved from **both** the local `.aoforge/` and the MAIN checkout's, so worktree-isolated agents are not denied by a gitignored marker they can never see (TRD 27-01) — or the PreToolUse payload's `agent_type` starts with `aoforge:` (objective 44, `compat.isOwnAgentType`; the pre-rename agent namespace is not trusted since 3.1.0), or the user prompt contains an override phrase (`skip aoforge`, `just edit`, `bypass aoforge`, `force edit`), or `AOFORGE_SKIP_EDIT_GATE=1` is set in the environment Claude Code was launched from. Markers carry `expires_at` (8h default). Targets outside the project root (session scratchpad, `/private/tmp`) are never gated (TRD 27-02). Severity is per-project via `.aoforge/config.json` → `gates.editGate`: `strict` (default) | `warn` | `off`. In store mode, cache/generated `.aoforge/` paths are denied for everyone (skill markers and aoforge agents included) with the verb to use; config.json, STACK.md and runtime files are allowed (needs an installed plugin carrying objective 48). Bash writes to the same files are gated by `gate-bash-writes.js`.
- `gate-bash-writes.js` — PreToolUse(Bash) via pre-bash; denies a Bash write to a tracked source file in ambient mode (redirect, `tee`, `sed -i`, `perl -i`, `cp`/`mv`, inline python/node), the same as Edit/Write (DECISION-001, objective 60). Mentions (heredoc bodies, quoted args) and writes to `.aoforge/`, `*.md`, untracked files, paths outside the project and unresolvable targets are never gated. Same escapes as gate-edits (live skill marker, `aoforge:*` agent, override phrase); the override marker is consumed only by a write that would be gated. Severity is the least of `gates.editGate` and `gates.bashEditGate` (`strict` deny | `warn` ask | `off`). With no `bashEditGate` key the default is `warn` (`BASH_EDIT_GATE_DEFAULT`), measured at 633/17,957 = 0.035251 of ambient Bash calls (an upper bound, above the 0.02 threshold), so `strict` is opt-in; `gates.editGate` `warn` softens it to ask and `off` disables it. Escape: `AOFORGE_SKIP_EDIT_GATE=1` only in the environment Claude Code was launched from, never as an inline command prefix (a hook runs in Claude Code's own process); needs an installed plugin carrying objective 60
- `gate-skill-requires.js` — UserPromptExpansion + PreToolUse(Skill); refuses a `/aoforge:<skill>` whose SKILL.md `requires:` names a tool that is not on PATH (block on a typed command, deny on a Skill call), naming the install hint and `/aoforge:doctor` (check `skill-requires`). Not project-scoped; fails open. Escape: `AOFORGE_SKIP_SKILL_REQUIRES=1`, only in the environment Claude Code is launched from; needs an installed plugin carrying objective 61
- `gate-interactive.js` — PreToolUse(Bash) via pre-bash; denies a TTY-requiring or shell-env command and queues it to `aoforge-watch` as a pending record carrying the payload's `session_id` and `agent_id`; with the daemon live the reason tells Claude to say in one line that the command waits in the user's aoforge-watch terminal (attended `start --foreground`, objective 73) and that the result returns by itself, else to ask for `! cmd`. Invocation-aware (TRD 73-10): matches each simple command from `shell-words.parseCommand`, so quoted text and heredoc bodies are data while a heredoc fed to a shell is read (one level); flags and the deny reason are per call (a compound command's reason names the matching call); `ssh-keygen` read-only forms (`-l`, `-F`, `-R`) pass and `-y` without `-P` is handed off. The matcher lives in `lib/interactive-commands.cjs` (loaded fail-open) and the watch daemon's built-in allowlist uses it too, so the daemon accepts exactly what the hook hands off (TRD 73-12); the daemon is read through `watcher-state.cjs`. Not matched: a quoted or path-qualified command name, `env`/`time`/`command`/`exec`/`sudo`/assignment prefixes and shell keywords, `$( )` inside double quotes, backticks, `bash -c` string bodies. Escape: `AOFORGE_SKIP_INTERACTIVE_GATE=1`
- `guard-no-progress.js` — PreToolUse on every tool (Bash via pre-bash, the rest registered directly with `^(?!Bash$).*`); detects the same tool called with identical arguments repeatedly. Warns on stderr at 3 repeats, escalates to `ask` at 5, resets whenever the agent varies its approach. Step limits cannot do this — they fire only after the budget is spent. Deliberately **not** wired to tool errors: those run 3.6–4.3% at every model tier and are dominated by environment friction (TRD 28-04). State is per-session under `~/.claude/aoforge/state/progress-guard/` (never in the repo; override `AOFORGE_PROGRESS_GUARD_DIR`). Escape: `AOFORGE_SKIP_PROGRESS_GUARD=1`
- `changelog-on-tag.js` — PreToolUse(Bash) via pre-bash; blocks `git tag -a vX.Y.Z` if `CHANGELOG.md` lacks `## [X.Y.Z]`. Escape: `AOFORGE_SKIP_CHANGELOG_GATE=1`
- `gate-executor-stop.js` — SubagentStop; blocks an `aoforge:executor` natural stop once when its TRD (read from the agent transcript's first prompt) has no `<id>-SUMMARY.md` in any checkout, or its final SUMMARY has no `tokens_input`/`tokens_output` (objective 66). Never when `stop_hook_active`; fails open. Escape: `AOFORGE_SKIP_EXECUTOR_STOP_GATE=1`
- `auto-continue.js` — Stop; blocks once when a skill marker is live, no background task is running, and the last sentence announced the model's own next step without asking (questions, `/aoforge:` hand-offs, waits and reports are ignored). Escape: `AOFORGE_SKIP_AUTOCONTINUE=1`

## Conventions

- **Module format**: CommonJS (`.cjs`), synchronous `fs` I/O, designed as a CLI not a library.
- **Naming**: skills `<name>/SKILL.md`, agents `<agent-name>.md`, hooks `<purpose>.js`, tests `<module>.test.cjs` beside the source.
- **Markdown structure**: YAML frontmatter + XML-like tags for prompt sections; `@path` references use `@~/.claude/aoforge/...`.
- **Workflow status**: every `aoforge/workflows/*.md` carries `status: active | legacy`.
- **Version sync**: `package.json`, `plugins/aoforge/.claude-plugin/plugin.json` and `.claude-plugin/marketplace.json` must match on every release.
- **Git commits**: `{type}({scope}): {description}` — feat, fix, test, refactor, perf, chore, docs. Planning docs commit through `aof-tools commit`.

## User-Facing Workflow

**new-project** → **discuss-objective** → **plan-objective** → **execute-objective** → **verify-work** → **complete-milestone**. Each step produces files in `.aoforge/` that feed the next. Execution is wave-based: independent TRDs run concurrently, each executor in a fresh context window.

## Intent Model: `kind` and `work`

A project declares `kind` (`api | app | library | ui-lib | cli | plugin`) on PROJECT.md; an objective declares `work` (`feature | port | refactor | foundation | bugfix | prototype | spike`) on OBJECTIVE.md or inherits `default_work`. The planner applies `references/defaults-table.md` for TDD posture, depth, model profile and rigor. Resolution, highest wins: TRD frontmatter → OBJECTIVE.md `overrides` → CLAUDE.md playbook sections (`## ... TDD|Test|Quality|Scope`) → defaults table → built-in fallback. Inspect with `aof-tools intent resolve --objective <id>`; each resolved field carries provenance metadata naming the level that supplied it. Migration for projects created before this model: `/aoforge:status check --migrate`, which runs `aof-tools upgrade`; setting `kind` is a `confirm` migration: `aof-tools upgrade --apply --only 0006 --kind <kind>`. Each apply backs up to `~/.claude/aoforge/backups/<repo>-<hash>/<timestamp>/`, outside the repo, before writing; the `upgrade-project.js` SessionStart hook applies the `auto` migrations on its own. Design rationale: `docs/PROPOSAL-kind-and-work.md`.
